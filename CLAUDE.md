# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, a dynamic-size frequency vocab — see `regen.ts` below) and styles (`STYLES`, 21 — a fixed closed set), both loaded from `data/labels.json`. A row carries 0–N emojis and 1–N styles. The shared trunk is `model/model.py:TextEncoder` — a char embedding → a stack of `len(ENCODER_CHANNELS)` spectral-norm `Conv1d` blocks (each `spectral_norm(Conv1d, padding=ENCODER_KERNEL//2) → LeakyReLU`; constant time length, **no pooling between blocks**, BatchNorm commented out) → PAD positions masked to `-inf` → one global max over time → a `TEXT_EMBED_SIZE` (= `ENCODER_CHANNELS[-1]`) vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` L2-norms this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead`, now **structurally identical** — `Dropout → Linear(TEXT_EMBED_SIZE → *_EMBED_SIZE, bias=False)` (`STYLE_EMBED_SIZE` 12 / `EMOJI_EMBED_SIZE` 48), then project against a learned label-embedding table (`nn.Embedding(n_labels, *_EMBED_SIZE)`, `logits = proj @ embed.weight.t() + bias`) → per-label logits. (`EmojiHead` no longer has an MLP; `EMOJI_HEAD_HIDDEN_LAYERS` was removed.) Both heads train as retrieval with `model/train.py:lse_infonce` — a multi-positive Log-Sum-Exp InfoNCE (`logsumexp` over all label logits − `logsumexp` over the row's positive logits, scaled by `INFONCE_TEMP`), averaged over rows with ≥1 positive (emoji rows carrying no emoji drop out). Both backprop into the encoder; no focal loss, no BCE/`pos_weight`, no softmax cross-entropy. Colors are a **conditional GAN**, not a head: `model/model.py:ColorGen` conditions on the **text embedding**, mixing it with unit-norm noise `z` as `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground). The generator loss is **adversarial BCE only** — no reconstruction/L1, no energy term (many colors fit one text); `ColorGen`'s output stays in sRGB, but the `ColorDsc` critic (conditioned on the same text embedding) consumes the palette in **OKLab** (`model/model.py:rgb_to_oklab`). Separately, an **OKLab energy distance** between the generator's samples and the real palette distribution is computed at validation as `energy/gan/val` (against a split-half real-vs-real `energy/gan/ref` baseline) and is the GAN stage's early-stop / checkpoint metric — **monitored, never backpropagated**. Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `model/train.py` — single Typer CLI, `train <task|gan|all> [--local] [--cpu N] [--memory MIB]`, installed as a `train` console script (`[project.scripts]` in `pyproject.toml`, pointing at `model.train:_app`; also runnable as `uv run python model/train.py ...` or `uv run train ...`) with free shell-completion (`train --install-completion`). `model` (the CLI argument, not the `model/` folder) picks which stage(s) run: `task` (encoder + `LitTask`'s style/emoji heads, both trained with `model/train.py:lse_infonce` Log-Sum-Exp InfoNCE; early-stop/checkpoint via `ModelCheckpoint`/`EarlyStopping` on `MRR@10/e/val` — emoji top-10 mean reciprocal rank from the hand-rolled `model/train.py:mrr_at_k`. Both `model/train.py:ap_at_k` (mAP) and `mrr_at_k` (MRR) are logged for each head at `EMOJI_AP_K`/`STYLE_AP_K` (10/5) from `model/config.py`, plus `f1/val` = harmonic mean of the two mAPs — no `torchmetrics`; emoji AP/MRR are measured only over rows carrying ≥1 emoji. **Planned:** also logging `acc@1`/`acc@10` (emoji) and `acc@1`/`acc@5` (style) on val — the stated priority metric set — is not wired into `model/train.py` yet; `acc@k` today lives only in the `tools/report.py` keyword probe); `gan` (`LitColorGAN` — color GAN on a **frozen** encoder; conditions on the encoder's text embedding, does not touch the classifier heads; GAN stage early-stop/checkpoint on `energy/gan/val`, min — trained against a pre-saved `pt/enc.pt`); `all` (task then gan, back to back, reloading the best task checkpoint before the GAN stage — the old bare `train.py`'s behavior). Location defaults to Modal (same machinery as the old `train-modal.py`: image build, artifact volume, TensorBoard tunnel, `EMOJIC_GIT_SHA`/`EMOJIC_DISPATCH_CHECKED` so Modal-trained `.pt` files carry the dispatch commit SHA); pass `--local` to run on this machine instead (`--cpu`/`--memory` then don't apply and are rejected). `task`/`all` train their own encoder wherever they run; `gan` needs a pre-trained `pt/enc.pt` **and** `pt/style.pt`/`pt/emoji.pt` (the latter two only for the post-training `export()`, not for the GAN training itself) — locally they must already be on disk, and on Modal the local `pt/enc.pt`/`pt/style.pt`/`pt/emoji.pt` bytes are uploaded into the remote container before training (so a from-scratch Modal `gan` run needs a prior `train task --local`, or `train task`'s artifacts already fetched back). After training, all three stages run the same `tools/report.py` (its sections don't depend on `pt/gen.pt`/`pt/style.pt`); `gan` and `all` additionally refresh `web/public/` via `model/export_onnx.py` first. The report always runs **locally**, never inside the Modal container: a Modal dispatch sets `EMOJIC_SKIP_REPORT=1` on the in-container `train.py <model> --local` subprocess (`_run_env`) so it skips its own report step, and `_dispatch` runs `tools/report.py` on this machine (`_run_report_local`) only after `_retrieve_and_cleanup` has actually fetched artifacts back from the Modal volume — so a failed dispatch, or a `--fetch-only` that finds nothing to retrieve, produces no report. `uv run modal run model/train.py::main -- --model <task|gan|all> [--cpu N] [--memory MIB] [--fetch-only]` reaches the same Modal dispatch directly through the Modal CLI — used by `Taskfile.yml`'s detached `modal-train` task, since that needs Modal's own `--detach` semantics rather than a plain blocking call; `--fetch-only` recovers artifacts from an interrupted run's volume without starting a new one (and, if anything was retrieved, runs the local report too). Code + data files are `add_local_file`d into the Modal image at build time (including `files.py` and `model/__init__.py`, so the `model` package resolves inside the container), so run `bun run regen` **locally first** — Modal does not regen. Aborts on a dirty git tree in every mode (`model/runmeta.py:require_clean_tree`, no override).
- `tools/report.py` — `uv run python tools/report.py [--only data,labels,emoji] [--out report]` is the **single** model + data report. It loads `pt/enc.pt` / `pt/emoji.pt` (missing or shape-mismatched `.pt` are skipped, not fatal — `style.pt`/`gen.pt` aren't read here) and writes one `report/<YY-MM-DD-HH-MM>-<model-sha>/{report.html,report.json}` per run. Sections: **Data** (record counts for `data/data.jsonl` / `data/train.jsonl` / `data/eval.jsonl`; a full bar chart of `data/data.jsonl` text lengths after `model/data.py:normalize`, one bar per distinct length, longest first); **Labels** (`# styles`, `# emojis` — sizes of the current `data/labels.json` sets); **Model → Emojis** (a line chart of `EmojiHead` retrieval `acc@k` for `k` 1–10 on `data/eval.jsonl`; a second line chart of `acc@k` for `k` 1–10 from the `data/keywords.json` keyword probe; a full table of every missed keyword — best-expected-emoji rank > 5, keywords whose expected emoji isn't in the vocab at all excluded — sorted worst-first by rank, each with its expected emoji(s), rank, and top-5 predicted emojis). A header banner flags provenance issues on `enc.pt`/`emoji.pt` only (`.pt` from different commits, model `train_sha` ≠ current `data/train.jsonl`, missing `.pt`). `report.json` mirrors the HTML under `provenance` / `data` / `labels` / `emoji`. Auto-runs at the end of every `model/train.py <task|gan|all>` run — the same report regardless of stage — always on the machine that invoked `train.py`; a Modal dispatch skips the in-container report and runs it locally instead once artifacts are fetched back; re-run it by hand after `bun run regen`. Styles/Colors reporting and the old per-file distinct-emoji-count + frequency-bar-chart + MRR/mAP metric cards were dropped; this is an interim report shape, not a permanent scope cut.
- `model/pred.py` — inference over the first 200 `data/eval.jsonl` rows → `data/pred.jsonl` (reference implementation of the inference graph; one GAN palette per row). Takes a mandatory `--pt <folder>` pointing at a directory holding `enc.pt`/`style.pt`/`emoji.pt`/`gen.pt` (typically `pt/`).
- `model/export_onnx.py` — `uv run python model/export_onnx.py` loads `pt/enc.pt` / `pt/style.pt` / `pt/emoji.pt` / `pt/gen.pt`, wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. Outputs are `style_logits`, `emoji_logits`, `color`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji.pt` label counts disagree with `data/labels.json`.
- `model/config.py` — flat module of hyperparameters: `MAX_TEXT_LEN`, `SEED`, `CHAR_EMBED_SIZE`, `ENCODER_CHANNELS` (list; `TEXT_EMBED_SIZE = ENCODER_CHANNELS[-1]`), `ENCODER_KERNEL`, `RELU_SLOPE` (one shared LeakyReLU slope for the encoder, both heads, GAN generator, and critic), `EMOJI_EMBED_SIZE`, `STYLE_EMBED_SIZE`, `DROPOUT_EMOJI`, `DROPOUT_STYLE`, `Z_WEIGHT`, `GEN_CHANNELS`, `CRITIC_CHANNELS`, `GAN_LR`, `LR`, `GRAD_CLIP`, `INFONCE_TEMP`, `TASK_BATCH_SIZE`, `GAN_BATCH_SIZE`, `EPOCHS_TASK`, `EPOCHS_GAN`, `VAL_CHECK_INTERVAL`, `EARLY_STOP_PATIENCE`, `EMOJI_AP_K` / `STYLE_AP_K` (10 / 5), and the energy-eval knobs `ENERGY_Z_SAMPLES` / `ENERGY_KEYWORD_MIN_TEXTS` / `ENERGY_KEYWORD_MAX_TEXTS` / `ENERGY_KEYWORDS_PATH`. `CONFIG_NAME` (timestamp + hyperparams, the TensorBoard run name) is built here, and `STYLES` / `EMOJIS` are read from `data/labels.json` here (path from `files.py:LABELS_JSON`). Removed: `BATCH_SIZE` (→ `TASK_BATCH_SIZE` / `GAN_BATCH_SIZE`), `TEXT_ENCODER_CHANNELS` (→ `ENCODER_CHANNELS`), `TASK_EPOCHS` / `GAN_EPOCHS` (→ `EPOCHS_TASK` / `EPOCHS_GAN`), `EMOJI_HEAD_HIDDEN_LAYERS`, `ENERGY_WEIGHT` (the OKLab energy term is monitor-only now), `FOCAL_ALPHA` / `FOCAL_GAMMA`, `ENCODER_RELU_SLOPE` / `GEN_RELU_SLOPE` / `CRITIC_RELU_SLOPE`.
- `data/labels.json` — a `styles` list and an `emojis` list. `emojis` = every emoji that survives `regen.ts`'s greedy `--min-count`/`--max-count` pass (descending by kept-record count, ties first-seen), regenerated by `bun run regen`; the vocab size is **dynamic** (whatever clears `--min-count`, default 100), not a fixed leaderboard length. Emojis are **open-set** in the corpus (annotator picks any emoji) and `data/labels.json` is just the current qualifying set. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `model/data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). The growth and annotation tools are not deterministic (LLM calls); `regen.ts` is pure but **not deterministic** — it shuffles unseeded, so the exact kept-row set, emoji vocab, and train/eval split differ run to run (`MRR@10/e/val` / `f1/val` numbers are only comparable within one `regen` invocation, not just one `data/data.jsonl` snapshot). `data/data.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex) is the **append-only master**: every growth tool appends to it and nothing ever rewrites or deletes from it. `data/train.jsonl`, `data/eval.jsonl` and `data/labels.json` are **gitignored artifacts** rebuilt from `data/data.jsonl` by `bun run regen` (`tools/data/regen.ts`) — it collapses rows sharing a `normalize(text)` key (union of emojis + closed-set styles, one palette hash-picked), shuffles the result and greedily keeps rows while capping each emoji's kept-record count at `--max-count` (default 500; a row is dropped once any of its emojis is already at cap), takes every emoji with `count ≥ --min-count` (default 100) into `data/labels.json`'s dynamic vocab, then shuffles the kept rows again and splits them into `data/train.jsonl` + `data/eval.jsonl` (`--n`, default eval size 1500). Run `bun run regen` after any pull that changed `data/data.jsonl` and before training. The growth tools do no dedup and no length filtering and retry nothing across runs; near-duplicate rows are collapsed only in `regen` (by `normalize(text)` key). Run every script from the repo root. Path constants for all of this (`data/data.jsonl`, `data/train.jsonl`, `data/eval.jsonl`, `data/labels.json`, `data/keywords.json`, `data/energy_keywords.txt`, `data/pred.jsonl`) live in `files.ts` (root); the Python side's equivalents live in `files.py` (root).
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `data/data.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/regen.ts` (`bun run regen [--min-count 100] [--max-count 500] [--n 1500]`) — rebuilds `data/train.jsonl` + `data/eval.jsonl` + `data/labels.json` from `data/data.jsonl` in one command, unseeded throughout: union-merge by `normalize(text)`, shuffle and greedily keep rows while capping each emoji's kept-record count at `--max-count` (a row is dropped once any of its emojis is already at cap), take every emoji with a kept count `≥ --min-count` into the dynamic `data/labels.json` vocab (styles stay the fixed set), then shuffle the kept rows again and split the first `--n` into `data/eval.jsonl` (rest to `data/train.jsonl`). Prints a summary (rows read/kept/dropped, vocab size, most/least frequent kept emojis, split sizes).
  - `tools/data/upsample.ts` (`bun run upsample`) — the single upsample tool; unifies what used to be separate `upsample-emojis.ts` / `upsample-emoji-test.ts` / `upsample-colors.ts` scripts, and is where a future kind of targeted upsampling gets added. Today it upsamples emoji-targeted rows: default mode reads `data/data.jsonl` to pick a rank-window of emojis by kept-record count (`--min-rank`/`--max-rank`, default 200-400) and generates texts for each; `--emojis <list>` targets exactly those emoji instead; `--report` targets emoji failing the latest report's `data/keywords.json` keyword probe (reads the newest `report/<ts>-<sha>/report.json`'s `emoji.keywords.words`). Generated texts are `annotate()`d and appended to `data/data.jsonl`.
  - `tools/preview.ts` (`bun run preview`, or `bun tools/preview.ts [file]`) — the single preview tool; unifies what used to be separate `preview.ts` / `preview-pred.ts` scripts under `tools/data/`. Reads `data/data.jsonl`-schema rows (`text`, `emojis`, `styles`, `bg`, `fg`) — from a `.jsonl` file path argument, or from stdin when no argument is given — and writes one preview card per row to a `preview/<stamp>.html` grid (`--all` renders every emoji per card instead of just the first). `tools/data/preview-card.ts` (the shared `cardHtml`/`page` renderer) is unchanged; `tools/data/show-labels.ts` (`bun run show-labels`, renamed from `preview-labels.ts`) previews `data/labels.json`, not `data/data.jsonl`-schema rows. `tools/data/preview-model.ts` (ONNX model output preview) was removed as unused.
  - Extra row fields — growth tools may write fields beyond the base `{text, emojis, styles, bg, fg}` schema. They are kept for debugging, filtering, and eval slicing: `regen.ts:collapse` carries every non-base field through to `data/train.jsonl` / `data/eval.jsonl` (first-seen value wins when rows merge on a `normalize(text)` key) and never strips them, and `toLine` emits them after the base fields. They are **not** training signal — `model/data.py:read` matches only the base schema and ignores every other key (this also covered the old `meta` field, which no row carries anymore).
- Eval set — historically `eval.jsonl` was a hand-curated hold-out (rows sampled from the corpus and kept only if styles + emojis were all correct, a full `bg`/`fg` palette was present, and raw length was 4–48; judged in-session, keep-or-drop, never relabeled). As of the data-files reorg it is a plain **unseeded random split** of the `data/data.jsonl` master (`bun run regen`, first 1500 rows of the post-greedy-cap kept set by default), not a curated set. The pre-reorg curated hold-out is recoverable from git history: `git show f9cb0e6:eval.jsonl`. `regen` is unseeded end to end (the greedy emoji-cap shuffle and the train/eval split both use `Math.random`), so `data/eval.jsonl` membership — and the `data/labels.json` emoji vocab — changes on **every** `regen` run, not just when `data/data.jsonl` grows: `MRR@10/e/val` / `f1/val` numbers are only comparable within a fixed `.pt` + `data/train.jsonl`/`data/eval.jsonl` pair, never across two `regen` runs.
- **Training corpus:** `model/data.py` reads `data/train.jsonl` for training and `data/eval.jsonl` for validation; both are regenerated from the `data/data.jsonl` master by `bun run regen` and are gitignored (run `regen` after a fresh checkout or a pull that touched `data/data.jsonl`). `model/data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `data/labels.json` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`).
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `data/labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` (reads `data/labels.json`) fails until every label has an entry with a unique font. (`web/src/feelings.js`, `data/labels.json`, and `tools/data/styles.ts` currently all carry the same 21 styles.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `model/export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `model/data.py`) and `decodeColors`/`decodeColorList` (the inverse of `model/data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `model/export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors). All of `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".
- Generated docs & reports — `model.md` (regenerated by the `update-model-md` skill) and `data.md` are prose descriptions of the model and corpus; both can lag the code, so treat them as background, not spec. `report/` holds git-tracked per-run folders `report/<YY-MM-DD-HH-MM>-<model-sha>/` (one per run), each with `report.html` + `report.json` written by `tools/report.py` — the **only** report generator, and the only thing under `report/`. No `.md` reports, no `meta.yml`, no per-type subtrees. Preview tools write to gitignored `preview/`.

## Project structure

- `model/` — the model stack (all trainable-model Python): `config.py`, `data.py`, `model.py`, `train.py`, `pred.py`, `export_onnx.py`, `runmeta.py`, `test_runmeta.py`, plus `__init__.py` (empty; makes `model` a real package). Internal imports between these files are package-qualified (`from model.config import ...`, `from model.data import ...`, etc.), not bare sibling imports. Every directly-run entry point in this folder (`train.py`, `pred.py`, `export_onnx.py`, `test_runmeta.py`) starts with `sys.path.insert(0, str(Path(__file__).resolve().parent.parent))` before its local imports, so both `uv run python model/train.py ...` and the installed `train`/`pred` console scripts resolve `model.*` and the root-level `files` module the same way.
- `tools/` — every tooling script, Python and TypeScript alike: `tools/report.py`, `tools/print_model_params.py`, `tools/preview.ts`, and the data-growth toolchain under `tools/data/` (`annotate.ts`, `train.ts`, `upsample.ts`, `regen.ts`, `show-labels.ts`, `styles.ts`, etc.). `tools/report.py` and `tools/print_model_params.py` import the model stack the same way — `sys.path.insert(0, ...)` to the repo root, then `from model.config import ...` / `from model.model import ...`.
- `pt/` — every `.pt` checkpoint (`enc.pt`, `style.pt`, `emoji.pt`, `gen.pt`, `tst.pt`), gitignored. `model/train.py` writes checkpoints here directly (`model/runmeta.py:save_pt` creates the directory if missing); `model/pred.py` takes a mandatory `--pt <folder>` argument (normally `pt`); `model/export_onnx.py` and `tools/report.py` read from here via the `files.py` path constants.
- `data/` — every data file, generated or committed: `data.jsonl` (committed master), `energy_keywords.txt` and `keywords.json` (committed — `keywords.json` from the `generating-emoji-keywords` skill, regenerate only when `data/labels.json`'s vocab drifts or the file is stale, not on every `bun run regen`), `train.jsonl` / `eval.jsonl` / `labels.json` (gitignored, from `bun run regen`), `pred.jsonl` (gitignored, `model/pred.py` output).
- `files.py` / `files.ts` (both at repo root) — the single source of truth for every path named above, one file per language. Python code does `from files import LABELS_JSON, ENC_PT, ...`; the Bun/TS tooling does `import { LABELS_JSON, ... } from "../../files.ts"` (path depth depends on where the importing file lives). Add a new data/model/pt path here first, then reference the constant everywhere else — don't hardcode a new bare filename in a script.
- `report/`, `runs/`, `preview/`, `pr/`, `docs/`, `web/` are unaffected by the above — none of them are model code, tooling scripts, `.pt` files, or data files in the sense above.

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `data/train.jsonl` / `data/eval.jsonl` / `data/labels.json` are gitignored and produced by `bun run regen` from `data/data.jsonl`. ## Conventions

- Colors are a GAN, not a head: `model/model.py:ColorGen` maps `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → 9 raw sRGB byte offsets (`tanh * 127.5`), where `text_embed` is the `TextEncoder` output, **L2-normed inside `ColorGen.forward`** (not the emoji query), and `z` is unit-norm Gaussian noise the same size. Trained adversarially via `ColorDsc` (BCE, spectral norm, no gradient penalty, **no L1/reconstruction term and no energy term in the generator loss**), critic conditioned on the same `text_embed` and fed the palette in OKLab (`model/model.py:rgb_to_oklab`), against `model/data.py:colors2tensor([*row.bg, row.fg])` (RGB bytes − 127.5). The OKLab **energy distance** to the real palette distribution (`model/train.py:energy_distance`) is only a monitored validation metric — `energy/gan/val` vs. the `energy/gan/ref` real-vs-real baseline, and the GAN early-stop / checkpoint key — not a training signal. `style`/`emoji` are the only classifier heads — both trained with `model/train.py:lse_infonce` Log-Sum-Exp InfoNCE (no focal loss, no BCE/`pos_weight`, no softmax cross-entropy). `model/export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` just clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS` is used.
- `normalize` (in `model/data.py`) collapses whitespace, trims, lowercases, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. `TextEncoder.forward` masks PAD positions to `-inf` before the global max over the time axis (`torch.max(out, dim=-1).values`), so pad steps never enter the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- One runnable Python check — `model/test_runmeta.py` (plain-assert script, `uv run python model/test_runmeta.py`) — but still no pytest suite and no CI gate on it; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `train all --local` (watch `MRR@10/e/val` — the early-stop/checkpoint metric — alongside `mAP@10/e/val` / `MRR@5/s/val` / `mAP@5/s/val` and `f1/val` in TensorBoard, and `energy/gan/val` vs. `energy/gan/ref` for the GAN stage; `pt/enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python model/pred.py --pt pt` for a `data/pred.jsonl` spot-check (threshold-based `top_labels`: styles 1–3, emojis exactly 1) and `uv run python tools/report.py` for the full run report (`report/<ts>-<sha>/report.html` — data record counts + text-length distribution, label counts, emoji `acc@k` on `data/eval.jsonl` and on the `data/keywords.json` keyword probe, plus the missed-keywords table). Grow the corpus with `bun run train` and/or `bun run upsample`, then `bun run regen`.
- `.pt` files are `{"state_dict", "meta"}` blobs — save with `model/runmeta.py:save_pt`, load with `model/runmeta.py:load_pt` (returns `(state_dict, meta|None)`; `None` = legacy bare file).
