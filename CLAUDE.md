## Project

> **Current phase: milestone 1** — a limited-vocab keyword-search baseline. Current goals/status/gaps for this phase live in the newest `plans/<stamp>/plan.md` (written by the `planning-emojic-improvements` skill), not a standing spec doc. One linear pipeline, no forks: `bun run regen` slices `data/data.jsonl` into a small emoji vocab (milestone-1 `--min-count` / `--max-count` / `--n` defaults live in `tools/data/regen.ts`, tuned via `bun run regen --matrix`), and the deliberately small char-CNN sized by `model/config.py` (`MAX_TEXT_LEN`, `ENCODER_CHANNELS`, `ENCODER_DILATION`) trains all four heads (`style`, `emoji`, `fusion`, `critic`) plus the colour GAN into `pt/`, and always refreshes `web/public/` — every iteration trains and measures the **full, shipped, functional web app end to end**, not a partial-heads checkpoint. **`model/config.py` and `files.py` are authoritative for every hyperparameter and path — do not restate their literal values here; name the symbol instead.** The prose below describes the full architecture; where it must mention a number, treat `model/config.py` as the source of truth. `cards` (the Cards report section) is a **default** section now that every run ships `style.pt`/`gen.pt`.

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, loaded from `data/labels.json` — a dynamic frequency vocab from `regen.ts`, sized by the milestone-1 `--min-count` / `--max-count` defaults) and styles (`STYLES` — a fixed closed set from `tools/data/styles.ts`). A row carries 0–N emojis and 1–N styles. The shared trunk is `model/model.py:TextEncoder` — a char embedding → a stack of `len(ENCODER_CHANNELS)` **dilated** spectral-norm `Conv1d` blocks (each `spectral_norm(Conv1d, dilation=ENCODER_DILATION[i], padding=dilation*(ENCODER_KERNEL_SIZE//2)) → LeakyReLU`; `ENCODER_DILATION` grows the dilation per block, so the receptive field is only **partial coverage** of `MAX_TEXT_LEN` (see `uv run python model/config.py`); constant time length through the stack, no spatial downsampling, no BatchNorm) → **each block's** full-length output is PAD-masked to `-inf` and max-pooled over time, and the per-block pooled vectors are **concatenated** → a `TEXT_EMBED_SIZE` (= `sum(ENCODER_CHANNELS)`) multi-scale vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` / `ColorCritic` L2-norm this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead` — each `Dropout → Linear(TEXT_EMBED_SIZE → *_EMBED_SIZE, bias=False)` (`STYLE_EMBED_SIZE` / `EMOJI_EMBED_SIZE`) → a query vector. `StyleHead` owns its label-embedding table (`nn.Embedding(len(STYLES), STYLE_EMBED_SIZE)` + bias, `logits = proj @ embed.weight.t() + bias`); the emoji side splits the table into `model/model.py:EmojiEmbedding` (`nn.Embedding(len(EMOJIS), EMOJI_EMBED_SIZE)` + bias, `score(q) = q @ E.t() + bias`) — scored by `EmojiHead` and trained by `loss/emoji`. `StyleHead` / `EmojiHead` train as retrieval with `model/train.py:lse_infonce` — a multi-positive Log-Sum-Exp InfoNCE (`logsumexp` over all label logits − `logsumexp` over the row's positive logits, scaled by `INFONCE_TEMP`), averaged over rows with ≥1 positive (emoji rows carrying no emoji drop out). Both backprop into the encoder; no focal loss, no BCE/`pos_weight`, no softmax cross-entropy. **`EmojiHead` trains standalone** — it has no keyword awareness. The keyword signal is a **non-learned hand-rolled inverted index**: `data/ii.json` postings projected to the emoji vocab (`proj`), IDF weight `1/log2(1+df)`, `queryTokens` (relocated verbatim into `tools/data/tokenize.ts` / `web/src/tokenize.js` / `model/kwtokens.py`) and `@leeoniya/ufuzzy` as the fuzzy step of `matches(word)` (exact posting hit `1.0` + uFuzzy `sim ≥ 0.5`); `regen.ts` computes it offline into a sparse per-row `kw` field + `web/public/kwproj.json`, and the browser runs the identical matcher live. Each keyword's posting list is sorted by `data/emoji_popularity.json` and its top entry gets a `PRIMARY_BONUS` so the canonical emoji outranks its co-listed siblings (the keyword-Acc@1 lever). `web/src/keywords.js` still needs the matching `+PRIMARY_BONUS` for browser parity — a follow-up, off the training path. Fusion is one **detached** learned combiner in `model/model.py` — `FusionHead`, a per-emoji diagonal-weight model: `fused = w_dl ⊙ emoji_logits + w_search ⊙ kw + b`, with `w_dl` / `w_search` / `b` each a `len(EMOJIS)` vector (init `w_dl = w_search = 1`, `b = 0`, so fusion starts at `emoji_logits + kw`). It consumes `(emoji_logits.detach(), kw)` so fusion loss never perturbs the encoder / `EmojiHead` / `EmojiEmbedding`. It trains in stage 1 by `lse_infonce` (`loss/fusion/{split}`); `MRR/fusion/{split}` scores the fused vector, `MRR/kw/{split}` scores `kw` directly, and `fusion/{w_dl_mean,w_search_mean,b_mean}/{split}` log the mean weights. Trained in stage 1 as a co-trained head (`--heads …,fusion`; `fusion` requires `emoji`); checkpoint/early-stop keys on `MRR/fusion/val`. Stage 1 writes `emoji_embed.pt` (with `emoji`) and `fusion.pt` (with `fusion`) next to `emoji.pt`. Colors are a **conditional GAN**, not a head: `model/model.py:ColorGen` conditions on the **text embedding**, mixing its L2-normed form with unit-norm noise `z` as `(1 - Z_WEIGHT) * normalize(text_embed) + Z_WEIGHT * normalize(z)` → an MLP (`GEN_CHANNELS`, BatchNorm1d + LeakyReLU on the hidden block) → a 9-vector `tanh`-squashed to `[-COLOR_SHIFT, COLOR_SHIFT]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground). The generator loss is a **relativistic hinge** — `relu(critic(text, real).detach() − critic(text, gen(text, z)) + GAN_GEN_MARGIN).mean()`, pushing generated palettes up toward the real score — with no reconstruction/L1 and no energy term. `ColorGen`'s output stays in sRGB and so does the `ColorCritic` — a dual-branch dot-product scorer (spectral-norm `Linear → BatchNorm1d → LeakyReLU` per branch; colour branch on the palette rescaled to `[-1, 1]` by `1/COLOR_SHIFT`, **not** OKLab; text branch on the L2-normed text embedding with dropout; the score is the bilinear term `(proj(text) · colour).sum()` only — the additive `self.out` head is commented out), trained with a pairwise BCE loss (real vs. within-batch-rolled real-palette negatives in stage 1, real vs. generator-sample negatives in stage 2). Separately, an **OKLab energy distance** (`model/color.py:rgb_to_oklab` + `model/train.py:energy_distance`) between the generator's samples and the real palette distribution is computed at validation as `energy/gan/val` (against a split-half real-vs-real `energy/gan/ref` baseline) and is the GAN stage's early-stop / checkpoint metric — **monitored, never backpropagated**. Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `model/train.py` — single Typer CLI, `train [enc|gan] [--local] [--gpu TYPE] [--cpu] [--heads style,emoji,critic,fusion] [--pt FOLDER] [-o FOLDER]`, installed as a `train` console script (`[project.scripts]` → `model.train:_app`; also `uv run python model/train.py ...`). The optional positional picks the stage: **`enc`** trains `LitEncoder` — the shared `TextEncoder` plus the `--heads` subset of `{style, emoji, critic, fusion}` (default all four; `fusion` requires `emoji` or `_parse_heads` aborts), co-trained; the style/emoji/fusion heads use `model/train.py:lse_infonce` (multi-positive Log-Sum-Exp InfoNCE), the `ColorCritic` uses a pairwise BCE loss whose negatives are within-batch-rolled (mismatched) real palettes, and every selected head's loss backprops into the encoder — except the `fusion` combiner (`FusionHead` — a per-emoji `w_dl ⊙ emoji_logits + w_search ⊙ kw + b`), which consumes `(emoji_logits.detach(), kw)` so it never perturbs the trunk, `EmojiHead` or `EmojiEmbedding` (stage 1 optimizes with Adam at `LR`). Checkpoint/early-stop keys on the first present of `MRR/fusion/val` (`fusion` selected) → `F1/val` (emoji **and** critic heads both selected — the harmonic mean of `MRR/e/val` and `auc/critic/val`, `model/train.py:harmonic_mean`) → `MRR/e/val` → `MRR/s/val` → `auc/critic/val` (all max; `auc/critic/val` is a hand-rolled Mann-Whitney ROC-AUC, `model/train.py:roc_auc`, monitor-only otherwise; `F1/train` is logged as the train-split counterpart, monitor-only; with `fusion` on, `MRR/e/val` + `MRR/kw/val` are logged next to `MRR/fusion/val`). Every `MRR/*/{split}` value is **macro-averaged by label class**, not a per-row mean: `model/metrics.py:macro_average` credits each row's reciprocal rank to every label it targets, averages within each class, drops classes under `MACRO_MIN_SUPPORT`, then averages the remaining classes equally — so the metric isn't dominated by the corpus's highest-frequency emojis/styles. It's computed once per epoch from buffered per-row values (`_val_e_rr`/`_trn_e_rr`, `_val_s_rr`/`_trn_s_rr`, `_val_f_rr`/`_val_kw_rr` and their `_trn_*` counterparts) in `LitEncoder._epoch_metrics`, not logged per step. `enc` writes `enc.pt` plus one `.pt` per selected head (`emoji_embed.pt` with `emoji`; `fusion.pt` when `fusion` is on). **`gan`** trains `LitColorGAN` on a **frozen** encoder: `ColorGen` conditioned on the text embedding + unit noise, `ColorCritic` warm-started from `<--pt>/critic.pt` and kept training with **generator samples** as negatives; generator loss is a relativistic hinge (`relu(critic(text, real).detach() − critic(text, gen) + GAN_GEN_MARGIN).mean()` — no reconstruction/L1, no energy term), and the GAN uses manual optimization with SGD (`GAN_GEN_LR` / `GAN_CRITIC_LR`, grad-clipped by `GRAD_CLIP_GEN` / `GRAD_CLIP_CRITIC`). GAN early-stop/checkpoint on `energy/gan/val` (min) — the OKLab energy distance vs. the split-half `energy/gan/ref` baseline, **monitored, never backpropagated**. `gan` requires `enc.pt`/`critic.pt`/`style.pt`/`emoji.pt`/`emoji_embed.pt`/`fusion.pt` in `--pt` (aborts otherwise) and writes `gen.pt`; the stage-2 critic is discarded. **No positional** runs `enc` (all heads) then `gan` back to back, reloading the best `enc` checkpoint first. Location defaults to Modal (image build, artifact volume, TensorBoard tunnel, `EMOJIC_GIT_SHA`/`EMOJIC_DISPATCH_CHECKED`); `--local` runs on this machine. A Modal dispatch defaults to a **GPU box** (`DEFAULT_GPU` `T4`); `--gpu TYPE` (e.g. `L4`/`A10G`, Modal-only, rejected with `--local`) picks another type and `--cpu` (mutually exclusive with `--gpu`) forces a CPU box. The GPU path applies `Function.with_options(gpu=…, cpu=GPU_CPU 8)`, larger batches (`EMOJIC_TASK_BATCH_SIZE`/`EMOJIC_GAN_BATCH_SIZE` → `GPU_TASK_BATCH_SIZE` 512 / `GPU_GAN_BATCH_SIZE` 1024), `EMOJIC_DATA_WORKERS=4`, and `deterministic="warn"` + TF32 + `cudnn.benchmark` (all gated on `torch.cuda.is_available()`, so CPU / `--local` runs are byte-identical). The Modal image always builds the CUDA torch (`uv sync … --group dev --group gpu`), and one image serves both box types. `--pt`/`-o` may differ from `pt/` only with `--local`, and a non-default `-o` skips the `web/public/` export. After training, all stages run `tools/report.py` locally (a Modal dispatch sets `EMOJIC_SKIP_REPORT=1` in-container and runs the report on this machine once `_retrieve_and_cleanup` has fetched artifacts back); the no-positional and `gan` stages additionally refresh `web/public/` via `model/export_onnx.py` first (only when `-o` is the default `pt/`). Code + data files are `add_local_file`d into the Modal image at build time, so run `bun run regen` **locally first**. Aborts on a dirty git tree in every mode (`model/runmeta.py:require_clean_tree`, no override). Removed: the `emoji`/`style`/`task`/`all`/`color-exp`/`critic` subcommands, the old resource-sizing `--memory` (and the old `--cpu`, whose name is now reused for "CPU box vs default GPU"), the `modal run model/train.py::main` entrypoint, and `--fetch-only`.

- `model/pred.py` — inference over the first 200 `data/eval.jsonl` rows → `data/pred.jsonl` (reference implementation of the inference graph; one GAN palette per row). Takes a mandatory `--pt <folder>` pointing at a directory holding `enc.pt`/`style.pt`/`emoji.pt`/`emoji_embed.pt`/`gen.pt` (typically `pt/`). If `<--pt>/fusion.pt` is present it also loads `FusionHead`, feeds it `(emoji_logits.detach(), row-kw)` (the `kw` field of the input jsonl rows), and writes a `fusion_top_labels` column (same threshold rule as `emojis`); otherwise that column is omitted.
- `model/export_onnx.py` — `uv run python model/export_onnx.py` loads `pt/enc.pt` / `pt/style.pt` / `pt/emoji.pt` / `pt/emoji_embed.pt` / `pt/gen.pt` plus `pt/fusion.pt` (`FusionHead`), wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. The graph takes **one input** — `input` (int64 char ids) — and emits **three outputs**: `style_logits`, `emoji_logits`, `color`. Keyword scoring and fusion happen **client-side** now (`web/src/keywords.js` + `web/src/fusion.js`); `meta.json` gains a `fusion` block (`_fusion_meta` — the `w_dl` / `w_search` / `b` vectors) and drops `flex_kw` / `flex_n`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji_embed.pt` / `fusion.pt` label counts disagree with `data/labels.json`.
- `model/config.py` — flat module of hyperparameters, currently sized small for milestone 1 (**read the file for the live values — never rely on a number quoted elsewhere in this doc**): `MAX_TEXT_LEN`, `SEED`, `CHAR_EMBED_SIZE`, `ENCODER_CHANNELS` (list) + `ENCODER_DILATION` (list, same length — asserted), `TEXT_EMBED_SIZE = sum(ENCODER_CHANNELS)` (the per-block pools are concatenated), `ENCODER_KERNEL_SIZE` (odd — asserted), `RELU_SLOPE` (one shared LeakyReLU slope for the encoder, both heads, GAN generator, and critic), `EMOJI_EMBED_SIZE` / `STYLE_EMBED_SIZE`, `DROPOUT_EMOJI` / `DROPOUT_STYLE` / `DROPOUT_CRITIC`, `Z_WEIGHT`, `GEN_CHANNELS`, `CRITIC_COLOR_CHANNELS` / `CRITIC_TEXT_CHANNELS` (the critic's two branches), `GAN_GEN_LR` / `GAN_CRITIC_LR`, `GAN_GEN_MARGIN`, `LR`, `GRAD_CLIP_GEN` / `GRAD_CLIP_CRITIC`, `INFONCE_TEMP`, `CLDR_WEIGHT` (the fraction of each train **and** eval batch drawn as a random sample from `data/cldr.jsonl`; see the Training-corpus bullet), `TASK_BATCH_SIZE` / `GAN_BATCH_SIZE` (env-overridable via `EMOJIC_TASK_BATCH_SIZE` / `EMOJIC_GAN_BATCH_SIZE`; the `--gpu` dispatch overrides both), `EPOCHS_TASK` / `EPOCHS_GAN`, `VAL_CHECK_INTERVAL`, `EARLY_STOP_PATIENCE`, `EMOJI_AP_K` / `STYLE_AP_K`, `MACRO_MIN_SUPPORT` (the minimum per-class row count for a label to count toward a macro-averaged `MRR/*/{split}`; see `model/metrics.py`), and the energy-eval knobs `ENERGY_Z_SAMPLES` / `ENERGY_KEYWORD_MIN_TEXTS` / `ENERGY_KEYWORD_MAX_TEXTS` / `ENERGY_KEYWORDS_PATH`. `CONFIG_NAME` (timestamp — `EMOJIC_RUN_TIME`-overridable — plus hyperparams, the TensorBoard run name) is built here, and `STYLES` / `EMOJIS` are read from `data/labels.json` here (path from `files.py:LABELS_JSON`). `uv run python model/config.py` prints a model-stats table (channel chain, effective kernels, receptive field vs `MAX_TEXT_LEN`, param counts). - `data/labels.json` — a `styles` list and an `emojis` list. `emojis` = every emoji that survives `regen.ts`'s greedy `--min-count`/`--max-count` pass (descending by kept-record count, ties first-seen), regenerated by `bun run regen`; the vocab size is **dynamic** (whatever clears `--min-count`, default 50), not a fixed leaderboard length. Emojis are **open-set** in the corpus (annotator picks any emoji) and `data/labels.json` is just the current qualifying set. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `model/data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). The growth and annotation tools are not deterministic (LLM calls); `regen.ts` is pure **and deterministic** — both its shuffles run a `SEED`-seeded mulberry32 PRNG (`SEED = 42` in `tools/data/config.ts`), so a given `data/data.jsonl` + flags always yields the same kept-row set, emoji vocab, and train/eval split (`MRR/e/val` numbers are comparable across `regen` runs as long as `data/data.jsonl` and the `--min-count`/`--max-count`/`--n` flags are unchanged). `data/data.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex) is the **append-only master**: every growth tool appends to it and nothing ever rewrites or deletes from it. `data/train.jsonl`, `data/eval.jsonl` and `data/labels.json` are **gitignored artifacts** rebuilt from `data/data.jsonl` by `bun run regen` (`tools/data/regen.ts`) — it collapses rows sharing a `normalize(text)` key (union of emojis + closed-set styles; the **last** row in file order with a valid `bg`/`fg` sets the palette, so a re-annotated row appended after its original wins), shuffles the result and greedily keeps rows while capping each emoji's kept-record count at `--max-count` (default 1000; a row is dropped once any of its emojis is already at cap), takes every emoji with `count ≥ --min-count` (default 50) into `data/labels.json`'s dynamic vocab, then shuffles the kept rows again and splits them into `data/train.jsonl` + `data/eval.jsonl` (`--n`, default eval size 2000). Run `bun run regen` after any pull that changed `data/data.jsonl` and before training. The growth tools do no dedup and no length filtering and retry nothing across runs; near-duplicate rows are collapsed only in `regen` (by `normalize(text)` key). Run every script from the repo root. Path constants for all of this (`data/data.jsonl`, `data/train.jsonl`, `data/eval.jsonl`, `data/labels.json`, `data/energy_keywords.txt`, `data/pred.jsonl`) live in `files.ts` (root); the Python side's equivalents live in `files.py` (root).
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped. The palette section of the prompt (`PALETTE_GUIDANCE`, shared) steers toward the full saturation range and expressive dark/bright, text-driven, with **no target-colour awareness**. `annotateColors(texts)` → `Map<index, {bg, fg}>` is a lean palette-only path (`paletteInstructions()`: no emoji/style rules, schema `{id, bg, fg}`) used by `upsample.ts --reannotate colors`; it runs `resolvePaletteRepairing` (→ `repairFg`), which nudges an unreadable `fg`'s lightness toward black/white — keeping hue — until it clears `MIN_CONTRAST` against both `bg` stops, so a bold palette is fixed rather than dropped (only malformed hex or an extreme-lightness-range gradient still drops; tallied in `lastPaletteFix`). `expandEmojis(texts, existing)` → `Map<index, string[]>` is a lean emoji-only path (`expandEmojiInstructions()`: shows each row's current emojis, asks for a whitespace-separated string of **only new** emojis, schema `{id, add}`, `EXPAND_CONCURRENCY` default 100) used by `upsample.ts --reannotate emojis`; it never drops a row for a bad emoji reply (caller diffs the additions against the row's existing emojis and always accepts what survives).
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `data/data.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/regen.ts` (`bun run regen [--min-count 50] [--max-count 1000] [--n 2000] [--no-cldr] [--no-kw] [--matrix] [--analysis]`) — rebuilds `data/train.jsonl` + `data/eval.jsonl` + `data/labels.json` from `data/data.jsonl` **only** in one command, **deterministically** (both shuffles run a `SEED`-seeded mulberry32, `SEED = 42` in `tools/data/config.ts`; the second shuffle seeds `SEED + 1`): union-merge by `normalize(text)`, shuffle and greedily keep rows while capping each emoji's kept-record count at `--max-count` (a row is dropped once any of its emojis is already at cap), take every emoji with a kept count `≥ --min-count` into the dynamic `data/labels.json` vocab (styles stay the fixed set), then shuffle the kept rows again and split the first `--n` into `data/eval.jsonl` (rest to `data/train.jsonl`). `data/cldr.jsonl` is **no longer merged into the split** — it is read only to write `data/cldr-baseline.json` and (in `--analysis`) the vocab-overlap report, and is instead sampled directly at train time by `model/data.py` (see the Training-corpus bullet); `--no-cldr` now only skips that baseline/overlap read. Every train/eval row also gets a sparse **`kw`** field — `[[emojiIdx, value], …]` (value > 0, rounded 3 dp; `emojiIdx` in `data/labels.json` order) — the non-learned keyword prediction. `regen` builds an inverted index `proj` from `data/ii.json` (each key's emoji list filtered to the current vocab), IDF `weight[k] = 1/log2(1 + proj[k].length)`, then per row: for each `word ∈ queryTokens(text)` (imported from `./tokenize.ts`), `matches(word)` yields an exact `proj[word]` hit (strength `1.0`) plus `@leeoniya/ufuzzy` fuzzy hits (`new uFuzzy({ intraIns: 1 })`, `sim = info.chars/keyword.length ≥ 0.5`), and `kw[e] = max(kw[e], strength·weight[k])` over every `e ∈ proj[k]`. It also writes `web/public/kwproj.json` = `{ "proj": { "<keyword>": [<emojiIdx>, …] } }` for the browser (which recomputes `weight` and runs the identical `matches`). `regen` is deterministic again — no report dependency. `--no-kw` skips the `kw` field and `kwproj.json`. `kw` feeds the detached `FusionHead` combiner — `model/data.py:read` captures `kw` onto each `record`, and `model/data.py:_row_kw` scatters it into a dense `[len(EMOJIS)]` float tensor. Prints a summary (rows read/kept/dropped, vocab size, most/least frequent kept emojis, split sizes, `kw` keys + mean nonzero count). `--matrix` is a dry sweep that writes nothing: it prints a grid of `kept-rows / emoji-vocab` for `--min-count` ∈ {50, 75, 100, 125, 150, 200, 250} × `--max-count` ∈ {500, 600, 750, 1000, 1250, 1500, 2000, 3000, 4000, 5000}. `--analysis` writes **only** `docs/regen.md` (no train/eval/labels/baseline writes): it simulates the pipeline from `data/data.jsonl` alone (no `data/cldr.jsonl` merge, honoring `--min-count`/`--max-count`) and reports the emoji-vocab overlap with `data/cldr.jsonl` — a count summary plus three lists: emojis in both, in the train vocab only, and in `data/cldr.jsonl` only.
  - `tools/data/upsample.ts` (`bun run upsample`) — the single upsample tool; unifies what used to be separate `upsample-emojis.ts` / `upsample-emoji-test.ts` / `upsample-colors.ts` scripts, and is where a future kind of targeted upsampling gets added. Today it upsamples emoji-targeted rows: default mode reads `data/data.jsonl` to pick a rank-window of emojis by kept-record count (`--min-rank`/`--max-rank`, default 200-400) and generates texts for each; `--emojis <list>` targets exactly those emoji instead. `--rare` targets the rarest emoji in `data/data.jsonl` by record count: it drops emoji with fewer than `--min-freq` (default 10) records, sorts the rest ascending by count (rarest first, ties by first-seen) and takes the first `--max-count` (default 100 — a **target count, not a frequency cap**); `--per` defaults to 50, and `--iter <n>` (default 1, `--rare` only) repeats the whole select→generate→`annotate()`→append cycle `n` times, re-reading `data/data.jsonl` each pass so rows appended by earlier passes shift the counts and the rarest set is recomputed. Not standalone (like the rank window it injects the target emoji into each appended row) but mutually exclusive with `--emojis`/`--min-rank`/`--max-rank` and every standalone mode. `--group <name>` is likewise **not standalone** (it injects the target emoji into each appended row) but mutually exclusive with `--rare`/`--emojis`/`--min-rank`/`--max-rank` and every standalone mode: it reads `data/group.json` (`GROUP_JSON` — committed, one entry per Unicode subgroup, regenerated by `bun run build-groups`), takes **every** emoji of subgroup `<name>` as the target set (`--count N` → a `SEED`-seeded random N-subset; unknown `<name>` aborts with the valid list), generates `--per` (default 50) texts per emoji, `annotate()`s with the **default** prompt, and appends each row with the target emoji prepended + a top-level `"group": "<name>"` field + `"meta": {"src": "group"}`. Serves a `goals.yml` `vocabulary.coverage.<group>` gap. `--negation` is a **standalone** mode (no emoji targeting — `--emojis`/`--min-rank`/`--max-rank` are ignored): it prompts the generator for `--count` (default 1000) negation-heavy short texts ("not good", "don't like it", "it isn't a dog it's a cat", refusals, denials, corrections), fanned over `VOICES` in batches of `--per`, and tags every appended row with a top-level `"neg": "true"` field. `--short` is another **standalone** mode (mutually exclusive with `--negation`/`--single-emoji`/`--colors`/`--flags`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank` ignored): it runs the plain generate→`annotate()`→append pipeline for `--count` (default 2000) short texts, fanned over `VOICES` in `--per` batches (default 50), but the generation prompt's length cap is the **weighted median normalized text length of the newest `report/*/report.json`** (`data.length_distribution`) instead of the standing 42 — biasing the corpus shorter; samples that come back longer than the median are kept anyway (no post-gen length filter), and it aborts if no report with a length distribution exists. Rows are tagged `"meta": {"src": "short"}`. `--single-emoji` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--colors`/`--flags`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--per` ignored): no generation at all — it reads `data/data.jsonl`, selects rows whose `normalize(text)` key is unique across the master **and** whose `emojis` string holds exactly one emoji, takes the first `--count` (default 5000) of them in file order, `annotate()`s their texts with the **default** prompt (no forcing), and appends a fresh row per successful annotation with the **re-annotation's** emojis replacing the original (rows re-annotated to zero emojis are dropped). `--colors` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--flags`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--count` ignored): for each of a fixed colour list (`red, green, blue, dark, bright`) it prompts the generator for `--per` (default 1000, auto-chunked into 50-per-call batches over `VOICES`) short texts that use or evoke that colour, `annotate()`s them with the **default** prompt (no forcing — the annotator's palette is the training signal), and tags every appended row with a top-level `"color": "<name>"` field. `--flags` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--colors`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank` ignored): it reads every `flag: <country>` emoji from `node_modules/emojibase-data/en/data.json` (262 country/subdivision flags, deterministic emojibase order), and for each prompts the generator for `--per` (default 50, auto-chunked into 50-per-call batches over `VOICES`) short texts about that country (cities, landmarks, food, sport, weather, daily life — not flags in the abstract), then `annotate()`s them with the **default** prompt plus a per-row `palette_hint` (`"the national flag colours of <country>"`) that steers `bg`/`fg` toward the flag's colours while still enforcing `fg` readability (so the flag palette is a bias, not a hard constraint — `fg` contrast wins). Every appended row gets the flag emoji **prepended** to the annotator's emoji list (deduped, like the emoji-target path) and a top-level `"flag": "<country>"` field. `--count` caps how many countries (first N of the deterministic list — used for cheap smoke runs / partial passes); default is all 262. `--reannotate <what>` (`what` = `colors` | `emojis`) is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--colors`/`--flags`/`--keywords`; `--emojis`/`--min-rank`/`--max-rank`/`--per` ignored): no generation — it reads `data/data.jsonl` and takes a `SEED`-seeded random sample of `--count` (default 300) rows that have a base palette and a `normalize(text)` key not already carrying **this mode's** marker field (`reannotatedKeys`, deduped by that key) — `colors` skips keys with a `reannotated` field, `emojis` skips keys with a `remojis` field, so the two modes are independent and a text can be re-annotated once by each. **`colors`** re-annotates **just the palette** via `annotateColors()` (widened palette-only prompt, no emoji/style forcing; an unreadable `fg` is lightness-nudged to clear `MIN_CONTRAST` rather than dropped), and appends a fresh row per success — original `emojis`/`styles` verbatim, the new `bg`/`fg`, a top-level `"reannotated": "colors"` marker, and `"meta": {"date": ..., "src": "reannotate"}`; `regen.ts:collapse`'s last-palette-wins rule means the appended row's palette supersedes the original at rebuild time. Also writes `preview/reannotate-<stamp>.jsonl` (old vs new `bg` pairs) and prints the mean-bg OKLab lightness/chroma shift. **`emojis`** re-annotates **just the emoji list** via `expandEmojis()` (shows the annotator the row's current emojis, asks only for *additional* relevant ones — not forced), diffs the reply against the existing emojis (`mergeEmojiAdditions`: drops repeats / unrecognized / dups, always accepts the rest), and appends a fresh row per annotator response — `styles`/`bg`/`fg` verbatim, `emojis` = original list **+** the new emojis, a top-level `"remojis": [...]` field holding **just the new emojis** as a JSON list (its presence is the emoji-reannotation marker), and `"meta": {"date": ..., "src": "reannotate"}`. Rows that gain no new emoji are still appended (`"remojis": []`); a row is dropped only when the annotator returns nothing for it. Also writes `preview/reannotate-emojis-<stamp>.jsonl` (`text` / `old` / `added`). `--keywords <kw1,kw2,...>` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--colors`/`--flags`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--count` ignored): for each comma-separated keyword (trimmed, de-duped) it prompts the generator for `--per` (default 50) short texts that naturally use that keyword, one keyword per generation call, `annotate()`s them with the **default** prompt (no forcing), and tags every appended row with a top-level `"keyword": "<kw>"` field. Generated/selected texts are `annotate()`d and appended to `data/data.jsonl`. `--dry` is a **global** flag (any mode): it runs only the target/plan selection, prints what would be upsampled (mode, target emoji / batch counts, approx texts), and exits before any generation, annotation, or append — with `--rare --iter>1` it reports only the first iteration, since later passes depend on rows an actual run would have appended. Every row `upsample.ts` appends (every mode) carries a `"meta": {"date": "YYYY-MM-DD", ...}` object — `--single-emoji` rows also get `"single-emoji": true`, `--short` rows `"src": "short"`, `--colors` rows `"src": "colors"`, `--flags` rows `"src": "flags"` (plus a top-level `"flag": "<country>"` field), `--group` rows `"src": "group"` (plus a top-level `"group": "<name>"` field), `--keywords` rows `"src": "keywords"`, `--rare` rows `"src": "rare"`, `--reannotate` rows `"src": "reannotate"` (plus the top-level `"reannotated": "colors"` for `colors` / `"remojis": [...]` for `emojis`); `meta` (like `neg`/`color`/`flag`/`keyword`/`reannotated`/`remojis`) is a non-base extra field, carried through by `regen.ts:collapse`, ignored by `model/data.py:read`, for filtering/eval-slicing only.
  - `tools/preview.ts` (`bun run preview`, or `bun tools/preview.ts [file]`) — the single preview tool; unifies what used to be separate `preview.ts` / `preview-pred.ts` scripts under `tools/data/`. Reads `data/data.jsonl`-schema rows (`text`, `emojis`, `styles`, `bg`, `fg`) — from a `.jsonl` file path argument, or from stdin when no argument is given — and writes one preview card per row to a `preview/<stamp>.html` grid (`--all` renders every emoji per card instead of just the first). `tools/data/preview-card.ts` (the shared `cardHtml`/`page` renderer) is unchanged; `tools/data/show-labels.ts` (`bun run show-labels`, renamed from `preview-labels.ts`) previews `data/labels.json`, not `data/data.jsonl`-schema rows. `tools/data/preview-model.ts` (ONNX model output preview) was removed as unused.
  - Extra row fields — growth tools may write fields beyond the base `{text, emojis, styles, bg, fg}` schema. They are kept for debugging, filtering, and eval slicing: `regen.ts:collapse` carries every non-base field through to `data/train.jsonl` / `data/eval.jsonl` (first-seen value wins when rows merge on a `normalize(text)` key) and never strips them, and `toLine` emits them after the base fields. They are **not** training signal — `model/data.py:read` matches only the base schema and ignores every other key. The `kw` field on train/eval rows is different in kind: not carried from a master row but **computed by `regen.ts`** at rebuild time (see the `regen.ts` bullet), and — unlike the other extras — **read by `model/data.py`** (`_row_kw` scatters it into a dense `[len(EMOJIS)]` tensor) as the input to the detached `FusionHead` combiner. `upsample.ts` writes a `meta` object (`{"date": ..., "src"?: ..., "single-emoji"?: true}`) on every row it appends; older rows and `train.ts` rows carry no `meta`. `--reannotate colors` rows also carry a top-level `"reannotated": "colors"` marker (passed through like any extra field); their palette supersedes the original only because `regen.ts:collapse` takes the last palette in file order and the re-annotated row is appended after its original. `--reannotate emojis` rows carry a top-level `"remojis": [...]` list of the newly added emojis (marker + payload in one field); the row's `emojis` is the original list plus those additions.
- Eval set — historically `eval.jsonl` was a hand-curated hold-out (rows sampled from the corpus and kept only if styles + emojis were all correct, a full `bg`/`fg` palette was present, and raw length was 4–48; judged in-session, keep-or-drop, never relabeled). As of the data-files reorg it is a plain **seeded random split** of the `data/data.jsonl` master (`bun run regen`, first `--n` — default 2000 — rows of the post-greedy-cap kept set), not a curated set. The pre-reorg curated hold-out is recoverable from git history: `git show f9cb0e6:eval.jsonl`. `regen` is deterministic end to end (the greedy emoji-cap shuffle and the train/eval split both run a `SEED`-seeded mulberry32, not `Math.random`), so `data/eval.jsonl` membership — and the `data/labels.json` emoji vocab — changes only when `data/data.jsonl` or the `--min-count`/`--max-count`/`--n` flags change: `MRR/e/val` numbers are comparable across `regen` runs on the same `data/data.jsonl` + flags.
- **Training corpus:** `model/data.py` reads `TRAIN_JSONL` for training and `EVAL_JSONL` for validation (from `files.py` — `data/train.jsonl` / `data/eval.jsonl`, rebuilt from the `data/data.jsonl` master by **`bun run regen`**; gitignored). `model/data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `LABELS_JSON` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`). Corpus rows longer than `MAX_TEXT_LEN` after `normalize` are dropped at load. **CLDR mix:** both `train_ds()` and `eval_data_loader()` build `EmojiDataset(..., mix_cldr=True)`; each `__getitem__` call, with probability `CLDR_WEIGHT` (`model/config.py`), returns a uniform-random row from `data/cldr.jsonl` instead of the indexed row (`_cldr_pool` — CLDR rows through the same `read()` filter, kept only if ≥1 in-vocab emoji; their `kw` vector is all-zero). So a `CLDR_WEIGHT` fraction of every training **and validation** batch is CLDR keyword→emoji pairs, resampled each step — `MRR/e/train` and `MRR/e/val` are measured on the same distribution. The whole `data/cldr.jsonl` is seen during training, which means `report.json` `cldr.acc_at_k` is a fit metric, not a held-out one. `EmojiDataset(mix_cldr=False)` (the default) is used only where a pure real-row read is wanted — `model/pred.py` and `tools/report.py` read `EVAL_PATH` directly, so their metrics stay CLDR-free. The random CLDR substitution is unseeded, so `MRR/e/val` carries some run-to-run noise.
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `data/labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` (reads `data/labels.json`) fails until every label has an entry with a unique font. (`web/src/feelings.js`, `data/labels.json`, and `tools/data/styles.ts` currently all carry the same 21 styles.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `model/export_onnx.py` (`model.onnx`, `meta.json`, `config.json`) plus `kwproj.json` (the `{ "proj": {...} }` inverted index, written by `bun run regen`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `model/data.py`) and `decodeColors`/`decodeColorList` (the inverse of `model/data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). `web/src/keywords.js:makeKeywordPredictor(kwproj.json)` runs the non-learned keyword predictor live (recomputes the IDF `weight` from `proj`, `@leeoniya/ufuzzy` fuzzy `matches`, char-identical to `regen.ts`), `web/src/tokenize.js` holds the verbatim `queryTokens`, and `web/src/fusion.js:makeFusion(meta.fusion)` reconstructs `FusionHead` (`w_dl ⊙ logits + w_search ⊙ kw + b`) from the exported `w_dl` / `w_search` / `b` vectors — so keyword scoring **and** fusion are fully client-side. Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `model/export_onnx.py`'s `ExportWrapper` takes **one input** (`input` int64 char ids) and exports **three outputs** — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors); `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`). `web/src/hooks/useOnnx.js` runs the session, then computes the `kw` and `fusion` vectors in JS. The masthead emoji-ranking toggle is still 3-way — `fusion` (default), `model` (raw `emoji_logits`), `keywords` (the client-side `kw` vector) — persisted in `localStorage` under `emojiMode` (migrates the legacy `emojiSource`); the old `web/src/cldrEmojis.ts` + `web/src/data/cldr-emoji-index.json` are gone. `web/package.json` swaps the `flexsearch` dep for `@leeoniya/ufuzzy` (root `package.json` keeps `flexsearch` — `tools/analysis/cldr-baseline.ts` still imports it).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".
- Generated docs & reports — `model.md` (regenerated by the `update-model-md` skill) and `data.md` are prose descriptions of the model and corpus; both can lag the code, so treat them as background, not spec. `docs/regen.md` is written by `bun run regen --analysis` (train-vocab vs `data/cldr.jsonl` emoji coverage). `report/` holds git-tracked per-run folders `report/<YY-MM-DD-HH-MM>-<model-sha>/` (one per run), each with `report.html` + `report.json` written by `tools/report.py` — the **only** report generator, and the only thing under `report/`. No `.md` reports, no `meta.yml`, no per-type subtrees. The repo-root `goals.yml` (`GOALS_YML`) is the single **long-term** goals statement — a nested `goals:` tree (emoji/style/colour Acc@k, energy distance, `max text len`, `vocabulary.size`, per-Unicode-group `vocabulary.coverage`); `tools/report.py` reads every `status` scorecard target from it. `goal/` holds git-tracked per-iteration goal files `goal/<YYYY-MM-DD>-<short-sha>.yml` (one per train → report → analysis → plan → implement loop; written by the `planning-emojic-improvements` skill; schema + leaf→`report.json` source map in `goal/README.md`) — each stating the targets the *next* iteration aims to hit for **every** priority-ordered goal in `goals.yml`'s tree (lower-priority goals get an easy hold-at-current target while a higher-priority one is still open — see `goal/README.md`), and `tools/report.py` grades the run against the newest one into `report.json` `goals` (and merges it into the priority scorecard at `status.goals`). `plans/<report-stamp>/plan.md` (git-tracked, mirrors `report/`) is that loop's derived plan. ## Conventions

- Colors are a GAN, not a head: `model/model.py:ColorGen` maps `(1 - Z_WEIGHT) * L2-norm(text_embed) + Z_WEIGHT * L2-norm(z)` → 9 raw sRGB byte offsets (`tanh * COLOR_SHIFT`, `COLOR_SHIFT` = 127.5 in `model/color.py`), `z` unit-norm Gaussian noise. Trained in stage 2 against `model/model.py:ColorCritic` — a dual-branch dot-product scorer (text branch on the L2-normed text embedding, colour branch on the palette in **sRGB** rescaled to `[-1, 1]` by `1/COLOR_SHIFT` — **not** OKLab; the score is the bilinear term only), warm-started from `pt/critic.pt` and kept training with generator samples as negatives. Critic loss is pairwise BCE; generator loss is a relativistic hinge (`relu(critic(text, real).detach() − critic(text, gen) + GAN_GEN_MARGIN).mean()` — no L1/reconstruction, no energy term). The OKLab **energy distance** (`model/color.py:rgb_to_oklab` + `model/train.py:energy_distance`) is the stage-2 early-stop/checkpoint key (`energy/gan/val` vs. `energy/gan/ref`), never a training signal. `style`/`emoji` are the only classifier heads — both `model/train.py:lse_infonce` Log-Sum-Exp InfoNCE. `model/export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS`.
- `normalize` (in `model/data.py`) lowercases, collapses whitespace, trims, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `CHARS` carries `a–z` only (no `A–Z`), so `normalize`'s collapse key treats `"Paris"` and `"paris"` as the same text. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. `TextEncoder.forward` masks PAD positions to `-inf` before max-pooling **each conv block's** output over the time axis and concatenating the per-block pools, so pad steps never enter the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- Runnable Python checks — `model/test_runmeta.py`, `model/test_train_cli.py`, and `tools/test_report.py` (plain-assert scripts, `uv run python <path>`) — but still no pytest suite and no CI gate on them; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is `bun run regen` then the full `train --local` (into the default `pt/`, all four heads + GAN + `web/public/` export; watch `MRR/fusion/val` — the early-stop/checkpoint metric, expected `≳ max(MRR/e/val, MRR/kw/val)` — alongside `MRR/e/val`, `MRR/kw/val`, `fusion/{w_dl_mean,w_search_mean,b_mean}`, `auc/critic/val` and `energy/gan/val` in TensorBoard; checkpoints are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python model/pred.py --pt pt` for a `data/pred.jsonl` spot-check and `uv run python tools/report.py --pt pt` for the run report (`report/<ts>-<sha>/report.html` — data record counts + text-length distribution, label counts, the `EmojiHead` / `Keywords` / `Fusion` `acc@k` on `data/eval.jsonl`, the **CLDR** keyword `acc@k`, the merged goal-status scorecard — global target + this iteration's target + current value — the `goal/*.yml` per-leaf detail table, and the default **Cards** section measuring the shipped web-app graph end to end). A single-head dev check (`train enc --local --heads <subset>`) is fine for iterating fast, but treat it as scratch work — the loop's real result comes from the full `train --local`. Grow the corpus with `bun run train` and/or `bun run upsample`, then `bun run regen`.
- `.pt` files are `{"state_dict", "meta"}` blobs — save with `model/runmeta.py:save_pt`, load with `model/runmeta.py:load_pt` (returns `(state_dict, meta|None)`; `None` = legacy bare file).
