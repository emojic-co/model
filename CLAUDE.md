# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, a dynamic-size frequency vocab — see `regen.ts` below) and styles (`STYLES`, 21 — a fixed closed set), both loaded from `data/labels.json`. A row carries 0–N emojis and 1–N styles. The shared trunk is `model/model.py:TextEncoder` — a char embedding → a stack of `len(ENCODER_CHANNELS)` **dilated** spectral-norm `Conv1d` blocks (each `spectral_norm(Conv1d, dilation=ENCODER_DILATION[i], padding=dilation*(ENCODER_KERNEL_SIZE//2)) → LeakyReLU`; `ENCODER_DILATION` is `[1, 2, 4]`, so the receptive field is 15 chars — **partial coverage** of `MAX_TEXT_LEN` 42; constant time length through the stack, no spatial downsampling, no BatchNorm) → **each block's** full-length output is PAD-masked to `-inf` and max-pooled over time, and the per-block pooled vectors are **concatenated** → a `TEXT_EMBED_SIZE` (= `sum(ENCODER_CHANNELS)` = 620) multi-scale vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` / `ColorCritic` L2-norm this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead`, **structurally identical** — `Dropout → Linear(TEXT_EMBED_SIZE → *_EMBED_SIZE, bias=False)` (`STYLE_EMBED_SIZE` 16 / `EMOJI_EMBED_SIZE` 64), then project against a learned label-embedding table (`nn.Embedding(n_labels, *_EMBED_SIZE)`, `logits = proj @ embed.weight.t() + bias`) → per-label logits. Both heads train as retrieval with `model/train.py:lse_infonce` — a multi-positive Log-Sum-Exp InfoNCE (`logsumexp` over all label logits − `logsumexp` over the row's positive logits, scaled by `INFONCE_TEMP`), averaged over rows with ≥1 positive (emoji rows carrying no emoji drop out). Both backprop into the encoder; no focal loss, no BCE/`pos_weight`, no softmax cross-entropy. Colors are a **conditional GAN**, not a head: `model/model.py:ColorGen` conditions on the **text embedding**, mixing its L2-normed form with unit-norm noise `z` as `(1 - Z_WEIGHT) * normalize(text_embed) + Z_WEIGHT * normalize(z)` → an MLP (`GEN_CHANNELS` `[64, 32]`, BatchNorm1d + LeakyReLU on the hidden block) → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground). The generator loss is a **relativistic hinge** — `relu(critic(text, real).detach() − critic(text, gen(text, z)) + GAN_GEN_MARGIN).mean()`, pushing generated palettes up toward the real score — with no reconstruction/L1 and no energy term. `ColorGen`'s output stays in sRGB and so does the `ColorCritic` — a dual-branch dot-product scorer (spectral-norm `Linear → BatchNorm1d → LeakyReLU` per branch; colour branch on the palette rescaled to `[-1, 1]` by `1/COLOR_SHIFT`, **not** OKLab; text branch on the L2-normed text embedding with dropout; the score is the bilinear term `(proj(text) · colour).sum()` only — the additive `self.out` head is commented out), trained with a pairwise BCE loss (real vs. within-batch-rolled real-palette negatives in stage 1, real vs. generator-sample negatives in stage 2). Separately, an **OKLab energy distance** (`model/color.py:rgb_to_oklab` + `model/train.py:energy_distance`) between the generator's samples and the real palette distribution is computed at validation as `energy/gan/val` (against a split-half real-vs-real `energy/gan/ref` baseline) and is the GAN stage's early-stop / checkpoint metric — **monitored, never backpropagated**. Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `model/train.py` — single Typer CLI, `train [enc|gan] [--local] [--gpu TYPE] [--cpu] [--heads style,emoji,critic] [--pt FOLDER] [-o FOLDER]`, installed as a `train` console script (`[project.scripts]` → `model.train:_app`; also `uv run python model/train.py ...`). The optional positional picks the stage: **`enc`** trains `LitEncoder` — the shared `TextEncoder` plus the `--heads` subset of `{style, emoji, critic}` (default all three), co-trained; the style/emoji heads use `model/train.py:lse_infonce` (multi-positive Log-Sum-Exp InfoNCE), the `ColorCritic` uses a pairwise BCE loss whose negatives are within-batch-rolled (mismatched) real palettes, and every selected head's loss backprops into the encoder (stage 1 optimizes with Adam at `LR`). Checkpoint/early-stop keys on the first present of `F1/val` (emoji **and** critic heads both selected — the harmonic mean of `MRR/e/val` and `auc/critic/val`, `model/train.py:harmonic_mean`) → `MRR/e/val` → `MRR/s/val` → `auc/critic/val` (all max; `auc/critic/val` is a hand-rolled Mann-Whitney ROC-AUC, `model/train.py:roc_auc`, monitor-only otherwise; `F1/train` is logged as the train-split counterpart, monitor-only). `enc` writes `enc.pt` plus one `.pt` per selected head. **`gan`** trains `LitColorGAN` on a **frozen** encoder: `ColorGen` conditioned on the text embedding + unit noise, `ColorCritic` warm-started from `<--pt>/critic.pt` and kept training with **generator samples** as negatives; generator loss is a relativistic hinge (`relu(critic(text, real).detach() − critic(text, gen) + GAN_GEN_MARGIN).mean()` — no reconstruction/L1, no energy term), and the GAN uses manual optimization with SGD (`GAN_GEN_LR` / `GAN_CRITIC_LR`, grad-clipped by `GRAD_CLIP_GEN` / `GRAD_CLIP_CRITIC`). GAN early-stop/checkpoint on `energy/gan/val` (min) — the OKLab energy distance vs. the split-half `energy/gan/ref` baseline, **monitored, never backpropagated**. `gan` requires `enc.pt`/`critic.pt`/`style.pt`/`emoji.pt` in `--pt` (aborts otherwise) and writes `gen.pt`; the stage-2 critic is discarded. **No positional** runs `enc` (all heads) then `gan` back to back, reloading the best `enc` checkpoint first. Location defaults to Modal (image build, artifact volume, TensorBoard tunnel, `EMOJIC_GIT_SHA`/`EMOJIC_DISPATCH_CHECKED`); `--local` runs on this machine. A Modal dispatch defaults to a **GPU box** (`DEFAULT_GPU` `T4`); `--gpu TYPE` (e.g. `L4`/`A10G`, Modal-only, rejected with `--local`) picks another type and `--cpu` (mutually exclusive with `--gpu`) forces a CPU box. The GPU path applies `Function.with_options(gpu=…, cpu=GPU_CPU 8)`, larger batches (`EMOJIC_TASK_BATCH_SIZE`/`EMOJIC_GAN_BATCH_SIZE` → `GPU_TASK_BATCH_SIZE` 512 / `GPU_GAN_BATCH_SIZE` 1024), `EMOJIC_DATA_WORKERS=4`, and `deterministic="warn"` + TF32 + `cudnn.benchmark` (all gated on `torch.cuda.is_available()`, so CPU / `--local` runs are byte-identical). The Modal image always builds the CUDA torch (`uv sync … --group dev --group gpu`), and one image serves both box types. `--pt`/`-o` may differ from `pt/` only with `--local`, and a non-default `-o` skips the `web/public/` export. After training, all stages run `tools/report.py` locally (a Modal dispatch sets `EMOJIC_SKIP_REPORT=1` in-container and runs the report on this machine once `_retrieve_and_cleanup` has fetched artifacts back); the no-positional and `gan` stages additionally refresh `web/public/` via `model/export_onnx.py` first (only when `-o` is the default `pt/`). Code + data files are `add_local_file`d into the Modal image at build time, so run `bun run regen` **locally first**. Aborts on a dirty git tree in every mode (`model/runmeta.py:require_clean_tree`, no override). Removed: the `emoji`/`style`/`task`/`all`/`color-exp`/`critic` subcommands, the old resource-sizing `--memory` (and the old `--cpu`, whose name is now reused for "CPU box vs default GPU"), the `modal run model/train.py::main` entrypoint, and `--fetch-only`.
- `tools/report.py` — `uv run python tools/report.py [--only data,labels,emoji,cldr,cards] [--out report]` is the **single** model + data report. It loads `pt/enc.pt` / `pt/emoji.pt` and, for the Cards section, `pt/style.pt` / `pt/gen.pt` (missing or shape-mismatched `.pt` are skipped, not fatal); it writes one `report/<YY-MM-DD-HH-MM>-<model-sha>/{report.html,report.json}` per run. Sections: **Data** (record counts for `data/data.jsonl` / `data/train.jsonl` / `data/eval.jsonl`; a full bar chart of `data/data.jsonl` text lengths after `model/data.py:normalize`, one bar per distinct length, longest first); **Labels** (`# styles`, `# emojis` — sizes of the current `data/labels.json` sets); **Model → Emojis** (a line chart of `EmojiHead` retrieval `acc@k` for `k` 1–10 on `data/eval.jsonl`, with the CLDR baseline overlaid; a second line chart of `acc@k` for `k` 1–10 from the `data/keywords.json` keyword probe — only keywords with ≥1 in-vocab target emoji are scored); **CLDR** (the same probe but keywords come from `data/cldr.jsonl` — each row's `text` is the CLDR keyword, `emojis` its target set; CLDR keywords under 3 chars or with no ASCII letter are dropped — an `acc@k` line chart for `k` 1–10); **Cards** (an end-to-end test of the **shipped inference graph** — enc + style + emoji + gen with the 5 constant-noise palettes from `model/export_onnx.py:CONST_Z` — run over a gold set **derived from `data/eval.jsonl` at report time**: for each colour `red`/`green`/`blue`/`dark`/`bright`, the 100 eval rows whose background is nearest that pure colour in OKLab (full `(L,a,b)` distance for `red`/`green`/`blue`, `|ΔL|` only for `dark`/`bright`, background = mean of the two `bg` stops), then a `SEED`-seeded random 25 of those 100 (125 rows total, 25 per colour); the gold-set performance is shown **above** the card grids — a single line chart of emoji **and** style `acc@k` for `k` 1–10, and a per-colour table of threshold accuracy (`dF < CARD_DIST_THRESHOLD`, OKLab, `0.15`) and mean OKLab distance `dF` — for `red`/`green`/`blue` `dF` is the full-`(L,a,b)` slot distance, for `dark`/`bright` it is `|ΔL|` only, in both cases the min over the 5 palettes averaged over `bg1`/`bg2`/`text_color`); below the performance, a 5×5 grid of mini-cards (1:1 aspect) per colour shows the model's actual palette + top-1 emoji + top-1 style, and at the very bottom the same grids render the **ground truth** — each gold row's real `bg`/`fg` palette + annotated emojis + styles from `data/eval.jsonl`. A header banner flags provenance issues on `enc.pt`/`emoji.pt`/`style.pt`/`gen.pt` (`.pt` from different commits, model `train_sha` ≠ current `data/train.jsonl`, missing `.pt`). `report.json` mirrors the HTML under `provenance` / `data` / `labels` / `emoji` / `cldr` / `cards`. Auto-runs at the end of every `model/train.py <task|gan|all>` run — the same report regardless of stage — always on the machine that invoked `train.py`; a Modal dispatch skips the in-container report and runs it locally instead once artifacts are fetched back; re-run it by hand after `bun run regen`. The per-failure tables (missed texts / missed keywords / missed CLDR) were dropped; this is an interim report shape, not a permanent scope cut.
- `model/pred.py` — inference over the first 200 `data/eval.jsonl` rows → `data/pred.jsonl` (reference implementation of the inference graph; one GAN palette per row). Takes a mandatory `--pt <folder>` pointing at a directory holding `enc.pt`/`style.pt`/`emoji.pt`/`gen.pt` (typically `pt/`).
- `model/export_onnx.py` — `uv run python model/export_onnx.py` loads `pt/enc.pt` / `pt/style.pt` / `pt/emoji.pt` / `pt/gen.pt`, wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. Outputs are `style_logits`, `emoji_logits`, `color`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji.pt` label counts disagree with `data/labels.json`.
- `model/config.py` — flat module of hyperparameters: `MAX_TEXT_LEN` (42), `SEED`, `CHAR_EMBED_SIZE`, `ENCODER_CHANNELS` (list) + `ENCODER_DILATION` (list, same length — asserted; `[1, 2, 4]`), `TEXT_EMBED_SIZE = sum(ENCODER_CHANNELS)` (the per-block pools are concatenated), `ENCODER_KERNEL_SIZE` (odd — asserted), `RELU_SLOPE` (one shared LeakyReLU slope for the encoder, both heads, GAN generator, and critic), `EMOJI_EMBED_SIZE` (64) / `STYLE_EMBED_SIZE` (16), `DROPOUT_EMOJI` / `DROPOUT_STYLE` / `DROPOUT_CRITIC`, `Z_WEIGHT`, `GEN_CHANNELS`, `CRITIC_COLOR_CHANNELS` / `CRITIC_TEXT_CHANNELS` (the critic's two branches), `GAN_GEN_LR` / `GAN_CRITIC_LR`, `GAN_GEN_MARGIN`, `LR`, `GRAD_CLIP_GEN` / `GRAD_CLIP_CRITIC`, `INFONCE_TEMP`, `TASK_BATCH_SIZE` / `GAN_BATCH_SIZE` (env-overridable via `EMOJIC_TASK_BATCH_SIZE` / `EMOJIC_GAN_BATCH_SIZE`; the `--gpu` dispatch sets 512 / 1024), `EPOCHS_TASK` / `EPOCHS_GAN`, `VAL_CHECK_INTERVAL`, `EARLY_STOP_PATIENCE`, `EMOJI_AP_K` / `STYLE_AP_K` (10 / 5), and the energy-eval knobs `ENERGY_Z_SAMPLES` / `ENERGY_KEYWORD_MIN_TEXTS` / `ENERGY_KEYWORD_MAX_TEXTS` / `ENERGY_KEYWORDS_PATH`. `CONFIG_NAME` (timestamp — `EMOJIC_RUN_TIME`-overridable — plus hyperparams, the TensorBoard run name) is built here, and `STYLES` / `EMOJIS` are read from `data/labels.json` here (path from `files.py:LABELS_JSON`). `uv run python model/config.py` prints a model-stats table (channel chain, effective kernels, receptive field vs `MAX_TEXT_LEN`, param counts). Removed: `GAN_LR` (→ `GAN_GEN_LR` / `GAN_CRITIC_LR`), `GRAD_CLIP` (→ `GRAD_CLIP_GEN` / `GRAD_CLIP_CRITIC`), `CRITIC_CHANNELS` (→ `CRITIC_COLOR_CHANNELS` / `CRITIC_TEXT_CHANNELS`), `ENCODER_KERNEL` (→ `ENCODER_KERNEL_SIZE`), `BATCH_SIZE` (→ `TASK_BATCH_SIZE` / `GAN_BATCH_SIZE`), `TEXT_ENCODER_CHANNELS` (→ `ENCODER_CHANNELS`), `TASK_EPOCHS` / `GAN_EPOCHS` (→ `EPOCHS_TASK` / `EPOCHS_GAN`), `EMOJI_HEAD_HIDDEN_LAYERS`, `ENERGY_WEIGHT` (the OKLab energy term is monitor-only now), `FOCAL_ALPHA` / `FOCAL_GAMMA`, `ENCODER_RELU_SLOPE` / `GEN_RELU_SLOPE` / `CRITIC_RELU_SLOPE`.
- `data/labels.json` — a `styles` list and an `emojis` list. `emojis` = every emoji that survives `regen.ts`'s greedy `--min-count`/`--max-count` pass (descending by kept-record count, ties first-seen), regenerated by `bun run regen`; the vocab size is **dynamic** (whatever clears `--min-count`, default 50), not a fixed leaderboard length. Emojis are **open-set** in the corpus (annotator picks any emoji) and `data/labels.json` is just the current qualifying set. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `model/data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). The growth and annotation tools are not deterministic (LLM calls); `regen.ts` is pure **and deterministic** — both its shuffles run a `SEED`-seeded mulberry32 PRNG (`SEED = 42` in `tools/data/config.ts`), so a given `data/data.jsonl` + flags always yields the same kept-row set, emoji vocab, and train/eval split (`MRR/e/val` numbers are comparable across `regen` runs as long as `data/data.jsonl` and the `--min-count`/`--max-count`/`--n` flags are unchanged). `data/data.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex) is the **append-only master**: every growth tool appends to it and nothing ever rewrites or deletes from it. `data/train.jsonl`, `data/eval.jsonl` and `data/labels.json` are **gitignored artifacts** rebuilt from `data/data.jsonl` by `bun run regen` (`tools/data/regen.ts`) — it collapses rows sharing a `normalize(text)` key (union of emojis + closed-set styles; the **last** row in file order with a valid `bg`/`fg` sets the palette, so a re-annotated row appended after its original wins), shuffles the result and greedily keeps rows while capping each emoji's kept-record count at `--max-count` (default 1000; a row is dropped once any of its emojis is already at cap), takes every emoji with `count ≥ --min-count` (default 50) into `data/labels.json`'s dynamic vocab, then shuffles the kept rows again and splits them into `data/train.jsonl` + `data/eval.jsonl` (`--n`, default eval size 2000). Run `bun run regen` after any pull that changed `data/data.jsonl` and before training. The growth tools do no dedup and no length filtering and retry nothing across runs; near-duplicate rows are collapsed only in `regen` (by `normalize(text)` key). Run every script from the repo root. Path constants for all of this (`data/data.jsonl`, `data/train.jsonl`, `data/eval.jsonl`, `data/labels.json`, `data/keywords.json`, `data/energy_keywords.txt`, `data/pred.jsonl`) live in `files.ts` (root); the Python side's equivalents live in `files.py` (root).
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped. The palette section of the prompt (`PALETTE_GUIDANCE`, shared) steers toward the full saturation range and expressive dark/bright, text-driven, with **no target-colour awareness**. `annotateColors(texts)` → `Map<index, {bg, fg}>` is a lean palette-only path (`paletteInstructions()`: no emoji/style rules, schema `{id, bg, fg}`) used by `upsample.ts --reannotate colors`; it runs `resolvePaletteRepairing` (→ `repairFg`), which nudges an unreadable `fg`'s lightness toward black/white — keeping hue — until it clears `MIN_CONTRAST` against both `bg` stops, so a bold palette is fixed rather than dropped (only malformed hex or an extreme-lightness-range gradient still drops; tallied in `lastPaletteFix`). `expandEmojis(texts, existing)` → `Map<index, string[]>` is a lean emoji-only path (`expandEmojiInstructions()`: shows each row's current emojis, asks for a whitespace-separated string of **only new** emojis, schema `{id, add}`, `EXPAND_CONCURRENCY` default 100) used by `upsample.ts --reannotate emojis`; it never drops a row for a bad emoji reply (caller diffs the additions against the row's existing emojis and always accepts what survives).
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `data/data.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/regen.ts` (`bun run regen [--min-count 50] [--max-count 1000] [--n 2000] [--no-cldr] [--matrix] [--analysis]`) — rebuilds `data/train.jsonl` + `data/eval.jsonl` + `data/labels.json` from `data/data.jsonl` (plus `data/cldr.jsonl`, unless `--no-cldr`) in one command, **deterministically** (both shuffles run a `SEED`-seeded mulberry32, `SEED = 42` in `tools/data/config.ts`; the second shuffle seeds `SEED + 1`): union-merge by `normalize(text)`, shuffle and greedily keep rows while capping each emoji's kept-record count at `--max-count` (a row is dropped once any of its emojis is already at cap), take every emoji with a kept count `≥ --min-count` into the dynamic `data/labels.json` vocab (styles stay the fixed set), then shuffle the kept rows again and split the first `--n` into `data/eval.jsonl` (rest to `data/train.jsonl`). Prints a summary (rows read/kept/dropped, vocab size, most/least frequent kept emojis, split sizes). `--matrix` is a dry sweep that writes nothing: it prints a grid of `kept-rows / emoji-vocab` for `--min-count` ∈ {50, 75, 100, 125, 150, 200, 250} × `--max-count` ∈ {500, 600, 750, 1000, 1250, 1500, 2000, 3000, 4000, 5000}. `--analysis` writes **only** `docs/regen.md` (no train/eval/labels/baseline writes): it simulates the pipeline from `data/data.jsonl` alone (no `data/cldr.jsonl` merge, honoring `--min-count`/`--max-count`) and reports the emoji-vocab overlap with `data/cldr.jsonl` — a count summary plus three lists: emojis in both, in the train vocab only, and in `data/cldr.jsonl` only.
  - `tools/data/upsample.ts` (`bun run upsample`) — the single upsample tool; unifies what used to be separate `upsample-emojis.ts` / `upsample-emoji-test.ts` / `upsample-colors.ts` scripts, and is where a future kind of targeted upsampling gets added. Today it upsamples emoji-targeted rows: default mode reads `data/data.jsonl` to pick a rank-window of emojis by kept-record count (`--min-rank`/`--max-rank`, default 200-400) and generates texts for each; `--emojis <list>` targets exactly those emoji instead. `--rare` targets the rarest emoji in `data/data.jsonl` by record count: it drops emoji with fewer than `--min-freq` (default 10) records, sorts the rest ascending by count (rarest first, ties by first-seen) and takes the first `--max-count` (default 100 — a **target count, not a frequency cap**); `--per` defaults to 50, and `--iter <n>` (default 1, `--rare` only) repeats the whole select→generate→`annotate()`→append cycle `n` times, re-reading `data/data.jsonl` each pass so rows appended by earlier passes shift the counts and the rarest set is recomputed. Not standalone (like the rank window it injects the target emoji into each appended row) but mutually exclusive with `--emojis`/`--min-rank`/`--max-rank` and every standalone mode. `--negation` is a **standalone** mode (no emoji targeting — `--emojis`/`--min-rank`/`--max-rank` are ignored): it prompts the generator for `--count` (default 1000) negation-heavy short texts ("not good", "don't like it", "it isn't a dog it's a cat", refusals, denials, corrections), fanned over `VOICES` in batches of `--per`, and tags every appended row with a top-level `"neg": "true"` field. `--short` is another **standalone** mode (mutually exclusive with `--negation`/`--single-emoji`/`--colors`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank` ignored): it runs the plain generate→`annotate()`→append pipeline for `--count` (default 2000) short texts, fanned over `VOICES` in `--per` batches (default 50), but the generation prompt's length cap is the **weighted median normalized text length of the newest `report/*/report.json`** (`data.length_distribution`) instead of the standing 42 — biasing the corpus shorter; samples that come back longer than the median are kept anyway (no post-gen length filter), and it aborts if no report with a length distribution exists. Rows are tagged `"meta": {"src": "short"}`. `--single-emoji` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--colors`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--per` ignored): no generation at all — it reads `data/data.jsonl`, selects rows whose `normalize(text)` key is unique across the master **and** whose `emojis` string holds exactly one emoji, takes the first `--count` (default 5000) of them in file order, `annotate()`s their texts with the **default** prompt (no forcing), and appends a fresh row per successful annotation with the **re-annotation's** emojis replacing the original (rows re-annotated to zero emojis are dropped). `--colors` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--keywords`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--count` ignored): for each of a fixed colour list (`red, green, blue, dark, bright`) it prompts the generator for `--per` (default 1000, auto-chunked into 50-per-call batches over `VOICES`) short texts that use or evoke that colour, `annotate()`s them with the **default** prompt (no forcing — the annotator's palette is the training signal), and tags every appended row with a top-level `"color": "<name>"` field. `--reannotate <what>` (`what` = `colors` | `emojis`) is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--colors`/`--keywords`; `--emojis`/`--min-rank`/`--max-rank`/`--per` ignored): no generation — it reads `data/data.jsonl` and takes a `SEED`-seeded random sample of `--count` (default 300) rows that have a base palette and a `normalize(text)` key not already carrying **this mode's** marker field (`reannotatedKeys`, deduped by that key) — `colors` skips keys with a `reannotated` field, `emojis` skips keys with a `remojis` field, so the two modes are independent and a text can be re-annotated once by each. **`colors`** re-annotates **just the palette** via `annotateColors()` (widened palette-only prompt, no emoji/style forcing; an unreadable `fg` is lightness-nudged to clear `MIN_CONTRAST` rather than dropped), and appends a fresh row per success — original `emojis`/`styles` verbatim, the new `bg`/`fg`, a top-level `"reannotated": "colors"` marker, and `"meta": {"date": ..., "src": "reannotate"}`; `regen.ts:collapse`'s last-palette-wins rule means the appended row's palette supersedes the original at rebuild time. Also writes `preview/reannotate-<stamp>.jsonl` (old vs new `bg` pairs) and prints the mean-bg OKLab lightness/chroma shift. **`emojis`** re-annotates **just the emoji list** via `expandEmojis()` (shows the annotator the row's current emojis, asks only for *additional* relevant ones — not forced), diffs the reply against the existing emojis (`mergeEmojiAdditions`: drops repeats / unrecognized / dups, always accepts the rest), and appends a fresh row per annotator response — `styles`/`bg`/`fg` verbatim, `emojis` = original list **+** the new emojis, a top-level `"remojis": [...]` field holding **just the new emojis** as a JSON list (its presence is the emoji-reannotation marker), and `"meta": {"date": ..., "src": "reannotate"}`. Rows that gain no new emoji are still appended (`"remojis": []`); a row is dropped only when the annotator returns nothing for it. Also writes `preview/reannotate-emojis-<stamp>.jsonl` (`text` / `old` / `added`). `--keywords <kw1,kw2,...>` is another **standalone** mode (mutually exclusive with `--negation`/`--short`/`--single-emoji`/`--colors`/`--reannotate`; `--emojis`/`--min-rank`/`--max-rank`/`--count` ignored): for each comma-separated keyword (trimmed, de-duped) it prompts the generator for `--per` (default 50) short texts that naturally use that keyword, one keyword per generation call, `annotate()`s them with the **default** prompt (no forcing), and tags every appended row with a top-level `"keyword": "<kw>"` field. Generated/selected texts are `annotate()`d and appended to `data/data.jsonl`. `--dry` is a **global** flag (any mode): it runs only the target/plan selection, prints what would be upsampled (mode, target emoji / batch counts, approx texts), and exits before any generation, annotation, or append — with `--rare --iter>1` it reports only the first iteration, since later passes depend on rows an actual run would have appended. Every row `upsample.ts` appends (every mode) carries a `"meta": {"date": "YYYY-MM-DD", ...}` object — `--single-emoji` rows also get `"single-emoji": true`, `--short` rows `"src": "short"`, `--colors` rows `"src": "colors"`, `--keywords` rows `"src": "keywords"`, `--rare` rows `"src": "rare"`, `--reannotate` rows `"src": "reannotate"` (plus the top-level `"reannotated": "colors"` for `colors` / `"remojis": [...]` for `emojis`); `meta` (like `neg`/`color`/`keyword`/`reannotated`/`remojis`) is a non-base extra field, carried through by `regen.ts:collapse`, ignored by `model/data.py:read`, for filtering/eval-slicing only.
  - `tools/preview.ts` (`bun run preview`, or `bun tools/preview.ts [file]`) — the single preview tool; unifies what used to be separate `preview.ts` / `preview-pred.ts` scripts under `tools/data/`. Reads `data/data.jsonl`-schema rows (`text`, `emojis`, `styles`, `bg`, `fg`) — from a `.jsonl` file path argument, or from stdin when no argument is given — and writes one preview card per row to a `preview/<stamp>.html` grid (`--all` renders every emoji per card instead of just the first). `tools/data/preview-card.ts` (the shared `cardHtml`/`page` renderer) is unchanged; `tools/data/show-labels.ts` (`bun run show-labels`, renamed from `preview-labels.ts`) previews `data/labels.json`, not `data/data.jsonl`-schema rows. `tools/data/preview-model.ts` (ONNX model output preview) was removed as unused.
  - Extra row fields — growth tools may write fields beyond the base `{text, emojis, styles, bg, fg}` schema. They are kept for debugging, filtering, and eval slicing: `regen.ts:collapse` carries every non-base field through to `data/train.jsonl` / `data/eval.jsonl` (first-seen value wins when rows merge on a `normalize(text)` key) and never strips them, and `toLine` emits them after the base fields. They are **not** training signal — `model/data.py:read` matches only the base schema and ignores every other key. `upsample.ts` writes a `meta` object (`{"date": ..., "src"?: ..., "single-emoji"?: true}`) on every row it appends; older rows and `train.ts` rows carry no `meta`. `--reannotate colors` rows also carry a top-level `"reannotated": "colors"` marker (passed through like any extra field); their palette supersedes the original only because `regen.ts:collapse` takes the last palette in file order and the re-annotated row is appended after its original. `--reannotate emojis` rows carry a top-level `"remojis": [...]` list of the newly added emojis (marker + payload in one field); the row's `emojis` is the original list plus those additions.
- Eval set — historically `eval.jsonl` was a hand-curated hold-out (rows sampled from the corpus and kept only if styles + emojis were all correct, a full `bg`/`fg` palette was present, and raw length was 4–48; judged in-session, keep-or-drop, never relabeled). As of the data-files reorg it is a plain **seeded random split** of the `data/data.jsonl` master (`bun run regen`, first `--n` — default 2000 — rows of the post-greedy-cap kept set), not a curated set. The pre-reorg curated hold-out is recoverable from git history: `git show f9cb0e6:eval.jsonl`. `regen` is deterministic end to end (the greedy emoji-cap shuffle and the train/eval split both run a `SEED`-seeded mulberry32, not `Math.random`), so `data/eval.jsonl` membership — and the `data/labels.json` emoji vocab — changes only when `data/data.jsonl` or the `--min-count`/`--max-count`/`--n` flags change: `MRR/e/val` numbers are comparable across `regen` runs on the same `data/data.jsonl` + flags.
- **Training corpus:** `model/data.py` reads `data/train.jsonl` for training and `data/eval.jsonl` for validation; both are regenerated from the `data/data.jsonl` master by `bun run regen` and are gitignored (run `regen` after a fresh checkout or a pull that touched `data/data.jsonl`). `model/data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `data/labels.json` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`).
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `data/labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` (reads `data/labels.json`) fails until every label has an entry with a unique font. (`web/src/feelings.js`, `data/labels.json`, and `tools/data/styles.ts` currently all carry the same 21 styles.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `model/export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `model/data.py`) and `decodeColors`/`decodeColorList` (the inverse of `model/data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `model/export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors). All of `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Conventions

- Colors are a GAN, not a head: `model/model.py:ColorGen` maps `(1 - Z_WEIGHT) * L2-norm(text_embed) + Z_WEIGHT * L2-norm(z)` → 9 raw sRGB byte offsets (`tanh * COLOR_SHIFT`, `COLOR_SHIFT` = 127.5 in `model/color.py`), `z` unit-norm Gaussian noise. Trained in stage 2 against `model/model.py:ColorCritic` — a dual-branch dot-product scorer (text branch on the L2-normed text embedding, colour branch on the palette in **sRGB** rescaled to `[-1, 1]` by `1/COLOR_SHIFT` — **not** OKLab; the score is the bilinear term only), warm-started from `pt/critic.pt` and kept training with generator samples as negatives. Critic loss is pairwise BCE; generator loss is a relativistic hinge (`relu(critic(text, real).detach() − critic(text, gen) + GAN_GEN_MARGIN).mean()` — no L1/reconstruction, no energy term). The OKLab **energy distance** (`model/color.py:rgb_to_oklab` + `model/train.py:energy_distance`) is the stage-2 early-stop/checkpoint key (`energy/gan/val` vs. `energy/gan/ref`), never a training signal. `style`/`emoji` are the only classifier heads — both `model/train.py:lse_infonce` Log-Sum-Exp InfoNCE. `model/export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS`.
- `normalize` (in `model/data.py`) lowercases, collapses whitespace, trims, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `CHARS` carries `a–z` only (no `A–Z`), so `normalize`'s collapse key treats `"Paris"` and `"paris"` as the same text. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. `TextEncoder.forward` masks PAD positions to `-inf` before max-pooling **each conv block's** output over the time axis and concatenating the per-block pools, so pad steps never enter the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- Runnable Python checks — `model/test_runmeta.py`, `model/test_train_cli.py`, and `tools/test_report.py` (plain-assert scripts, `uv run python <path>`) — but still no pytest suite and no CI gate on them; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `train --local` (watch `F1/val` — the early-stop/checkpoint metric when emoji+critic heads are both on — alongside `MRR/e/val`, `MRR/s/val` and `auc/critic/val` in TensorBoard, and `energy/gan/val` vs. `energy/gan/ref` for the GAN stage; `pt/enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python model/pred.py --pt pt` for a `data/pred.jsonl` spot-check (threshold-based `top_labels`: styles 1–3, emojis exactly 1) and `uv run python tools/report.py` for the full run report (`report/<ts>-<sha>/report.html` — data record counts + text-length distribution, label counts, emoji `acc@k` on `data/eval.jsonl` / `data/keywords.json` / `data/cldr.jsonl`, and the Cards end-to-end gold-set section). Grow the corpus with `bun run train` and/or `bun run upsample`, then `bun run regen`.
- `.pt` files are `{"state_dict", "meta"}` blobs — save with `model/runmeta.py:save_pt`, load with `model/runmeta.py:load_pt` (returns `(state_dict, meta|None)`; `None` = legacy bare file).
