# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two labels: an emoji (`EMOJIS`, decoupled from feelings) and a feeling (`FEELINGS`), both loaded from `labels.json`. The shared trunk is `model.py:TextEncoder` — a char embedding → spectral-norm 1-D CNN stack (`MaxPool1d` between blocks) → global max-pool over time → a `TEXT_EMBED_SIZE` vector (no recurrence). On top of it: `FeelingHead` (`Linear` → feeling logits, cross-entropy, backprops into the encoder) and `EmojiHead` (`Linear` → L2-normed query `q`; in-batch InfoNCE against an L2-normed emoji embedding table; emoji logits = `q @ emoji_vec.t()`). Colors are a **conditional GAN**, not a head: `model.py:ColorGen` maps `cat(z[GEN_Z_DIM], q[EMOJI_EMBED_SIZE])` → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground), NOT OKLab. It is trained adversarially (`ColorTst` critic) against the corpus `bg`/`fg` hex (`data.py:colors2tensor` = RGB bytes − 127.5); no reconstruction/L1 loss (many colors fit one text). Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Feeling only selects a font + animation.

- `train.py` — `LitTask` (encoder + feeling + emoji, early-stop/checkpoint on `f1/val` = harmonic mean of feeling acc@5 and emoji acc@10) and `LitColorGAN` (color GAN on a **frozen** encoder+emoji). `uv run python train.py` trains both stages and saves five loose state dicts: `enc.pt`, `feels.pt`, `emoji.pt`, `gen.pt`, `tst.pt` (all gitignored).
- `train_gan.py` — retrains just the GAN stage against pre-saved `enc.pt` + `emoji.pt`, re-saving `gen.pt` / `tst.pt`.
- `run.py` — batch inference over `eval.jsonl` → `pred.jsonl` (the reference implementation of the inference graph).
- `export_onnx.py` — `uv run python export_onnx.py` loads `enc.pt` / `feels.pt` / `emoji.pt` / `gen.pt`, wraps them, and writes `web/public/model.onnx` + `meta.json` + `config.json`. The GAN is sampled with **5 predefined constant noise vectors** baked into the graph (seeded by `SEED`), so `color` is a `[5, 9]` output — 5 deterministic palettes per text.
- `config.py` — flat module of hyperparameters (`MAX_TEXT_LEN`, `BATCH_SIZE`, `CHAR_EMBED_SIZE`, `TEXT_ENCODER_CHANNELS`, `ENCODER_KERNEL`, `EMOJI_EMBED_SIZE`, `GEN_CHANNELS`, `GEN_Z_DIM`, `CRITIC_CHANNELS`, `LR`, `GAN_LR`, `GRAD_CLIP`, `INFONCE_TEMP`, `TASK_EPOCHS`, `GAN_EPOCHS`, …); `FEELINGS`/`EMOJIS` are read from `labels.json` here.
- `labels.json` — the `feelings` and `emojis` lists, regenerated by `tools/data/labels.ts` from `train.jsonl`: `feelings` = top 32, `emojis` = top 200 (`TOP_FEELINGS` / `TOP_EMOJIS` in `tools/data/config.ts`), each by frequency (descending, ties keep first-seen order). Both label sets are **open-set** in the corpus — the annotator picks any capitalized feeling word and any emoji; `labels.json` is just the current frequency leaderboard.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). Not deterministic. `train.jsonl` (one JSON object per line: `text`, `feeling`, `emoji`, `bg`, `fg`, plus `meta` on rows written since the coverage update) is the corpus the new pipeline grows; the legacy `data.jsonl` (same shape) is a fixed pool that `re-annotate.ts` drains into `train.jsonl`. No dedup, no length filtering, nothing retried across runs. Run every script from the repo root.
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emoji, feeling}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt is general — best emoji (any emoji, no rare/common bias), best single feeling word (common preferred, `Neutral` allowed but not encouraged), no label list given.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `train.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage, and the batch's topic is recorded on every row it produces. Phase 2: `annotate()` every text; each annotated text is written as `{text, feeling, emoji, bg, fg, meta}` (texts that fail annotation are dropped).
  - `tools/data/re-annotate.ts` (`bun run tools/data/re-annotate.ts`) — reads a random `SAMPLE_SIZE` (2,000) rows from `data.jsonl`, keeps each `text` and re-derives both labels via `annotate()`. Rows that annotate successfully are appended to `train.jsonl` and removed from `data.jsonl` (count-aware); rows that fail stay in `data.jsonl` for a later run.
  - `tools/data/upsample-emojis.ts` (`bun run upsample-emojis`) — reads `train.jsonl`, counts each `labels.json` emoji's rows (palette emojis absent count 0; non-palette emojis ignored), takes the `RARE_EMOJI_COUNT` (60) rarest, generates `TEXTS_PER_EMOJI` (40) voice-spread texts per emoji (emoji never named), runs the shared `annotate()` (open-set labels + `bg`/`fg`), and appends every annotated row to `train.jsonl` with `meta.target_emoji`. No dedup, no length pre-filter — `data.py` filters at load.
  - `tools/data/upsample-feelings.ts` (`bun run upsample-feelings`) — same shape, seeded by the `FEELINGS_PER_RUN` (3) rarest `labels.json` feelings (counting only rows whose emoji is also in the palette), `BATCHES_PER_FEELING` (20) batches of `GEN_BATCH_SIZE` (100) per feeling; appends with `meta.target_feeling`.
  - `tools/data/labels.ts` (`bun run tools/data/labels.ts`) — rewrites `labels.json` (top 32 feelings + top 200 emojis in `train.jsonl`, as above).
  - `tools/data/stat.ts` (`bun run tools/data/stat.ts`) — writes `report/data-stat/<MM-DD-HH:MM>.md` summarizing `train.jsonl` and `eval.jsonl` side by side (row counts, feeling distribution, raw text-length histogram + count outside 4–48, emoji distribution). Auto-run by the `.claude/settings.json` PostToolUse hook whenever `train.jsonl` or `eval.jsonl` is written.
  - Provenance `meta` — every row written by `train.ts` / `upsample-emojis.ts` / `upsample-feelings.ts` / `re-annotate.ts` carries `meta`: `{src, v, at (YYYY-MM-DD), model, params}` plus `topic` (train only) or `target_emoji` / `target_feeling` (upsamplers only). `v` is the per-script logic version — bump it by hand when a script's generation/annotation logic changes. Pre-existing rows have no `meta`; `data.py:read` ignores the field either way. Groundwork for later data cleaning.
- Eval set — the `generate-eval-jsonl` skill (`.claude/commands/generate-eval-jsonl.md`) samples 1,200 rows from `train.jsonl`, keeps only the ones whose feeling **and** emoji are correct and whose raw text length is 4–48 (judged in-session, keep-or-drop, never relabeled), appends those to `eval.jsonl`, and removes them from `train.jsonl` (count-aware). The pre-migration holdout is preserved as `eval.jsonl.bak`.
- **Training corpus:** `data.py` reads `train.jsonl` for training and `eval.jsonl` for validation; `data.jsonl` is legacy and is never trained on directly — `re-annotate.ts` migrates it into `train.jsonl`. `_load` still filters to the closed `labels.json` palette (rows whose feeling/emoji is out-of-vocab, or whose normalized text exceeds `MAX_TEXT_LEN`, are skipped).
- **Web feeling styling:** `web/` consumes the `meta.json` feelings list; `web/src/feelings.js` gives **each** feeling its own Google font family plus a per-feeling `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any feeling not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the feeling leaderboard (`meta.json` / `labels.json`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` fails until every feeling has an entry with a unique font.
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-feeling font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `data.py`) and `decodeColors`/`decodeColorList` (the inverse of `data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `feeling_logits`, `emoji_logits` (`q @ emoji_vec.t()`), and `color` (`[5, 9]`, from 5 constant noise vectors).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run python train.py` trains the task stage then the GAN stage (see `TASK_EPOCHS` / `GAN_EPOCHS` in `config.py`) and writes `enc.pt` / `feels.pt` / `emoji.pt` / `gen.pt` / `tst.pt`. Slow — don't use it as a smoke test. `train_gan.py` retrains only the GAN. `onnx` + `onnxscript` (dev deps) are required by `export_onnx.py`.
- Refresh the site's model without retraining: `uv run python export_onnx.py` reloads the `.pt` files and rewrites `web/public/model.onnx` + `meta.json` + `config.json` (no training). The `.pt` files are gitignored, so commit the regenerated `web/public/` files; pushing `web/**` to `main` triggers the Pages deploy.
- Run the web app locally with `cd web && npm install && npm run dev`; `npm test` (in `web/`) runs the vitest suite, `npm run build` writes `web/dist`.
- Training writes TensorBoard logs to `runs/<CONFIG_NAME>/` (task run) and `runs/<CONFIG_NAME>/gan` (GAN run); `CONFIG_NAME` (in `config.py`) encodes a timestamp + model/train hyperparameters. View with `uv run tensorboard --logdir runs`.
- The data toolchain is Bun, not `uv`: `bun install`, then (from the repo root) grow the corpus with `bun run tools/data/train.ts`, `bun run tools/data/re-annotate.ts`, and/or the rare-label upsamplers `bun run upsample-emojis` / `bun run upsample-feelings`, then `bun run tools/data/labels.ts` to refresh `labels.json`. package.json aliases (root-relative): `bun run train` / `re-annotate` / `upsample-emojis` / `upsample-feelings` / `labels` / `stat`.
- Non-model scripts live under `tools/data/`; the model stack — `config.py`, `data.py`, `model.py`, `train.py`, `train_gan.py`, `run.py`, `export_onnx.py` — stays at the repo root. `test_model.py` is stale (imports a removed `Model` class). All tool scripts assume the repo root as CWD.
- Python 3.13.

## Conventions

- Colors are a GAN, not a head: `model.py:ColorGen` maps `cat(z, q)` → 9 raw sRGB byte offsets (`tanh * 127.5`), where `q` is the L2-normed emoji query from `EmojiHead` and `z ~ N(0, I)` of dim `GEN_Z_DIM`. Trained adversarially via `ColorTst` (BCE, spectral norm, no gradient penalty, **no L1/reconstruction term**) against `data.py:colors2tensor(row.bg, row.fg)` (RGB bytes − 127.5). `feeling`/`emoji` are the only classifier heads (cross-entropy / InfoNCE). `export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` just clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS` is used.
- `normalize` (in `data.py`) collapses whitespace, trims, lowercases, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. The encoder is a 1-D CNN with a global max-pool over the time axis (`torch.max(out, dim=-1)`), so trailing pad steps do not shift the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No Python test suite; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run python train.py` (watch `f1/val` in TensorBoard; `enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python run.py` for a `pred.jsonl` spot-check. Grow the corpus with `bun run tools/data/train.ts` and/or `bun run tools/data/re-annotate.ts`, then `bun run tools/data/labels.ts`.
