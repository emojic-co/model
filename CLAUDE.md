# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level LSTM (`main.py`) that maps a short text string to two labels: an emoji (`EMOJIS`, a 300-emoji palette, fully decoupled from feelings) and a feeling (`feeling`, the 7 in `labels.json`: Happy, Calm, Sad, Angry, Anxious, Neutral, Love). Both label sets are loaded from `labels.json`. Colors are **not** learned and never pass through Python: `web/public/palette.json` maps each feeling to fixed hex colors for `bg1`/`bg2` (gradient background) and `text_color` (foreground), and `web/src` fetches it directly.

- `main.py` — data loading, model, training, eval, `predict`, and `export_web` (writes `web/public/model.onnx` + `web/public/meta.json`).
- `config.py` — flat module of training hyperparameters (`LR`, `BATCH_SIZE`, `EMBED_SIZE`, `H_SIZE`, `NUM_LAYERS`, `MAX_TEXT_LEN`, `GRAD_CLIP`, `EPOCHS`); imported by `main.py`.
- `labels.json` — the `feelings` and `emojis` lists, shared by `data.py` and `tools/data/gen_labels.ts`. `feelings` is a fixed closed set of 7; `emojis` is regenerated by `tools/data/gen_labels.ts` (top 300 by frequency in `data.jsonl`).
- Data pipeline (`tools/data/`) — two independent generator scripts plus a label refresher, each using the Vercel AI SDK + GPT-5.6 Luna via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). Not deterministic; each run **appends** to `data.jsonl` and grows the corpus. There is no intermediate file — each generator does generation + annotation in one run, both phases `PQueue`-parallelized, and nothing is retried across runs (a failed generate/annotate batch is logged and dropped; the next run regenerates). Run every tool script from the repo root (paths inside them are root-relative).
  - `tools/data/feeling2emoji.ts` (`bun run tools/data/feeling2emoji.ts`) — rebalances feelings. Reads `data.jsonl`, picks the 3 `labels.json` feelings with the least coverage (ties: `labels.json` order), generates short WhatsApp-style texts (≤ 50 chars) that convey them across an emotion-neutral voice spread (round-robin, ~500 per feeling), then emoji-annotates the fresh, deduped texts in batches (emoji = free choice; feeling carried through). Appends `{feeling, text, emoji}` to `data.jsonl`. Dedup + the `MAX_TEXT_LEN` pre-annotation cut use `data.py`'s normalize key.
  - `tools/data/emoji2feeling.ts` (`bun run tools/data/emoji2feeling.ts`) — upsamples rare emojis. Reads `data.jsonl`, counts each `labels.json` emoji's rows (palette emojis absent from `data.jsonl` count as 0; emojis outside the palette ignored), takes the 100 least represented (rarest first, ties keep `labels.json` order), generates 20 short texts per emoji (one batch each, voice-spread; emoji never named in the output), then feeling-annotates the fresh, deduped texts in batches against the closed `labels.json` feelings list (emoji carried through; annotations outside the list are dropped). Appends `{emoji, text, feeling}` to `data.jsonl`.
  - `tools/data/gen_labels.ts` (`bun run tools/data/gen_labels.ts`) — rewrites `labels.json`: feelings untouched, emojis = top 300 by frequency in `data.jsonl` (descending, ties keep first-seen order).
  - `tools/data/fix.ts` (`bun run tools/data/fix.ts`) — one-off corpus re-annotation: keeps `data.jsonl` texts, re-derives both labels, rebuilds `labels.json` by `MIN_COUNT`, moves originals to `*.bak`.
  - `tools/data/scan_text_len.py` (`uv run tools/data/scan_text_len.py [--prune]`) — reports (or prunes) `data.jsonl` rows whose normalized text exceeds `MAX_TEXT_LEN`.
- Eval-set tooling (`tools/eval/`):
  - `tools/eval/gen_eval.ts` (`bun run tools/eval/gen_eval.ts [--force]`) — builds the balanced, feeling-perfect `eval.jsonl` holdout, cold-verified and deduped against `data.jsonl`. Never touches `data.jsonl`.
  - `tools/eval/eval-stat.py` (`uv run python tools/eval/eval-stat.py`) — writes `report/eval/<MM-DD-HH:MM>.md` summarizing `eval.jsonl` (feeling / length / emoji distributions). Auto-run by the `.claude/settings.json` PostToolUse hook whenever `eval.jsonl` is written.
- `data.jsonl` is append-only; `data.py`'s `read()` does all filtering at load time (drops rows whose feeling/emoji isn't in `labels.json`, or whose normalized text exceeds `MAX_TEXT_LEN`).
- `data.jsonl` — one JSON sample per line: `text`, `emoji`, `feeling` (no color fields).
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `train.py`'s `export_web` (`model.onnx`, `meta.json`, `config.json`) plus the hand-maintained `palette.json` (per-feeling hex colors). `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` and must stay byte-identical to `train.py`. Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `train.py`'s `ExportWrapper` still replaces `pack_padded_sequence` with a `gather` so the LSTM traces to ONNX.
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run main.py` trains for `EPOCHS` epochs (see `config.py`), writes `model.pt`, refreshes `web/public/model.onnx` + `web/public/meta.json`, and prints a sample inference. This is slow — don't use it as a smoke test. `onnx` + `onnxscript` (dev deps) are required by the ONNX export.
- Refresh the site's model without retraining: `uv run main.py --export-only` rewrites `web/public/model.onnx` + `web/public/meta.json` from the committed `model.pt`. Commit `model.pt` and the regenerated `web/public/` files together; pushing `web/**` to `main` triggers the Pages deploy.
- Run the web app locally with `cd web && npm install && npm run dev`; `npm test` (in `web/`) runs the vitest suite, `npm run build` writes `web/dist`.
- Training writes TensorBoard logs to `runs/<config-name>/` (run name, from `run_name()`, encodes embed/hidden/layers/lr/batch/epochs); view with `uv run tensorboard --logdir runs`.
- The generator toolchain is Bun, not `uv`: `bun install`, then (from the repo root) run either generator followed by `gen_labels.ts` — `bun run tools/data/feeling2emoji.ts` → `bun run tools/data/gen_labels.ts` (rebalance feelings) or `bun run tools/data/emoji2feeling.ts` → `bun run tools/data/gen_labels.ts` (upsample rare emojis). package.json aliases (also root-relative): `bun run feeling2emoji` / `emoji2feeling` / `labels` / `gen_eval` / `fix`.
- Non-model scripts live under `tools/<group>/` (`tools/data/`, `tools/eval/`); the model stack — `config.py`, `data.py`, `model.py`, `train.py` — and the behavioral suite `test_model.py` stay at the repo root. All tool scripts assume the repo root as CWD.
- Python 3.13.

## Conventions

- Colors are a fixed lookup, not a model head: `web/public/palette.json` holds one `{bg1, bg2, text_color}` of hex strings per feeling (warm/bright for Happy, cool for Calm, muted/dark for Sad/Anxious, dark saturated red for Angry, neutral grey for Neutral). `web/src` fetches it and drops the values straight into CSS / canvas fills, falling back to `Neutral` for any unlisted feeling. The model has only two heads (`emoji`, `feeling`), both cross-entropy; there is no color loss.
- `normalize` (in `main.py`) collapses whitespace, lowercases, then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` also invalidates the committed `model.pt` (retrain) and reshuffles the hash-based train/test split.
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses `padding_idx=0`. The LSTM is fed via `pack_padded_sequence`, so the classifier reads the hidden state at each row's last real character, not a trailing pad step. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No Python test suite; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run main.py`: loss should decrease, `feeling_acc` trains well, `emoji_acc` is weak at the current `H_SIZE`/`EMBED_SIZE` and thin/imbalanced `data.jsonl`. Grow the corpus with `bun run tools/data/feeling2emoji.ts` or `bun run tools/data/emoji2feeling.ts`, then `bun run tools/data/gen_labels.ts`; `feelings` in `labels.json` is the only label set edited by hand.
