# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, a dynamic-size frequency vocab — see `regen.ts` below) and styles (`STYLES`, 21 — a fixed closed set), both loaded from `labels.json`. A row carries 0–N emojis and 1–N styles. The shared trunk is `model.py:TextEncoder` — a char embedding → a stack of `len(ENCODER_CHANNELS)` spectral-norm `Conv1d` blocks (each `spectral_norm(Conv1d, padding=ENCODER_KERNEL//2) → LeakyReLU`; constant time length, **no pooling between blocks**, BatchNorm commented out) → PAD positions masked to `-inf` → one global max over time → a `TEXT_EMBED_SIZE` (= `ENCODER_CHANNELS[-1]`) vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` L2-norms this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead`, now **structurally identical** — `Dropout → Linear(TEXT_EMBED_SIZE → *_EMBED_SIZE, bias=False)` (`STYLE_EMBED_SIZE` 12 / `EMOJI_EMBED_SIZE` 48), then project against a learned label-embedding table (`nn.Embedding(n_labels, *_EMBED_SIZE)`, `logits = proj @ embed.weight.t() + bias`) → per-label logits. (`EmojiHead` no longer has an MLP; `EMOJI_HEAD_HIDDEN_LAYERS` was removed.) Both heads train as retrieval with `train.py:lse_infonce` — a multi-positive Log-Sum-Exp InfoNCE (`logsumexp` over all label logits − `logsumexp` over the row's positive logits, scaled by `INFONCE_TEMP`), averaged over rows with ≥1 positive (emoji rows carrying no emoji drop out). Both backprop into the encoder; no focal loss, no BCE/`pos_weight`, no softmax cross-entropy. Colors are a **conditional GAN**, not a head: `model.py:ColorGen` conditions on the **text embedding**, mixing it with unit-norm noise `z` as `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground). The generator loss is **adversarial BCE only** — no reconstruction/L1, no energy term (many colors fit one text); `ColorGen`'s output stays in sRGB, but the `ColorDsc` critic (conditioned on the same text embedding) consumes the palette in **OKLab** (`model.py:rgb_to_oklab`). Separately, an **OKLab energy distance** between the generator's samples and the real palette distribution is computed at validation as `energy/gan/val` (against a split-half real-vs-real `energy/gan/ref` baseline) and is the GAN stage's early-stop / checkpoint metric — **monitored, never backpropagated**. Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `train.py` — single Typer CLI, `train <task|gan|all> [--local] [--cpu N] [--memory MIB]`, installed as a `train` console script (`[project.scripts]` in `pyproject.toml`; also runnable as `uv run python train.py ...` or `uv run train ...`) with free shell-completion (`train --install-completion`). `model` picks which stage(s) run: `task` (encoder + `LitTask`'s style/emoji heads, both trained with `train.py:lse_infonce` Log-Sum-Exp InfoNCE; early-stop/checkpoint via `ModelCheckpoint`/`EarlyStopping` on `MRR@10/e/val` — emoji top-10 mean reciprocal rank from the hand-rolled `train.py:mrr_at_k`. Both `train.py:ap_at_k` (mAP) and `mrr_at_k` (MRR) are logged for each head at `EMOJI_AP_K`/`STYLE_AP_K` (10/5) from `config.py`, plus `f1/val` = harmonic mean of the two mAPs — no `torchmetrics`; emoji AP/MRR are measured only over rows carrying ≥1 emoji. **Planned:** also logging `acc@1`/`acc@10` (emoji) and `acc@1`/`acc@5` (style) on val — the stated priority metric set — is not wired into `train.py` yet; `acc@k` today lives only in the `tools/report.py` keyword probe); `gan` (`LitColorGAN` — color GAN on a **frozen** encoder; conditions on the encoder's text embedding, does not touch the classifier heads; GAN stage early-stop/checkpoint on `energy/gan/val`, min — trained against a pre-saved `enc.pt`); `all` (task then gan, back to back, reloading the best task checkpoint before the GAN stage — the old bare `train.py`'s behavior). Location defaults to Modal (same machinery as the old `train-modal.py`: image build, artifact volume, TensorBoard tunnel, `EMOJIC_GIT_SHA`/`EMOJIC_DISPATCH_CHECKED` so Modal-trained `.pt` files carry the dispatch commit SHA); pass `--local` to run on this machine instead (`--cpu`/`--memory` then don't apply and are rejected). `task`/`all` train their own encoder wherever they run; `gan` needs a pre-trained `enc.pt` **and** `style.pt`/`emoji.pt` (the latter two only for the post-training `export()`, not for the GAN training itself) — locally they must already be on disk, and on Modal the local `enc.pt`/`style.pt`/`emoji.pt` bytes are uploaded into the remote container before training (so a from-scratch Modal `gan` run needs a prior `train task --local`, or `train task`'s artifacts already fetched back). After training, `task` alone runs `tools/report.py --only data,emoji,style` (no `gen.pt` yet, so Colors is skipped); `gan` and `all` refresh `web/public/` via `export_onnx.py` and run the full `tools/report.py`. `uv run modal run train.py::main -- --model <task|gan|all> [--cpu N] [--memory MIB] [--fetch-only]` reaches the same Modal dispatch directly through the Modal CLI — used by `Taskfile.yml`'s detached `modal-train` task, since that needs Modal's own `--detach` semantics rather than a plain blocking call; `--fetch-only` recovers artifacts from an interrupted run's volume without starting a new one. Code + data files are `add_local_file`d into the Modal image at build time, so run `bun run regen` **locally first** — Modal does not regen. Aborts on a dirty git tree in every mode (`runmeta.require_clean_tree`, no override).
- `tools/report.py` — `uv run python tools/report.py [--only data,emoji,style,color] [--out report]` is the **single** model + data report. It loads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt` (missing or shape-mismatched `.pt` are skipped, not fatal) and writes one `report/<YY-MM-DD-HH-MM>-<model-sha>/{report.html,report.json}` per run. Sections: **Data** (record counts for `data.jsonl` / `train.jsonl` / `eval.jsonl`); **Emojis** (distinct-emoji counts per file; a top-10 + bottom-10 `train.jsonl` frequency bar chart; `EmojiHead` retrieval `acc@{1,5,10}` + `MRR@10` on `eval.jsonl`; a `words.json` keyword probe — `acc@{1,3,5,10}` + `MRR` + the full per-word rank list, worst 10 shown); **Styles** (a full 21-label `train.jsonl` distribution bar chart; `StyleHead` retrieval `acc@{1,5}` + `MRR@5` + `mAP@5` on `eval.jsonl`); **Colors** (a `bg`-colour distribution over 5 OKLab anchors + *other*; whole-eval OKLab energy `gen↔real` vs `real↔real` floor + gap; 6 big colour cards feeding the bare colour name into the model and reporting a ΔE<`COLOR_DELTA_E` hit-rate vs a random-text baseline → *text-driven* / *weak* / *random*). A header banner flags provenance issues (`.pt` from different commits, model `train_sha` ≠ current `train.jsonl`, missing `.pt`). `report.json` mirrors the HTML under `provenance` / `data` / `emoji` / `style` / `color`. Auto-runs at the end of every `train.py <task|gan|all> --local` run (and inside the Modal container for `task`/`gan`/`all` dispatched to Modal); re-run it by hand after `bun run regen`. Thresholds for the colour-tinted metric cards and the anchor set are module constants in `tools/report.py`.
- `run.py` — inference over the first 200 `eval.jsonl` rows → `pred.jsonl` (reference implementation of the inference graph; one GAN palette per row).
- `export_onnx.py` — `uv run python export_onnx.py` loads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt`, wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. Outputs are `style_logits`, `emoji_logits`, `color`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji.pt` label counts disagree with `labels.json`.
- `config.py` — flat module of hyperparameters: `MAX_TEXT_LEN`, `SEED`, `CHAR_EMBED_SIZE`, `ENCODER_CHANNELS` (list; `TEXT_EMBED_SIZE = ENCODER_CHANNELS[-1]`), `ENCODER_KERNEL`, `RELU_SLOPE` (one shared LeakyReLU slope for the encoder, both heads, GAN generator, and critic), `EMOJI_EMBED_SIZE`, `STYLE_EMBED_SIZE`, `DROPOUT_EMOJI`, `DROPOUT_STYLE`, `Z_WEIGHT`, `GEN_CHANNELS`, `CRITIC_CHANNELS`, `GAN_LR`, `LR`, `GRAD_CLIP`, `INFONCE_TEMP`, `TASK_BATCH_SIZE`, `GAN_BATCH_SIZE`, `EPOCHS_TASK`, `EPOCHS_GAN`, `VAL_CHECK_INTERVAL`, `EARLY_STOP_PATIENCE`, `EMOJI_AP_K` / `STYLE_AP_K` (10 / 5), and the energy-eval knobs `ENERGY_Z_SAMPLES` / `ENERGY_KEYWORD_MIN_TEXTS` / `ENERGY_KEYWORD_MAX_TEXTS` / `ENERGY_KEYWORDS_PATH`. `CONFIG_NAME` (timestamp + hyperparams, the TensorBoard run name) is built here, and `STYLES` / `EMOJIS` are read from `labels.json` here. Removed: `BATCH_SIZE` (→ `TASK_BATCH_SIZE` / `GAN_BATCH_SIZE`), `TEXT_ENCODER_CHANNELS` (→ `ENCODER_CHANNELS`), `TASK_EPOCHS` / `GAN_EPOCHS` (→ `EPOCHS_TASK` / `EPOCHS_GAN`), `EMOJI_HEAD_HIDDEN_LAYERS`, `ENERGY_WEIGHT` (the OKLab energy term is monitor-only now), `FOCAL_ALPHA` / `FOCAL_GAMMA`, `ENCODER_RELU_SLOPE` / `GEN_RELU_SLOPE` / `CRITIC_RELU_SLOPE`.
- `labels.json` — a `styles` list and an `emojis` list. `emojis` = every emoji that survives `regen.ts`'s greedy `--min-count`/`--max-count` pass (descending by kept-record count, ties first-seen), regenerated by `bun run regen`; the vocab size is **dynamic** (whatever clears `--min-count`, default 100), not a fixed leaderboard length. Emojis are **open-set** in the corpus (annotator picks any emoji) and `labels.json` is just the current qualifying set. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). The growth and annotation tools are not deterministic (LLM calls); `regen.ts` is pure but **not deterministic** — it shuffles unseeded, so the exact kept-row set, emoji vocab, and train/eval split differ run to run (`MRR@10/e/val` / `f1/val` numbers are only comparable within one `regen` invocation, not just one `data.jsonl` snapshot). `data.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex) is the **append-only master**: every growth tool appends to it and nothing ever rewrites or deletes from it. `train.jsonl`, `eval.jsonl` and `labels.json` are **gitignored artifacts** rebuilt from `data.jsonl` by `bun run regen` (`tools/data/regen.ts`) — it collapses rows sharing a `normalize(text)` key (union of emojis + closed-set styles, one palette hash-picked), shuffles the result and greedily keeps rows while capping each emoji's kept-record count at `--max-count` (default 500; a row is dropped once any of its emojis is already at cap), takes every emoji with `count ≥ --min-count` (default 100) into `labels.json`'s dynamic vocab, then shuffles the kept rows again and splits them into `train.jsonl` + `eval.jsonl` (`--n`, default eval size 1500). Run `bun run regen` after any pull that changed `data.jsonl` and before training. The growth tools do no dedup and no length filtering and retry nothing across runs; near-duplicate rows are collapsed only in `regen` (by `normalize(text)` key). Run every script from the repo root.
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `data.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/regen.ts` (`bun run regen [--min-count 100] [--max-count 500] [--n 1500]`) — rebuilds `train.jsonl` + `eval.jsonl` + `labels.json` from `data.jsonl` in one command, unseeded throughout: union-merge by `normalize(text)`, shuffle and greedily keep rows while capping each emoji's kept-record count at `--max-count` (a row is dropped once any of its emojis is already at cap), take every emoji with a kept count `≥ --min-count` into the dynamic `labels.json` vocab (styles stay the fixed set), then shuffle the kept rows again and split the first `--n` into `eval.jsonl` (rest to `train.jsonl`). Prints a summary (rows read/kept/dropped, vocab size, most/least frequent kept emojis, split sizes).
  - `tools/data/upsample.ts` (`bun run upsample`) — the single upsample tool; unifies what used to be separate `upsample-emojis.ts` / `upsample-emoji-test.ts` / `upsample-colors.ts` scripts, and is where a future kind of targeted upsampling gets added. Today it upsamples emoji-targeted rows: default mode reads `labels.json` + `data.jsonl` to pick a rank-window of emojis by kept-record count (`--min-rank`/`--max-rank`, default 200-400) and generates texts for each; `--emojis <list>` targets exactly those emoji instead; `--report` targets emoji failing the latest report's `words.json` keyword probe (reads the newest `report/<ts>-<sha>/report.json`'s `emoji.keywords.words`). Generated texts are `annotate()`d and appended to `data.jsonl`.
  - `tools/preview.ts` (`bun run preview`, or `bun tools/preview.ts [file]`) — the single preview tool; unifies what used to be separate `preview.ts` / `preview-pred.ts` scripts under `tools/data/`. Reads `data.jsonl`-schema rows (`text`, `emojis`, `styles`, `bg`, `fg`) — from a `.jsonl` file path argument, or from stdin when no argument is given — and writes one preview card per row to a `preview/<stamp>.html` grid (`--all` renders every emoji per card instead of just the first). `tools/data/preview-card.ts` (the shared `cardHtml`/`page` renderer) and `tools/data/preview-model.ts` / `tools/data/preview-labels.ts` (which preview ONNX model output and `labels.json` respectively, not `data.jsonl`-schema rows) are unchanged.
  - Extra row fields — growth tools may write fields beyond the base `{text, emojis, styles, bg, fg}` schema. They are kept for debugging, filtering, and eval slicing: `regen.ts:collapse` carries every non-base field through to `train.jsonl` / `eval.jsonl` (first-seen value wins when rows merge on a `normalize(text)` key) and never strips them, and `toLine` emits them after the base fields. They are **not** training signal — `data.py:read` matches only the base schema and ignores every other key (this also covered the old `meta` field, which no row carries anymore).
- Eval set — historically `eval.jsonl` was a hand-curated hold-out (rows sampled from the corpus and kept only if styles + emojis were all correct, a full `bg`/`fg` palette was present, and raw length was 4–48; judged in-session, keep-or-drop, never relabeled). As of the data-files reorg it is a plain **unseeded random split** of the `data.jsonl` master (`bun run regen`, first 1500 rows of the post-greedy-cap kept set by default), not a curated set. The pre-reorg curated hold-out is recoverable from git history: `git show f9cb0e6:eval.jsonl`. `regen` is unseeded end to end (the greedy emoji-cap shuffle and the train/eval split both use `Math.random`), so `eval.jsonl` membership — and the `labels.json` emoji vocab — changes on **every** `regen` run, not just when `data.jsonl` grows: `MRR@10/e/val` / `f1/val` numbers are only comparable within a fixed `.pt` + `train.jsonl`/`eval.jsonl` pair, never across two `regen` runs.
- **Training corpus:** `data.py` reads `train.jsonl` for training and `eval.jsonl` for validation; both are regenerated from the `data.jsonl` master by `bun run regen` and are gitignored (run `regen` after a fresh checkout or a pull that touched `data.jsonl`). `data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `labels.json` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`).
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` fails until every label has an entry with a unique font. (`web/src/feelings.js`, `labels.json`, and `tools/data/styles.ts` currently all carry the same 21 styles.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `data.py`) and `decodeColors`/`decodeColorList` (the inverse of `data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors). All of `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".
- Generated docs & reports — `model.md` (regenerated by the `update-model-md` skill) and `data.md` are prose descriptions of the model and corpus; both can lag the code, so treat them as background, not spec. `report/` holds git-tracked per-run folders `report/<YY-MM-DD-HH-MM>-<model-sha>/` (one per run), each with `report.html` + `report.json` written by `tools/report.py` — the **only** report generator, and the only thing under `report/`. No `.md` reports, no `meta.yml`, no per-type subtrees. Preview tools write to gitignored `preview/`.

## Conventions

- Colors are a GAN, not a head: `model.py:ColorGen` maps `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → 9 raw sRGB byte offsets (`tanh * 127.5`), where `text_embed` is the `TextEncoder` output, **L2-normed inside `ColorGen.forward`** (not the emoji query), and `z` is unit-norm Gaussian noise the same size. Trained adversarially via `ColorDsc` (BCE, spectral norm, no gradient penalty, **no L1/reconstruction term and no energy term in the generator loss**), critic conditioned on the same `text_embed` and fed the palette in OKLab (`model.py:rgb_to_oklab`), against `data.py:colors2tensor([*row.bg, row.fg])` (RGB bytes − 127.5). The OKLab **energy distance** to the real palette distribution (`train.py:energy_distance`) is only a monitored validation metric — `energy/gan/val` vs. the `energy/gan/ref` real-vs-real baseline, and the GAN early-stop / checkpoint key — not a training signal. `style`/`emoji` are the only classifier heads — both trained with `train.py:lse_infonce` Log-Sum-Exp InfoNCE (no focal loss, no BCE/`pos_weight`, no softmax cross-entropy). `export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` just clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS` is used.
- `normalize` (in `data.py`) collapses whitespace, trims, lowercases, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. `TextEncoder.forward` masks PAD positions to `-inf` before the global max over the time axis (`torch.max(out, dim=-1).values`), so pad steps never enter the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- One runnable Python check — `test_runmeta.py` (plain-assert script, `uv run python test_runmeta.py`) — but still no pytest suite and no CI gate on it; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `train all --local` (watch `MRR@10/e/val` — the early-stop/checkpoint metric — alongside `mAP@10/e/val` / `MRR@5/s/val` / `mAP@5/s/val` and `f1/val` in TensorBoard, and `energy/gan/val` vs. `energy/gan/ref` for the GAN stage; `enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python run.py` for a `pred.jsonl` spot-check (threshold-based `top_labels`: styles 1–3, emojis exactly 1) and `uv run python tools/report.py` for the full run report (`report/<ts>-<sha>/report.html` — emoji/style `acc@k`, `words.json` keyword probe, OKLab colour energy + per-colour hit-rate). Grow the corpus with `bun run train` and/or `bun run upsample`, then `bun run regen`.
- `.pt` files are `{"state_dict", "meta"}` blobs — save with `runmeta.save_pt`, load with `runmeta.load_pt` (returns `(state_dict, meta|None)`; `None` = legacy bare file).
