# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, 320 — a frequency leaderboard) and styles (`STYLES`, 21 — a fixed closed set), both loaded from `labels.json`. A row carries 0–N emojis and 1–N styles. The shared trunk is `model.py:TextEncoder` — a char embedding → spectral-norm 1-D CNN stack (`MaxPool1d` between blocks) → global max-pool over time → a `TEXT_EMBED_SIZE` vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` L2-norms this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead`, both the same shape — `Linear(TEXT_EMBED_SIZE → *_EMBED_SIZE, bias=False)` → project against a learned label-embedding table (`logits = proj @ embed.weight.t() + bias`) → per-label logits. `StyleHead` trains multi-label with `binary_cross_entropy_with_logits` + a per-label `pos_weight` (`train.py:pos_weight`, `sqrt(neg/pos)` clamped to 10); `EmojiHead` trains with `train.py:focal_loss` (sigmoid focal, `FOCAL_ALPHA`/`FOCAL_GAMMA`, normalized by positive count). Both backprop into the encoder; no InfoNCE, no softmax cross-entropy. Colors are a **conditional GAN**, not a head: `model.py:ColorGen` conditions on the **text embedding**, mixing it with unit-norm noise `z` as `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground), NOT OKLab. It is trained adversarially (`ColorDsc` critic, conditioned on the same text embedding) against the corpus `bg`/`fg` hex (`data.py:colors2tensor` = RGB bytes − 127.5); no reconstruction/L1 loss (many colors fit one text). Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `train.py` — `LitTask` (encoder + style BCE/`pos_weight` + emoji `focal_loss` heads; early-stop/checkpoint via `ModelCheckpoint`/`EarlyStopping` on `f1/val` = harmonic mean of `mAP@10/e/val` and `mAP@5/s/val`, both from the hand-rolled `train.py:ap_at_k` top-k AP with `EMOJI_AP_K`/`STYLE_AP_K` from `config.py` — no `torchmetrics`; emoji AP is measured only over rows carrying ≥1 emoji) and `LitColorGAN` (color GAN on a **frozen** encoder; conditions on the encoder's text embedding, does not touch the classifier heads). `uv run python train.py` trains both stages, reloads the best task checkpoint, and saves five loose state dicts: `enc.pt`, `style.pt`, `emoji.pt`, `gen.pt`, `tst.pt` (all gitignored).
- `train_gan.py` — retrains just the GAN stage against a pre-saved `enc.pt`, re-saving `gen.pt` / `tst.pt`.
- `run.py` — batch inference over `eval.jsonl` → `pred.jsonl` (the reference implementation of the inference graph).
- `export_onnx.py` — `uv run python export_onnx.py` loads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt`, wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. Outputs are `style_logits`, `emoji_logits`, `color`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji.pt` label counts disagree with `labels.json`.
- `config.py` — flat module of hyperparameters (`MAX_TEXT_LEN`, `BATCH_SIZE`, `CHAR_EMBED_SIZE`, `TEXT_ENCODER_CHANNELS`, `ENCODER_KERNEL`, `EMOJI_EMBED_SIZE`, `STYLE_EMBED_SIZE`, `DROPOUT_EMOJI`, `DROPOUT_STYLE`, `GEN_CHANNELS`, `CRITIC_CHANNELS`, `LR`, `GAN_LR`, `GRAD_CLIP`, `TASK_EPOCHS`, `GAN_EPOCHS`, `EARLY_STOP_PATIENCE`, `VAL_CHECK_INTERVAL`, …; `INFONCE_TEMP` is still defined but only feeds `CONFIG_NAME` — no head uses it); `STYLES`/`EMOJIS` are read from `labels.json` here.
- `labels.json` — a `styles` list and an `emojis` list. `emojis` = top 320 (`TOP_EMOJIS` in `tools/data/config.ts`) by frequency in `train.jsonl` (descending, ties keep first-seen order), regenerated by `tools/data/labels.ts`; emojis are **open-set** in the corpus (annotator picks any emoji) and `labels.json` is just the current leaderboard. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). Not deterministic. `train.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex, plus `meta` on rows written since the coverage update) is the corpus the new pipeline grows; the legacy `data.jsonl` (older `feeling`/`emoji` singular shape) is a fixed pool that `re-annotate.ts` drains into `train.jsonl` under the new schema. No dedup, no length filtering, nothing retried across runs. Run every script from the repo root.
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `train.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage, and the batch's topic is recorded on every row it produces. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg, meta}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/re-annotate.ts` (`bun run tools/data/re-annotate.ts`) — reads a random `SAMPLE_SIZE` (2,000) rows from `data.jsonl`, keeps each `text` and re-derives labels + palette via `annotate()`. Rows that annotate successfully are appended to `train.jsonl` (new `emojis`/`styles` schema) and removed from `data.jsonl` (count-aware); rows that fail stay in `data.jsonl` for a later run.
  - `tools/data/labels.ts` (`bun run tools/data/labels.ts`) — rewrites `labels.json`: the fixed `styles` set + top 320 emojis in `train.jsonl`, as above.
  - `tools/data/stat.ts` (`bun run tools/data/stat.ts`) — writes `report/data-stat/<MM-DD-HH:MM>.md` summarizing `train.jsonl` and `eval.jsonl` side by side (row counts, style distribution, raw text-length histogram + count outside 4–48, emoji distribution). Auto-run by the `.claude/settings.json` PostToolUse hook whenever `train.jsonl` or `eval.jsonl` is written.
  - Provenance `meta` — every row written by `train.ts` / `re-annotate.ts` carries `meta`: `{src, v, at (YYYY-MM-DD), model, params}` plus `topic` (train only) or `target_emoji` / `target_style` (upsamplers only). `v` is the per-script logic version — bump it by hand when a script's generation/annotation logic changes. Pre-existing rows have no `meta`; `data.py:read` ignores the field either way. Groundwork for later data cleaning.
- Eval set — the `generate-eval-jsonl` skill (`.claude/commands/generate-eval-jsonl.md`) samples 1,200 rows from `train.jsonl`, keeps only the ones whose styles **and** emojis are all correct, which carry a full `bg`/`fg` palette, and whose raw text length is 4–48 (judged in-session, keep-or-drop, never relabeled), appends those to `eval.jsonl`, and removes them from `train.jsonl` (count-aware). The pre-migration holdout is preserved as `eval.jsonl.bak`.
- **Training corpus:** `data.py` reads `train.jsonl` for training and `eval.jsonl` for validation; `data.jsonl` is legacy and is never trained on directly — `re-annotate.ts` migrates it into `train.jsonl`. `data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `labels.json` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`).
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` fails until every label has an entry with a unique font. (This map currently lags `tools/data/styles.ts` — reconcile the two when touching either.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `data.py`) and `decodeColors`/`decodeColorList` (the inverse of `data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors). All of `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run python train.py` trains the task stage then the GAN stage (see `TASK_EPOCHS` / `GAN_EPOCHS` in `config.py`) and writes `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt` / `tst.pt`. Slow — don't use it as a smoke test. `train_gan.py` retrains only the GAN. `onnx` + `onnxscript` (dev deps) are required by `export_onnx.py`.
- Refresh the site's model without retraining: `uv run python export_onnx.py` reloads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt` and rewrites `web/public/model.onnx` + `meta.json` + `config.json` (no training). The `.pt` files are gitignored, so commit the regenerated `web/public/` files; pushing `web/**` to `main` triggers the Pages deploy.
- Run the web app locally with `cd web && npm install && npm run dev`; `npm test` (in `web/`) runs the vitest suite, `npm run build` writes `web/dist`.
- Training writes TensorBoard logs to `runs/<CONFIG_NAME>/` (task run) and `runs/<CONFIG_NAME>/gan` (GAN run); `CONFIG_NAME` (in `config.py`) encodes a timestamp + model/train hyperparameters. View with `uv run tensorboard --logdir runs`.
- The data toolchain is Bun, not `uv`: `bun install`, then (from the repo root) grow the corpus with `bun run tools/data/train.ts` and/or `bun run tools/data/re-annotate.ts`, then `bun run tools/data/labels.ts` to refresh `labels.json`. package.json aliases (root-relative): `bun run train` / `re-annotate` / `labels` / `stat`.
- Non-model scripts live under `tools/data/`; the model stack — `config.py`, `data.py`, `model.py`, `train.py`, `train_gan.py`, `run.py`, `export_onnx.py` — stays at the repo root. `test_model.py` is stale (imports a removed `Model` class). All tool scripts assume the repo root as CWD.
- Python 3.13.

## Conventions

- Colors are a GAN, not a head: `model.py:ColorGen` maps `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → 9 raw sRGB byte offsets (`tanh * 127.5`), where `text_embed` is the **L2-normed `TextEncoder` output** (not the emoji query) and `z` is unit-norm Gaussian noise the same size. Trained adversarially via `ColorDsc` (BCE, spectral norm, no gradient penalty, **no L1/reconstruction term**), critic conditioned on the same `text_embed`, against `data.py:colors2tensor([*row.bg, row.fg])` (RGB bytes − 127.5). `style`/`emoji` are the only classifier heads — both multi-label `binary_cross_entropy_with_logits` with a per-label `pos_weight` (no cross-entropy, no InfoNCE). `export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` just clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS` is used.
- `normalize` (in `data.py`) collapses whitespace, trims, lowercases, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. The encoder is a 1-D CNN with a global max-pool over the time axis (`torch.max(out, dim=-1)`, then L2-normed), so trailing pad steps do not shift the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No Python test suite; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run python train.py` (watch `f1/val` = harmonic mean of `mAP/s/val` + `mAP/e/val` in TensorBoard; `enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python run.py` for a `pred.jsonl` spot-check (threshold-based `top_labels`: styles 1–3, emojis 0–6). Grow the corpus with `bun run tools/data/train.ts` and/or `bun run tools/data/re-annotate.ts`, then `bun run tools/data/labels.ts`.
