# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level LSTM (`main.py`) that maps a short text string to two labels: an emoji (`EMOJIS`, a 300-emoji palette, fully decoupled from feelings) and a feeling (`feeling`, the 7 in `labels.json`: Happy, Calm, Sad, Angry, Anxious, Neutral, Love). Both label sets are loaded from `labels.json`. Colors are **not** learned and never pass through Python: `web/public/palette.json` maps each feeling to fixed hex colors for `bg1`/`bg2` (gradient background) and `text_color` (foreground), and `web/src` fetches it directly.

- `main.py` — data loading, model, training, eval, `predict`, and `export_web` (writes `web/public/model.onnx` + `web/public/meta.json`).
- `config.py` — flat module of training hyperparameters (`LR`, `BATCH_SIZE`, `EMBED_SIZE`, `H_SIZE`, `NUM_LAYERS`, `MAX_TEXT_LEN`, `GRAD_CLIP`, `EPOCHS`); imported by `main.py`.
- `labels.json` — the `feelings` and `emojis` lists, regenerated by `tools/data/labels.ts` from `train.jsonl`: `feelings` = top 10, `emojis` = top 100, each by frequency (descending, ties keep first-seen order). Both label sets are **open-set** in the corpus — the annotator picks any capitalized feeling word and any emoji; `labels.json` is just the current frequency leaderboard.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). Not deterministic. `train.jsonl` (one JSON object per line: `text`, `feeling`, `emoji`) is the corpus the new pipeline grows; the legacy `data.jsonl` (same shape) is a fixed pool that `re-annotate.ts` drains into `train.jsonl`. No dedup, no length filtering, nothing retried across runs. Run every script from the repo root.
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emoji, feeling}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt is general — best emoji (any emoji, no rare/common bias), best single feeling word (common preferred, `Neutral` allowed but not encouraged), no label list given.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `train.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length, no steering. Phase 2: `annotate()` every text; each annotated text is written as `{text, feeling, emoji}` (texts that fail annotation are dropped).
  - `tools/data/re-annotate.ts` (`bun run tools/data/re-annotate.ts`) — reads a random `SAMPLE_SIZE` (2,000) rows from `data.jsonl`, keeps each `text` and re-derives both labels via `annotate()`. Rows that annotate successfully are appended to `train.jsonl` and removed from `data.jsonl` (count-aware); rows that fail stay in `data.jsonl` for a later run.
  - `tools/data/labels.ts` (`bun run tools/data/labels.ts`) — rewrites `labels.json` (top 10 feelings + top 100 emojis in `train.jsonl`, as above).
  - `tools/data/stat.ts` (`bun run tools/data/stat.ts`) — writes `report/data-stat/<MM-DD-HH:MM>.md` summarizing `train.jsonl` and `eval.jsonl` side by side (row counts, feeling distribution, raw text-length histogram + count outside 4–48, emoji distribution). Auto-run by the `.claude/settings.json` PostToolUse hook whenever `train.jsonl` or `eval.jsonl` is written.
- Eval set — the `generate-eval-jsonl` skill (`.claude/commands/generate-eval-jsonl.md`) samples 1,000 rows from `train.jsonl`, keeps only the ones whose feeling **and** emoji are correct and whose raw text length is 4–48 (judged in-session, keep-or-drop, never relabeled), appends those to `eval.jsonl`, and removes them from `train.jsonl` (count-aware). The pre-migration holdout is preserved as `eval.jsonl.bak`.
- **Training corpus:** `data.py` reads `train.jsonl` for training and `eval.jsonl` for validation; `data.jsonl` is legacy and is never trained on directly — `re-annotate.ts` migrates it into `train.jsonl`. `_load` still filters to the closed `labels.json` palette (rows whose feeling/emoji is out-of-vocab, or whose normalized text exceeds `MAX_TEXT_LEN`, are skipped).
- **Web is on the open-set palette:** `web/` consumes the 30-feeling `meta.json` and `web/public/palette.json` (30 `{bg1,bg2,text_color}` entries); `web/src/feelings.js` maps each feeling to one of 9 style clusters (font + text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any feeling not listed. Changing the feeling leaderboard (`meta.json` / `labels.json`) therefore requires a matching entry in `web/src/feelings.js` (`FEELINGS`) and a row in `web/public/palette.json`; `web/src/feelings.test.js` fails until both exist.
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `train.py`'s `export_web` (`model.onnx`, `meta.json`, `config.json`) plus the hand-maintained `palette.json` (per-feeling hex colors) and `web/src/feelings.js` (per-feeling font + animation cluster). `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` and must stay byte-identical to `train.py`. Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `train.py`'s `ExportWrapper` still replaces `pack_padded_sequence` with a `gather` so the LSTM traces to ONNX.
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run main.py` trains for `EPOCHS` epochs (see `config.py`), writes `model.pt`, refreshes `web/public/model.onnx` + `web/public/meta.json`, and prints a sample inference. This is slow — don't use it as a smoke test. `onnx` + `onnxscript` (dev deps) are required by the ONNX export.
- Refresh the site's model without retraining: `uv run main.py --export-only` rewrites `web/public/model.onnx` + `web/public/meta.json` from the committed `model.pt`. Commit `model.pt` and the regenerated `web/public/` files together; pushing `web/**` to `main` triggers the Pages deploy.
- Run the web app locally with `cd web && npm install && npm run dev`; `npm test` (in `web/`) runs the vitest suite, `npm run build` writes `web/dist`.
- Training writes TensorBoard logs to `runs/<config-name>/` (run name, from `run_name()`, encodes embed/hidden/layers/lr/batch/epochs); view with `uv run tensorboard --logdir runs`.
- The data toolchain is Bun, not `uv`: `bun install`, then (from the repo root) grow the corpus with `bun run tools/data/train.ts` and/or `bun run tools/data/re-annotate.ts`, then `bun run tools/data/labels.ts` to refresh `labels.json`. package.json aliases (root-relative): `bun run train` / `re-annotate` / `labels` / `stat`.
- Non-model scripts live under `tools/data/`; the model stack — `config.py`, `data.py`, `model.py`, `train.py` — and the behavioral suite `test_model.py` stay at the repo root. All tool scripts assume the repo root as CWD.
- Python 3.13.

## Conventions

- Colors are a fixed lookup, not a model head: `web/public/palette.json` holds one `{bg1, bg2, text_color}` of hex strings per feeling (warm/bright for Happy, cool for Calm, muted/dark for Sad/Anxious, dark saturated red for Angry, neutral grey for Neutral). `web/src` fetches it and drops the values straight into CSS / canvas fills, falling back to `Neutral` for any unlisted feeling. The model has only two heads (`emoji`, `feeling`), both cross-entropy; there is no color loss.
- `normalize` (in `main.py`) collapses whitespace, lowercases, then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` also invalidates the committed `model.pt` (retrain) and reshuffles the hash-based train/test split.
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses `padding_idx=0`. The LSTM is fed via `pack_padded_sequence`, so the classifier reads the hidden state at each row's last real character, not a trailing pad step. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No Python test suite; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run main.py`: loss should decrease, `feeling_acc` trains well, `emoji_acc` is weak at the current `H_SIZE`/`EMBED_SIZE` and thin/imbalanced `data.jsonl`. Grow the corpus with `bun run tools/data/train.ts` and/or `bun run tools/data/re-annotate.ts`, then `bun run tools/data/labels.ts`.
