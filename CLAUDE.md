# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level LSTM (`main.py`) that maps a short text string to two labels: an emoji (`EMOJIS`, an 80-emoji palette, fully decoupled from feelings) and a feeling (`feeling`, the 7 that all appear in `data.jsonl`). Both label sets are loaded from `labels.json`. Colors are **not** learned and never pass through Python: `docs/palette.json` maps each feeling to fixed hex colors for `bg1`/`bg2` (gradient background) and `text_color` (foreground), and `docs/app.js` fetches it directly.

- `main.py` — data loading, model, training, eval, `predict`, and `export_web` (writes `docs/model.onnx` + `docs/meta.json`).
- `config.py` — flat module of training hyperparameters (`LR`, `BATCH_SIZE`, `EMBED_SIZE`, `H_SIZE`, `NUM_LAYERS`, `MAX_TEXT_LEN`, `GRAD_CLIP`, `EPOCHS`); imported by `main.py`.
- `labels.json` — the `feelings` and `emojis` lists, shared by `data.py` and `gen_labels.ts`. `feelings` is a fixed closed set; `emojis` is regenerated by `gen_labels.ts` (top 100 by frequency in `data.jsonl`).
- Data pipeline — three Bun/TypeScript scripts, run in order, each using the Vercel AI SDK + GPT-5.6 Luna via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). Not deterministic; each run grows the corpus.
  - `raw_txt.ts` (`bun raw_txt.ts`) — generates short, informal WhatsApp-style texts (≤ 50 chars) across a topic/voice spread and **appends** the unique ones to `raw.txt` (deduped against itself and existing `raw.txt` via `data.py`'s normalize key).
  - `annotation.ts` (`bun annotation.ts`) — drains `raw.txt`: skips lines longer than `MAX_TEXT_LEN` or already in `data.jsonl`, annotates the rest in batches (emoji = free choice, feeling = one of `labels.json`'s feelings), **appends** `{emoji, feeling, text}` to `data.jsonl`, and removes handled lines from `raw.txt` (annotation failures stay for the next run).
  - `gen_labels.ts` (`bun gen_labels.ts`) — rewrites `labels.json`: feelings untouched, emojis = top 100 by frequency in `data.jsonl` (descending, ties keep first-seen order).
- `data.jsonl` is append-only; `data.py`'s `read()` does all filtering at load time (drops rows whose feeling/emoji isn't in `labels.json`, or whose normalized text exceeds `MAX_TEXT_LEN`).
- `data.jsonl` — one JSON sample per line: `text`, `emoji`, `feeling` (no color fields).
- `docs/` — the one web app: a committed, backend-free static site served as-is by GitHub Pages (no build step). `index.html` + `app.js` run inference in the browser via onnxruntime-web (`ort.Tensor` int64, argmax both heads) and reimplement `normalize`/`encode` from `meta.json`; `style.css` is the styling. `model.onnx`, `meta.json` (CHARS / `MAX_TEXT_LEN` / `EMOJIS` / feelings — so the JS hardcodes nothing `main.py` owns) and `config.json` (`max_text_len`, used by `app.js` to cap the input field's `maxlength`) are regenerated by `main.py`'s `export_web`; everything else in `docs/`, including the hand-maintained `palette.json` (per-feeling hex colors, fetched by `app.js`), is hand-maintained. `export_web` wraps the model in an `ExportWrapper` that replaces `pack_padded_sequence` with a `gather` at the last real char so the LSTM traces to ONNX. Serve locally with any static server, e.g. `uv run python -m http.server -d docs`.
- `docs/vendor/` — committed browser deps, no CDN dependency (see its README): the onnxruntime-web wasm backend (`ort.wasm.min.js` + glue/wasm; single-threaded, so no COOP/COEP headers).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `docs/**` (and `workflow_dispatch`), uploads `docs/` and deploys it to Pages. No build step. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run main.py` trains for `EPOCHS` epochs (see `config.py`), writes `model.pt`, refreshes `docs/model.onnx` + `docs/meta.json`, and prints a sample inference. This is slow — don't use it as a smoke test. `onnx` + `onnxscript` (dev deps) are required by the ONNX export.
- Refresh the site's model without retraining: `uv run main.py --export-only` rewrites `docs/model.onnx` + `docs/meta.json` from the committed `model.pt`. Commit `model.pt` and the regenerated `docs/` files together; pushing `docs/**` to `main` triggers the Pages deploy.
- Training writes TensorBoard logs to `runs/<config-name>/` (run name, from `run_name()`, encodes embed/hidden/layers/lr/batch/epochs); view with `uv run tensorboard --logdir runs`.
- The generator toolchain is Bun, not `uv`: `bun install` then `bun raw_txt.ts` → `bun annotation.ts` → `bun gen_labels.ts` (package.json aliases: `bun run raw` / `annotate` / `labels`).
- Python 3.11.

## Conventions

- Colors are a fixed lookup, not a model head: `docs/palette.json` holds one `{bg1, bg2, text_color}` of hex strings per feeling (warm/bright for Happy/Excited, cool for Calm, muted/dark for Sad/Anxious, dark saturated red for Angry, neutral grey for Neutral). `docs/app.js` fetches it and drops the values straight into CSS / canvas fills, falling back to `Neutral` for any unlisted feeling. The model has only two heads (`emoji`, `feeling`), both cross-entropy; there is no color loss.
- `normalize` (in `main.py`) collapses whitespace, lowercases, then drops non-vocab chars. `docs/app.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` also invalidates the committed `model.pt` (retrain) and reshuffles the hash-based train/test split.
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses `padding_idx=0`. The LSTM is fed via `pack_padded_sequence`, so the classifier reads the hidden state at each row's last real character, not a trailing pad step. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No test suite; the only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run main.py`: loss should decrease, `feeling_acc` trains well, `emoji_acc` is weak at the current `H_SIZE`/`EMBED_SIZE` and thin/imbalanced `data.jsonl`. Grow the corpus with `bun raw_txt.ts` → `bun annotation.ts` → `bun gen_labels.ts`; `feelings` in `labels.json` is the only label set edited by hand.
