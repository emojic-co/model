# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`emojic` trains a small multi-task char-level model that maps a short text string to two **multi-label** label sets: emojis (`EMOJIS`, 352 — a frequency leaderboard) and styles (`STYLES`, 21 — a fixed closed set), both loaded from `labels.json`. A row carries 0–N emojis and 1–N styles. The shared trunk is `model.py:TextEncoder` — a char embedding → spectral-norm 1-D CNN stack (`MaxPool1d` between blocks) → global max-pool over time → a `TEXT_EMBED_SIZE` vector (`TextEncoder.forward` returns the raw pooled vector, **not** L2-normed; the heads consume it raw, and `ColorGen` L2-norms this conditioning vector internally). On top of it: `StyleHead` and `EmojiHead`. `StyleHead` is `Dropout → Linear(TEXT_EMBED_SIZE → STYLE_EMBED_SIZE, bias=False)`; `EmojiHead` is `Dropout → Linear(TEXT_EMBED_SIZE → EMOJI_EMBED_SIZE, bias=False)` then `EMOJI_HEAD_HIDDEN_LAYERS` (currently 1) MLP blocks of `LeakyReLU → Linear(EMOJI_EMBED_SIZE → EMOJI_EMBED_SIZE, bias=False)` (input `Dropout` only, no per-block dropout) (`EMOJI_HEAD_HIDDEN_LAYERS = 0` collapses it back to `StyleHead`'s single-`Linear` shape). Both then project against a learned label-embedding table (`logits = proj @ embed.weight.t() + bias`) → per-label logits. `StyleHead` trains multi-label with `binary_cross_entropy_with_logits` + a per-label `pos_weight` (`train.py:pos_weight`, `sqrt(neg/pos)` clamped to 10); `EmojiHead` trains with `train.py:focal_loss` (sigmoid focal, `FOCAL_ALPHA`/`FOCAL_GAMMA`, normalized by positive count). Both backprop into the encoder; no InfoNCE, no softmax cross-entropy. Colors are a **conditional GAN**, not a head: `model.py:ColorGen` conditions on the **text embedding**, mixing it with unit-norm noise `z` as `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → a 9-vector `tanh`-squashed to `[-127.5, 127.5]` — raw sRGB byte offsets for `bg1`/`bg2` (gradient background) and `text_color` (foreground), NOT OKLab. It is trained adversarially (`ColorDsc` critic, conditioned on the same text embedding) against the corpus `bg`/`fg` hex (`data.py:colors2tensor` = RGB bytes − 127.5); no reconstruction/L1 loss (many colors fit one text). Decoded back to hex in the browser by `web/src/model.js:decodeColors` (just `+127.5`, clamp, hex). Style only selects a font + animation.

- `train.py` — `LitTask` (encoder + style BCE/`pos_weight` + emoji `focal_loss` heads; early-stop/checkpoint via `ModelCheckpoint`/`EarlyStopping` on `f1/val` = harmonic mean of `mAP@10/e/val` and `mAP@5/s/val`, both from the hand-rolled `train.py:ap_at_k` top-k AP with `EMOJI_AP_K`/`STYLE_AP_K` from `config.py` — no `torchmetrics`; emoji AP is measured only over rows carrying ≥1 emoji) and `LitColorGAN` (color GAN on a **frozen** encoder; conditions on the encoder's text embedding, does not touch the classifier heads). `uv run python train.py` trains both stages, reloads the best task checkpoint, and saves five loose state dicts: `enc.pt`, `style.pt`, `emoji.pt`, `gen.pt`, `tst.pt` (all gitignored).
- `train_gan.py` — retrains just the GAN stage against a pre-saved `enc.pt`, re-saving `gen.pt` / `tst.pt`.
- `run.py` — inference over the first 200 `eval.jsonl` rows → `pred.jsonl` (reference implementation of the inference graph; one GAN palette per row).
- `export_onnx.py` — `uv run python export_onnx.py` loads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt`, wraps them (`ExportWrapper`), and writes `web/public/model.onnx` + `meta.json` + `config.json`. Outputs are `style_logits`, `emoji_logits`, `color`. The GAN is sampled with **5 predefined constant noise vectors** (each a `TEXT_EMBED_SIZE` unit vector, seeded by `SEED`) baked into the graph and mixed with the text embedding, so `color` is a `[5, 9]` output — 5 deterministic palettes per text. It aborts if `style.pt` / `emoji.pt` label counts disagree with `labels.json`.
- `config.py` — flat module of hyperparameters (`MAX_TEXT_LEN`, `BATCH_SIZE`, `CHAR_EMBED_SIZE`, `TEXT_ENCODER_CHANNELS`, `ENCODER_KERNEL`, `RELU_SLOPE` (one shared LeakyReLU slope for the encoder, emoji head, GAN generator, and critic), `EMOJI_HEAD_HIDDEN_LAYERS`, `EMOJI_EMBED_SIZE`, `STYLE_EMBED_SIZE`, `DROPOUT_EMOJI`, `DROPOUT_STYLE`, `GEN_CHANNELS`, `CRITIC_CHANNELS`, `LR`, `GAN_LR`, `GRAD_CLIP`, `FOCAL_ALPHA`, `FOCAL_GAMMA`, `EMOJI_AP_K`, `STYLE_AP_K`, `TASK_EPOCHS`, `GAN_EPOCHS`, `EARLY_STOP_PATIENCE`, `VAL_CHECK_INTERVAL`, …; `INFONCE_TEMP`, `ENCODER_RELU_SLOPE`, `GEN_RELU_SLOPE`, and `CRITIC_RELU_SLOPE` have been removed); `STYLES`/`EMOJIS` are read from `labels.json` here.
- `labels.json` — a `styles` list and an `emojis` list. `emojis` = top 352 (`TOP_EMOJIS` in `tools/data/config.ts`) by frequency over `data.jsonl` (descending, ties keep first-seen order), regenerated by `bun run regen`; emojis are **open-set** in the corpus (annotator picks any emoji) and `labels.json` is just the current leaderboard. `styles` is the **fixed closed set** from `tools/data/styles.ts` (21 entries) — the annotator must pick from it, and `data.py` drops rows with no in-set style.
- Data pipeline (`tools/data/`) — all scripts use the Vercel AI SDK + `openai/gpt-5.6-luna` via the AI Gateway (needs `AI_GATEWAY_API_KEY`, Bun auto-loads it from `.env`). The growth and annotation tools are not deterministic (LLM calls); `regen.ts` is pure and deterministic. `data.jsonl` (one JSON object per line: `text`, `emojis` — a single space-separated string of 0–N emojis, `styles` — a list of 1–N style labels, `bg` — two hex stops, `fg` — one hex) is the **append-only master**: every growth tool appends to it and nothing ever rewrites or deletes from it. `train.jsonl`, `eval.jsonl` and `labels.json` are **gitignored artifacts** rebuilt from `data.jsonl` by `bun run regen` (`tools/data/regen.ts`) — it collapses rows sharing a `normalize(text)` key (union of emojis + closed-set styles, one palette hash-picked), seeded-shuffles the result into `train.jsonl` + `eval.jsonl` (default seed 42, eval size 1500), and writes the `labels.json` leaderboard. Run `bun run regen` after any pull that changed `data.jsonl` and before training. The growth tools do no dedup and no length filtering and retry nothing across runs; near-duplicate rows are collapsed only in `regen` (by `normalize(text)` key). Run every script from the repo root.
  - `tools/data/annotate.ts` — shared module (no entrypoint). `annotate(texts)` → `Map<index, {emojis, styles, bg?, fg?}>`, `PQueue`-parallel batches (`ANNOTATE_BATCH_SIZE`, `ANNOTATE_CONCURRENCY`), one retry per failed batch; missing map entries = that text could not be annotated. Prompt asks for a space-separated string of 0–`MAX_EMOJIS` emojis (specific over generic, mood emoji only when the mood is strong, empty string allowed) and 1–`MAX_STYLES` labels **from the fixed `STYLES` set** (`tools/data/styles.ts`), plus a `bg`/`fg` palette. Rows with no in-set style (`noStyle`) or no palette (`noPalette`) are dropped.
  - `tools/data/train.ts` (`bun run tools/data/train.ts`) — appends ~1,000 fresh rows to `data.jsonl` per run. Phase 1: `PQueue`-parallel generation of short texts (`BATCH_SIZE` × `BATCH_COUNT`, `CONCURRENCY`), 4–48 chars, broad spread of persona/mood/intent/length; each batch is anchored round-robin to one of `TOPICS` (24 concrete domains — food, chores, tv & film, pets, tech, …) so object/noun emojis get corpus coverage. Phase 2: `annotate()` every text; each annotated text is written as `{text, emojis, styles, bg, fg}` (texts that fail annotation, or that come back with no in-set style / no palette, are dropped).
  - `tools/data/regen.ts` (`bun run regen`) — rebuilds `train.jsonl` + `eval.jsonl` + `labels.json` from `data.jsonl` in one command: union-merge by `normalize(text)`, seeded train/eval split (`--seed`, `--n`), and the fixed `styles` set + top-`TOP_EMOJIS` emoji leaderboard (frequency over the whole master).
  - `tools/data/upsample-colors.ts` (`bun run upsample-colors`) — grows color-conditioned rows for a later color test. Iterates a fixed 11-name color list (`--colors red blue …` restricts it), generates `BATCHES_PER_COLOR` × `BATCH_SIZE` short texts per color with a prompt that evokes the color only indirectly (never names it), `annotate()`s them, and appends `{text, emojis, styles, bg, fg, color}` to `data.jsonl` — one extra `color` field tagging which color each row was generated for. No result validation; rows that fail annotation or come back with no palette are dropped.
  - `tools/data/stat.ts` (`bun run tools/data/stat.ts`) — writes `report/data-stat/<MM-DD-HH:MM>.md` summarizing `data.jsonl` (row counts, style distribution, raw text-length histogram + count outside 4–48, emoji distribution). Auto-run by the `.claude/settings.json` PostToolUse hook whenever `data.jsonl` is written.
  - `tools/data/color-analysis.ts` (`bun run color-analysis`) — read-only report on whether `upsample-colors.ts` rows actually got an on-target palette. For each `color`-tagged row it scores `bg` against a per-name anchor hex via OKLab similarity (`sim = max(0, 100·(1 − ΔE_OK/0.5))`, `mean`/`max` over the two stops), and compares each color's average to a random baseline sample of other `bg` rows (`--sample`, default 5000, `--seed`). Runs twice — muted and vivid anchor sets. Writes `report/color-analysis/<MM-DD-HH:MM>.md`; touches no data file.
  - Extra row fields — growth tools may write fields beyond the base `{text, emojis, styles, bg, fg}` schema (currently `color`, from `upsample-colors.ts`). They are kept for debugging, filtering, and eval slicing: `regen.ts:collapse` carries every non-base field through to `train.jsonl` / `eval.jsonl` (first-seen value wins when rows merge on a `normalize(text)` key) and never strips them, and `toLine` emits them after the base fields. They are **not** training signal — `data.py:read` matches only the base schema and ignores every other key (this also covered the old `meta` field, which no row carries anymore).
- Eval set — historically `eval.jsonl` was a hand-curated hold-out (rows sampled from the corpus and kept only if styles + emojis were all correct, a full `bg`/`fg` palette was present, and raw length was 4–48; judged in-session, keep-or-drop, never relabeled). As of the data-files reorg it is a plain **seeded random split** of the `data.jsonl` master (`bun run regen`, default seed 42, first 1500 collapsed rows), not a curated set. The pre-reorg curated hold-out is recoverable from git history: `git show f9cb0e6:eval.jsonl`. Because the split shuffles the entire collapsed master, appending rows to `data.jsonl` and re-running `regen` reshuffles the whole split — `eval.jsonl` membership changes on every regen after the master grows, so `f1/val` numbers are only comparable within a fixed `data.jsonl` snapshot.
- **Training corpus:** `data.py` reads `train.jsonl` for training and `eval.jsonl` for validation; both are regenerated from the `data.jsonl` master by `bun run regen` and are gitignored (run `regen` after a fresh checkout or a pull that touched `data.jsonl`). `data.py:read` only accepts rows with `text` + `emojis` + `styles` + `bg` + `fg`; it drops rows whose normalized text is empty or exceeds `MAX_TEXT_LEN` and rows left with no in-set style, and filters `emojis` to the `labels.json` vocab (a row may legitimately end up with zero emojis). Both label sets become multi-hot vectors (`multi_hot`).
- **Web label styling:** `web/` consumes the `meta.json` `styles` list; `web/src/feelings.js` (still so named; keys are style labels) maps **each** label to its own Google font family plus a per-label `style` (weight/italic/case/spacing) and a motion `cluster` (text-entrance motif + emoji motif + drift speed), with `Neutral` as the fallback for any label not listed. There is no `palette.json` — colors come from the GAN as **5 `{bg1,bg2,text_color}` palettes per prediction** (`ColorBar` swatches; the picked one styles the card). `feelings.js:DEFAULT_COLORS` is the pre-prediction fallback. Changing the label set (`meta.json` / `labels.json` / `tools/data/styles.ts`) requires a matching `FEELINGS` entry in `web/src/feelings.js` (with a distinct font) and a matching Google Fonts family in `web/index.html`; `web/src/feelings.test.js` fails until every label has an entry with a unique font. (This map currently lags `tools/data/styles.ts` — reconcile the two when touching either.)
- `web/` — the web app: a Vite + React project. `npm run dev` for local dev, `npm run build` writes the static site to `web/dist`, which the Pages workflow deploys (the build runs in CI, never on Pages). `web/public/` holds the assets regenerated by `export_onnx.py` (`model.onnx`, `meta.json`, `config.json`); the hand-maintained web files are `web/src/feelings.js` (per-label font + style + animation cluster) and the Google Fonts `<link>` in `web/index.html`. `web/src/model.js` reimplements `normalize`/`encode` from `meta.json` (byte-identical to `data.py`) and `decodeColors`/`decodeColorList` (the inverse of `data.py:colors2tensor` — `+127.5`, clamp to 0–255, hex; `decodeColorList` chunks the flat `[5, 9]` `color` output into 5 palettes). Inference runs in the browser via `onnxruntime-web` (wasm backend from npm, single-threaded, no COOP/COEP). `export_onnx.py`'s `ExportWrapper` takes one input (`input`, int64 char ids) and exports three outputs — `style_logits`, `emoji_logits`, and `color` (`[5, 9]`, from 5 constant noise vectors). All of `style_logits` / `emoji_logits` are raw per-label logits (`sigmoid` in the browser, not `softmax`).
- `.github/workflows/deploy-pages.yml` — on push to `main` touching `web/**` (and `workflow_dispatch`), builds and deploys the site to Pages. Runs `npm ci && npm run build` in `web/` and uploads `web/dist`. Repo Settings → Pages → Source must be "GitHub Actions".

## Environment & commands

- Package management is `uv` only. Do not `pip install` — dependencies and the lockfile are managed with `uv add` / `uv sync`.
- `train.jsonl` / `eval.jsonl` / `labels.json` are gitignored and produced by `bun run regen` from `data.jsonl`. A fresh checkout must run `bun run regen` **before** `uv run python train.py` / `run.py` / `export_onnx.py` / `train-modal.py` (they import `config`, which loads `labels.json`; `train-modal.py` also `add_local_file`s `train.jsonl` / `labels.json` over `CODE_FILES` at import) and before `npm test` in `web/` (`feelings.test.js` reads `labels.json`). The Pages deploy is unaffected — it builds from the committed `web/public/`.
- `torch` is pinned to the PyTorch CPU wheel index (see `[tool.uv.sources]` in `pyproject.toml`). Keep that index config intact when editing dependencies.
- Quick verify (no training run): `uv run ruff check .` and `uv run ruff format --check .`.
- Full run: `uv run python train.py` trains the task stage then the GAN stage (see `TASK_EPOCHS` / `GAN_EPOCHS` in `config.py`) and writes `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt` / `tst.pt`. Slow — don't use it as a smoke test. `train_gan.py` retrains only the GAN. `onnx` + `onnxscript` (dev deps) are required by `export_onnx.py`.
- Refresh the site's model without retraining: `uv run python export_onnx.py` reloads `enc.pt` / `style.pt` / `emoji.pt` / `gen.pt` and rewrites `web/public/model.onnx` + `meta.json` + `config.json` (no training). The `.pt` files are gitignored, so commit the regenerated `web/public/` files; pushing `web/**` to `main` triggers the Pages deploy.
- Run the web app locally with `cd web && npm install && npm run dev`; `npm test` (in `web/`) runs the vitest suite, `npm run build` writes `web/dist`.
- Training writes TensorBoard logs to `runs/<CONFIG_NAME>/` (task run) and `runs/<CONFIG_NAME>/gan` (GAN run); `CONFIG_NAME` (in `config.py`) encodes a timestamp + model/train hyperparameters. View with `uv run tensorboard --logdir runs`.
- The data toolchain is Bun, not `uv`: `bun install`, then (from the repo root) grow the corpus with `bun run train` and/or `bun run upsample-emojis` / `bun run upsample-emoji-test` / `bun run upsample-colors` (all append to `data.jsonl`), then `bun run regen` to rebuild `train.jsonl` / `eval.jsonl` / `labels.json`. package.json aliases (root-relative): `bun run train` / `upsample-emojis` / `upsample-emoji-test` / `upsample-colors` / `regen` / `stat`. `regen` is not only a post-growth step: several read-side Bun tools need it to have run first — `bun run upsample-emojis` (default mode reads `labels.json` + `data.jsonl` to pick the rarest emojis), `tools/analysis/fails.ts`, `tools/data/preview.ts` / `preview-model.ts` (read `eval.jsonl`), and `tools/data/preview-labels.ts` (reads `labels.json`). On a fresh checkout run `bun run regen` before any of those.
- Non-model scripts live under `tools/data/`; the model stack — `config.py`, `data.py`, `model.py`, `train.py`, `train_gan.py`, `run.py`, `export_onnx.py` — stays at the repo root. `test_model.py` is stale (imports a removed `Model` class). All tool scripts assume the repo root as CWD.
- Python 3.13.

## Conventions

- Colors are a GAN, not a head: `model.py:ColorGen` maps `(1 - Z_WEIGHT) * text_embed + Z_WEIGHT * z` → 9 raw sRGB byte offsets (`tanh * 127.5`), where `text_embed` is the `TextEncoder` output, **L2-normed inside `ColorGen.forward`** (not the emoji query), and `z` is unit-norm Gaussian noise the same size. Trained adversarially via `ColorDsc` (BCE, spectral norm, no gradient penalty, **no L1/reconstruction term**), critic conditioned on the same `text_embed`, against `data.py:colors2tensor([*row.bg, row.fg])` (RGB bytes − 127.5). `style`/`emoji` are the only classifier heads — style is `binary_cross_entropy_with_logits` + per-label `pos_weight`, emoji is `focal_loss` (no softmax cross-entropy, no InfoNCE). `export_onnx.py` bakes `+127.5` into the graph so the ONNX `color` output is 0–255; `web/src/model.js:decodeColors` just clamps + hexes. Pre-prediction, `feelings.js:DEFAULT_COLORS` is used.
- `normalize` (in `data.py`) collapses whitespace, trims, lowercases, collapses any char run of 3+ to 2 (`(.)\1{2,}` → `\1\1`), then drops non-vocab chars. `web/src/model.js` reimplements it with the same regex — the two must stay byte-identical or browser inference sees a different input distribution than training. Changing `normalize` invalidates the `.pt` files (retrain).
- Char indexing reserves index 0 for padding (`PAD_IDX`); real characters in `CHARS` are numbered from 1, and `nn.Embedding` uses index 0 as pad. The encoder is a 1-D CNN with a global max-pool over the time axis (`torch.max(out, dim=-1).values`, no normalization), so trailing pad steps do not shift the pooled vector. Sequences are always encoded to `MAX_TEXT_LEN` (train and inference must match).
- No Python test suite; `web/` has a vitest suite (`npm test` in `web/`) covering `model.js` and `fit.js`, but no CI gates on it. The only CI is the Pages deploy (`deploy-pages.yml`), which does not gate on lint or tests. For code changes, lint/format with `ruff` (above) before committing. Behavioral verification is a full `uv run python train.py` (watch `f1/val` = harmonic mean of `mAP@5/s/val` + `mAP@10/e/val` in TensorBoard; `enc.pt` etc. are overwritten even when a run is worse — trust the logs, not the files) plus `uv run python run.py` for a `pred.jsonl` spot-check (threshold-based `top_labels`: styles 1–3, emojis exactly 1). Grow the corpus with `bun run train` and/or `bun run upsample-emojis` / `bun run upsample-emoji-test` / `bun run upsample-colors`, then `bun run regen`.
