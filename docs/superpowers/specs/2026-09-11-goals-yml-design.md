# Global `goals.yml` — design

Date: 2026-09-11

## Problem

Project goals are scattered: hard-coded target constants in `tools/report.py`
(`SHORT_TEXT_ACC_TARGETS`, `CLDR_ACC1_TARGET_EXACT`, `VOCAB_SIZE_FLOOR`,
`VOCAB_COVERAGE_TARGET`, `VOCAB_DIVERSITY_TARGET`), a prose "Hard targets" table
in the `planning-emojic-improvements` skill, and the per-iteration `goal/*.yml`
files with their own ad-hoc dotted schema. There is no single long-term
statement of what the project is aiming at.

Vocab breadth is currently split across two metrics — popularity-weighted
`_coverage()` and a composite `_diversity()` (keyword coverage + group balance +
flag completeness). Neither answers the direct question "what fraction of each
Unicode emoji group does the vocab hold".

## Solution

One committed `goals.yml` at the repo root — the single, dynamic, long-term
goals statement. `tools/report.py` reads it for every scorecard target. The
per-iteration `goal/*.yml` files become strict subsets of its schema. Vocab
breadth is redefined as per-Unicode-group coverage, backed by a new committed
`data/group.json`.

## `goals.yml` schema (repo root)

```yaml
goals:
  emoji prediction:
    exact keyword:  {acc@1: 0.95, acc@5: 0.95, acc@10: 0.95}
    fuzzy keyword:  {acc@1: 0.90, acc@5: 0.95, acc@10: 0.95}
    full text:      {acc@1: 0.80, acc@5: 0.85, acc@10: 0.90}
  style prediction:
    full text:      {acc@1: 0.80, acc@5: 0.85, acc@10: 0.90}
  color generator:
    energy distance: {global: 0.01, red: 0.01, green: 0.01, blue: 0.01, dark: 0.01, bright: 0.01}
  max text len: 42
  vocabulary:
    size: 700
    coverage:
      <subgroup-key>: <target fraction 0..1>   # all 101 Unicode subgroups
```

- Keys are the spec's literal spaced strings (`exact keyword`, `full text`,
  `energy distance`, `max text len`).
- `vocabulary.coverage` enumerates all 101 Unicode emoji subgroups (emojibase
  `messages.json` `subgroups`, which mirror the unicode.org emoji-list.html
  anchors), in canonical order, each with a per-group target.
- Coverage target bands (initial "sensible" values, freely re-tuned later):
  Smileys&Emotion 0.30–0.60 · People&Body 0.05–0.15 · Component 0.0 ·
  Animals&Nature 0.35–0.60 · Food&Drink 0.40–0.70 · Travel&Places 0.20–0.50 ·
  Activities 0.30–0.50 · Objects 0.20–0.45 · Symbols 0.15–0.40 ·
  Flags `flag` 0.80 / `country-flag` 1.0 / `subdivision-flag` 1.0.

`GOALS_YML = "goals.yml"` added to `files.py` and `files.ts`.

## `data/group.json`

`{ "<subgroup-key>": ["😀", …], … }` — 101 keys, emoji as emojibase's
fully-qualified `emoji` field, in emojibase order. Empty groups (`food-marine`
in the current emojibase) map to `[]`.

Generated by new `tools/data/build-groups.ts` (reads
`node_modules/emojibase-data/en/{data,messages}.json`), `bun run build-groups`
alias, output committed. `GROUP_JSON = "data/group.json"` in `files.py` /
`files.ts`.

## `tools/report.py` changes

### Global-goals loader

`_load_global_goals()` — reads `goals.yml`, cached. Source of truth for all
scorecard targets. Removes module constants `SHORT_TEXT_ACC_TARGETS`,
`CLDR_ACC1_TARGET_EXACT`, `CLDR_ACC1_TARGET_FUZZY`, `VOCAB_SIZE_FLOOR`,
`VOCAB_COVERAGE_TARGET`, `VOCAB_DIVERSITY_TARGET`, `DIVERSITY_WEIGHTS`,
`DIVERSITY_MIN_GROUPS`, `DIVERSITY_GROUPS`.

### Vocab coverage

`_coverage()` and `_diversity()` deleted. New `_vocab_coverage()`:

- Reads `data/group.json` and `goals.yml` `vocabulary.coverage`.
- Per group: `covered = |{ e in group : strip_fe0f(e) in vocab_norm }|`,
  `total = len(group)`, `score = covered / total` (`None` when `total == 0`),
  `target` from `goals.yml`, `passed = score >= target`.
- Emits `status.vocab_coverage = { groups: {<g>: {score, covered, total,
  target, passed}}, groups_passed, groups_measurable, groups_total,
  top_missing: [<emoji>…] }`.
- `_emoji_popularity()` and its use drop from report.py;
  `data/emoji_popularity.json` stays on disk (regen PRIMARY_BONUS).

### Goal spec map

`_goal_specs()` rekeyed to the flattened nested paths:

| flattened goal path | dir | report.json source |
|---|---|---|
| `emoji prediction.exact keyword.acc@{1,5,10}` | max | `keyword.fusion.acc_at_k[{0,4,9}]` — the fusion model on CLDR keywords (exact-matched kw vector); the whole `emoji prediction` branch grades the fusion model, not the standalone kw search (`keyword.exact`) |
| `emoji prediction.fuzzy keyword.acc@{1,5,10}` | max | `keyword.fuzzy_fusion.acc_at_k[…]` — fusion model on a uFuzzy kw vector — null until wired |
| `emoji prediction.full text.acc@{1,5,10}` | max | best fusion variant `emoji.eval.*_acc_at_k[…]` |
| `style prediction.full text.acc@{1,5,10}` | max | `cards.style_acc_at_k[…]` |
| `color generator.energy distance.global` | min | `cards.energy` — null until wired |
| `color generator.energy distance.{red,green,blue,dark,bright}` | min | `cards.per_color.<c>.gt_mean_distance` |
| `max text len` | max | `data.max_text_len` (= `config.MAX_TEXT_LEN`) |
| `vocabulary.size` | max | `labels.emojis` |
| `vocabulary.coverage.<group>` | max | `status.vocab_coverage.groups.<group>.score` |

`_section_goals()` walker is unchanged (already flattens arbitrary nesting);
`actual is None` → `unmeasured`.

### Scorecard (`_section_status`)

Rebuilt from `goals.yml`. Priority order:

1. exact keyword Acc@{1,5,10}
2. full-text emoji Acc@{1,5,10}
3. fuzzy keyword Acc@{1,5,10}
4. color energy distance (global + per-color)
5. style Acc@{1,5,10}
6. max text len (met when `MAX_TEXT_LEN >= 42`)
7. vocab size
8. vocab coverage — one rollup row `N/M groups meet target`; `deferred`
   (grey) while any priority ≤ 5 accuracy goal is red/amber; per-group detail
   lives in `status.vocab_coverage`.

`report["data"]["max_text_len"] = MAX_TEXT_LEN` added in `_section_data()`.

### HTML

`_status_html` gains a compact per-group coverage grid (group · covered/total ·
target · colour). `_goals_html` unchanged structurally (nested walk already
generic); verify leaf-path display with spaced keys.

## `upsample --group <name>` (`tools/data/upsample.ts`)

New **standalone** mode:

- `--group <name>`: validated against `data/group.json` keys (unknown → error
  listing valid keys).
- Targets **all** emoji in the group; `--count N` → seeded-random N-subset
  (`seededShuffle(list, SEED).slice(0, N)`).
- `--per <n>` texts per target emoji (default `TEXTS_PER_EMOJI`).
- Pipeline mirrors the rank-window path: per emoji `genBatch`/`genPrompt` →
  `annotate()` → append with the target emoji prepended to the annotator's
  emoji list (deduped) + top-level `"group": "<name>"` + `"meta": {"date": …,
  "src": "group"}`.
- Mutually exclusive with `--negation` / `--short` / `--single-emoji` /
  `--colors` / `--flags` / `--keywords` / `--reannotate`; ignores `--emojis` /
  `--min-rank` / `--max-rank` / `--rare`.
- `--dry`: prints group, emoji count, capped count, approx texts; no writes.
- `GROUP_JSON` imported from `files.ts`.

CLAUDE.md: update the `upsample.ts` bullet, the `data/` bullet (new
`group.json`), the `files.py` / `files.ts` bullet, and the report/goals bullets
(new `goals.yml`, `status.vocab_coverage`, dropped diversity).
