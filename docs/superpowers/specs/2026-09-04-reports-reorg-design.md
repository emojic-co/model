# Reports reorg — design

Date: 2026-09-04

## Problem

Three problems with `report/` today:

1. **Too many report types.** Eight subtrees, 215 files, 13 MB: `test-emoji/` (34),
   `test-color/` (14), `data-stat/` (34), `data-quality/` (3), `color-analysis/` (2),
   `preview/` (91), `preview-labels/` (33), `preview-model/` (4).
2. **No link from a report to the model that produced it.** Every report is named
   by a bare timestamp (`%y-%m-%d-%H-%M`). The `.pt` state dicts are anonymous bare
   `state_dict`s, overwritten every run; the only run identity anywhere is the
   gitignored `runs/<CONFIG_NAME>/` TensorBoard dir.
3. **Reports are git-tracked** (259 commits, 685 blobs ever) and therefore cloned
   into every git worktree.

## Decisions (settled with the user)

- **Keep only** `test-emoji` and `test-color` as report families. Every other
  generator stops writing report files.
- **Stop tracking `report/`.** Delete all current report files. Future reports are
  written locally but never committed. Historical reports are regenerated by
  checking out the relevant commit and re-running the flow — no tooling is built
  for that.
- **Linkage via embedded `.pt` metadata.** Each `.pt` file is saved as
  `{"state_dict": ..., "meta": {...}}` where `meta` carries the training commit
  SHA (+ dirty flag), timestamp, `CONFIG_PARTS`, stage, and a `train.jsonl` hash.
  The probes read the loaded model's `meta` and stamp the report with it, plus
  their own probe-time timestamp/SHA. `data-quality` records probe-time SHA +
  timestamp only.
- **Rewrite git history** to strip `report/` entirely (`git-filter-repo`), then
  force-push `main`.
- **Preview tools** write to a gitignored top-level `preview/` folder. `stat.ts` /
  `color-analysis.ts` / `fails.ts` print to stdout. `data-quality` reports
  in-session (chat) only.
- Worktrees are **not** required for run tracking and per-run isolation is not made
  a policy — the identity lives in the file.

## Design

### A. `runmeta.py` (new, repo root)

Comment/docstring-free per repo convention. Imports `torch`, `config`, stdlib
only — no import of `train` / `export_onnx` / lightning (avoids cycles;
`train_gan.py` and `export_onnx.py` will import `runmeta`).

```
run_meta() -> {
    "sha":        "<short sha>" | "unknown",
    "dirty":      bool,
    "generated":  "<ISO-8601 seconds>",
    "config":     [<config.CONFIG_PARTS entries>],
    "train_sha":  "<sha256(train.jsonl)[:12]>" | None,
}
```

- `sha` — `git rev-parse --short HEAD`; `"unknown"` on failure.
- `dirty` — `git status --porcelain` non-empty.
- `generated` — `datetime.now().isoformat(timespec="seconds")`.
- `config` — `config.CONFIG_PARTS` (see B).
- `train_sha` — `sha256` of `Path("train.jsonl")` bytes if present, else `None`
  (guards against the eval-set reshuffle: two runs on different `train.jsonl`
  snapshots are distinguishable).

```
save_pt(state_dict, path, **extra) -> None
    torch.save({"state_dict": state_dict, "meta": run_meta() | extra}, path)

load_pt(path, *, map_location="cpu") -> (state_dict, meta | None)
    blob = torch.load(path, map_location=map_location, weights_only=False)
    if isinstance(blob, dict) and "state_dict" in blob:
        return blob["state_dict"], blob.get("meta")
    return blob, None          # legacy / hand-made bare state_dict
```

`weights_only=False` is explicit (the blob holds a plain-dict `meta`, not just
tensors); these files are already `torch.load`ed today with the same trust level.

```
stamp_lines(model_meta, *, label) -> list[str]
```
Renders the two provenance lines used by both probes (see F), falling back to
`run_meta()` when `model_meta is None`.

### B. `config.py`

Expose the section strings `CONFIG_NAME` already builds:

```
CONFIG_PARTS = [enc_str, emj_str, style_str, gan_str, train_str]
CONFIG_NAME  = " | ".join([f'TIME: {...}', *CONFIG_PARTS])
```

Pure data, no new imports.

### C. Save sites — `save_pt` instead of `torch.save`

| file:line | files saved | `extra` |
| --- | --- | --- |
| `train.py:329` | `enc.pt` `style.pt` `emoji.pt` | `stage="task"` |
| `train.py:370` | `gen.pt` `tst.pt` | `stage="gan"` |
| `train_gan.py:77` | `gen.pt` `tst.pt` | `stage="gan"` |

Each loop body becomes `save_pt(mod.state_dict(), f"{name}.pt", stage=...)`.
`run_meta()` is evaluated at save time, so `generated` / `sha` reflect the
training run (in `train.py` that's after the best-checkpoint reload — correct;
the code state is unchanged across the fit).

### D. Load sites — `load_pt` instead of `torch.load` + `load_state_dict`

Five modules have a local `_load(mod, path)` / `load(mod, path)` helper that does
`mod.load_state_dict(torch.load(path, map_location="cpu"))`. Each becomes:

```
def _load(mod, path):
    sd, meta = load_pt(path)
    mod.load_state_dict(sd)
    mod._pt_meta = meta        # stash for callers that report it
    return mod
```

| file | helper | consumers that need `meta` |
| --- | --- | --- |
| `test_emoji.py:20` | `_load` | yes — encoder meta → report |
| `test_color.py:40` | `_load` | yes — encoder meta → report |
| `export_onnx.py:28` | `_load` | encoder meta → `web/public/meta.json` (F) |
| `run.py:26` | `_load` | no (stash only) |
| `train_gan.py:30` | `load` | no (stash only) |

`train.py` / `train_gan.py` also call `LitTask.load_from_checkpoint` /
`LitColorGAN.load_from_checkpoint` on Lightning `.ckpt` files — those are
untouched (not our `.pt` format).

### E. `test_emoji.py` / `test_color.py` — report changes

- **`run_meta` once** in `test_emoji()` / `test_color()`; take the encoder's
  `_pt_meta` as the model's provenance.
- **Filename** gains the model's short SHA:
  `REPORT_DIR / f"{stamp}-{model_sha}.md"` (+ `.json` / `.html`). `stamp` stays
  `%y-%m-%d-%H-%M` so files sort chronologically and the Taskfile
  `find -name '*.md'` glob still matches. `model_sha` is `meta["sha"]` or
  `"nometa"` when the `.pt` had none.
- **`test_emoji.py`** — cross-check `emoji.pt`'s `meta["sha"]` against `enc.pt`'s;
  if they differ, add a `⚠ enc/emoji from different commits` line.
- **`test_color.py`** — `enc.pt` (`stage=task`) and `gen.pt` (`stage=gan`) come
  from different stages; cross-check their `sha` / `config` (not `stage`), warn on
  mismatch.

### F. Report stamp (`stamp_lines`)

Both `_render` / `_render_html` emit, directly under the title:

```
- model: `enc.pt` — trained <sha>[ dirty] @ <generated>, train.jsonl <train_sha>
  - config: <part> | <part> | …
- probe run: <probe generated> (code <probe sha>[ dirty])
```

When `model_meta is None`:

```
- model: `enc.pt` — no embedded metadata (legacy .pt)
- probe run: <probe generated> (code <probe sha>[ dirty])
  - config: <live config parts>
```

**`.json` sidecars** gain top-level `model_meta` (the dict, or `null`) and
`probe_meta` (`run_meta()` output). The existing `stamp` / `enc` / `emoji` /
`gen` keys stay for back-compat.

**`export_onnx.py`** folds the encoder's `meta` into `web/public/meta.json` as a
`"model_meta"` key (or `null`), so the deployed site records which model it runs.

### M. Git surgery

1. **Pause the background pipeline job** that auto-commits `fix` commits to `main`
   (it would re-push pre-rewrite history).
2. Land A–L on `main` as normal commits first (clean tree; new `.gitignore` in
   history).
3. `git worktree prune` (clears the 15 `prunable` run worktrees). Finish or
   `git worktree remove` the 3 live ones (`emojic-runs/modal-train-26-09-04-09-07`,
   `…-08-09`, `.worktrees/rvr-impl`).
4. Backup: `git clone --mirror . ../emojic-backup.git`.
5. Install `git-filter-repo` (`uvx git-filter-repo …` or `pipx install
   git-filter-repo`).
6. `git filter-repo --path report/ --invert-paths`.
7. Re-add the remote (`filter-repo` drops it):
   `git remote add origin git@github.com:emojic-co/model`.
8. `git push --force origin main`.
9. Recreate any needed worktrees from the rewritten `main`.
10. Re-enable the background pipeline job.
11. Collaborators re-clone (or hard-reset to the new `main`).

## Out of scope

- Reproduce-a-historical-report tooling (explicit: checkout + re-run by hand).
- Per-run output directories / run-ID registry / mandatory training worktrees.
- Fixing `update-model-md`'s stale `report/model/` reference.
- `model.md` / `data.md` regeneration.

## Testing / verification

- `uv run ruff check . && uv run ruff format --check .` — `runmeta.py`,
  `config.py`, `test_emoji.py`, `test_color.py`, `export_onnx.py`, `run.py`,
  `train.py`, `train_gan.py`.
- `uv run python -c "import runmeta; print(runmeta.run_meta())"` — dict with a
  real short SHA, `dirty` matching `git status`, non-null `train_sha` when
  `train.jsonl` exists.
- `load_pt` round-trip: `save_pt({'w': torch.zeros(1)}, '/tmp/x.pt', stage='task')`
  then `load_pt('/tmp/x.pt')` returns `(state_dict, meta)` with `stage="task"`;
  `torch.save(bare_dict)` then `load_pt` returns `(bare_dict, None)`.
- If local `.pt` files exist: `uv run python test_emoji.py` — report at
  `report/test-emoji/<stamp>-<sha>.md`, provenance lines present, `.json` has
  `model_meta` / `probe_meta`. `uv run python export_onnx.py` — `web/public/
  meta.json` has `model_meta`. (Skip if no `.pt`.)
- `bun run tools/data/stat.ts` — prints to stdout, writes nothing; `git status`
  clean, no `report/data-stat/`.
- `bun run tools/data/preview.ts …` — writes `preview/<stamp>.html`; `git status`
  clean (`preview/` ignored).
- `git check-ignore report/ preview/` — both ignored.
- Post-rewrite: `git log --stat | grep -c report/` is 0; a fresh clone has no
  `report/` history; `du -sh .git` dropped.
- `web/` build untouched (`report/` was never part of the Pages build).
