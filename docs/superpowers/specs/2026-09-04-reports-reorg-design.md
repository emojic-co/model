# Reports reorg — design

Date: 2026-09-04

## Problem

Three problems with `report/` today:

1. **Too many report types.** Eight subtrees, 215 files, 13 MB: `test-emoji/` (34),
   `test-color/` (14), `data-stat/` (34), `data-quality/` (3), `color-analysis/` (2),
   `preview/` (91), `preview-labels/` (33), `preview-model/` (4).
2. **No link from a report to the model/config that produced it.** Every report is
   named by a bare timestamp (`%y-%m-%d-%H-%M`). The `.pt` state dicts are anonymous
   and overwritten every run; the only run identity anywhere is the gitignored
   `runs/<CONFIG_NAME>/` TensorBoard dir.
3. **Reports are git-tracked** (259 commits, 685 blobs ever) and therefore cloned
   into every git worktree.

## Decisions (settled with the user)

- **Keep only** `test-emoji` and `test-color` as report families. Every other
  generator stops writing report files.
- **Stop tracking `report/`.** Delete all current report files. Future reports are
  written locally but never committed. Historical reports are regenerated by
  checking out the relevant commit and re-running the flow — no tooling is built
  for that.
- **Linkage:** each `test-emoji` / `test-color` report records the **git commit SHA**
  (with a dirty flag), a **timestamp**, and the **model configuration** (the
  `CONFIG_NAME` breakdown). `data-quality` records SHA + timestamp only (no model
  config — not applicable).
- **Rewrite git history** to strip `report/` entirely (`git-filter-repo`), then
  force-push `main`.
- **Preview tools** write to a gitignored top-level `preview/` folder (HTML meant to
  be opened in a browser). `stat.ts` / `color-analysis.ts` / `fails.ts` print to
  stdout. `data-quality` reports in-session (chat) only.

## Design

### A. `runmeta.py` (new, repo root)

A small module, comment/docstring-free per repo convention, that shells out to git:

```
run_meta() -> {
    "sha":       "<short sha>" | "unknown",
    "dirty":     bool,
    "generated": "<ISO-8601 seconds>",
    "config":    [<CONFIG_PARTS entries>],
}
```

- `sha`  — `git rev-parse --short HEAD`; `"unknown"` if git call fails.
- `dirty` — `git status --porcelain` non-empty.
- `generated` — `datetime.now().isoformat(timespec="seconds")`.
- `config` — imported from `config.CONFIG_PARTS` (see B).

No dependency on lightning/torch; safe to import from the probes.

### B. `config.py`

Expose the per-section strings that `CONFIG_NAME` already builds as a module-level
list, so `runmeta` and the reports can carry them without re-deriving:

```
CONFIG_PARTS = [enc_str, emj_str, style_str, gan_str, train_str]
CONFIG_NAME  = " | ".join([f'TIME: …', *CONFIG_PARTS])
```

Pure data, no new imports.

### C. `test_emoji.py`

- Import `run_meta` from `runmeta`.
- **Filename:** `REPORT_DIR / f"{stamp}-{meta['sha']}.md"` and `…-{sha}.json`
  (`stamp` stays `%y-%m-%d-%H-%M`, so files still sort chronologically and the
  Taskfile `find -name '*.md'` glob still matches).
- **Markdown header** (`_render`) gains, right under the `# Emoji test` line:
  ```
  - commit: `<sha>`<space>(dirty)   ← "(dirty)" only when dirty
  - generated: <iso>
  - config: <part> | <part> | …
  ```
- **`.json` sidecar** gains top-level keys `commit` (`{"sha", "dirty"}`),
  `generated`, `config` (list).
- `_render`'s signature grows a `meta` param (or reads `run_meta()` itself —
  implementer's choice, but compute it once in `test_emoji()` and thread it
  through so md and json agree).
- `write_report=False` path unchanged.

### D. `test_color.py`

Same as C, against the `.html` report:

- Filename `…-{sha}.html` / `…-{sha}.json`.
- `_render_html`'s `<p>model: …</p>` block gains `commit`, `generated`, and a
  `config:` line.
- `meta` dict (currently `{"stamp", "enc", "gen"}`) gains `commit`, `generated`,
  `config`; the `.json` inherits them via `**meta`.

### E. `tools/data/stat.ts`

- Drop `import { mkdir, writeFile }`, `REPORT_DIR`, the `mkdir` + `writeFile`.
- Print the assembled `doc.join("\n")` to stdout instead.
- Keep the final `console.log` of nothing / or just let the doc be the output.

### F. `.claude/settings.json`

Remove the entire `PostToolUse` hook block (its only case is `data.jsonl` →
`bun run tools/data/stat.ts`). Leaves `{ "hooks": {} }` or an empty file — keep
`{}`.

### G. `tools/data/color-analysis.ts`, `tools/analysis/fails.ts`

- Drop `mkdir` / `writeFile` / `OUT_DIR`.
- Print the `.md` body (`doc.join("\n")`) to stdout.

### H. Preview tools → gitignored `preview/`

`tools/data/preview.ts`, `preview-pred.ts`, `preview-labels.ts`, `preview-model.ts`:

| tool | old `OUT_DIR` | new `OUT_DIR` |
| --- | --- | --- |
| `preview.ts` | `report/preview` | `preview` |
| `preview-pred.ts` | `report/preview` | `preview` |
| `preview-labels.ts` | `report/preview-labels` | `preview/labels` |
| `preview-model.ts` | `report/preview-model` | `preview/model` |

Still `mkdir(..., {recursive:true})` + `writeFile` + `console.log(dest)`. Only the
path constant changes.

### I. `data-quality` skill (`.claude/commands/data-quality.md`)

Rewrite so it produces **no file**:

- Section 1: run `bun run tools/data/stat.ts`, read its **stdout** (no
  `report/data-stat/*.md` to `ls`).
- Section 3: `shuf -n 200 data.jsonl > "$SCRATCH/dq-sample.jsonl"` where
  `$SCRATCH` is the session scratchpad, not `report/data-quality/`.
- Section 5: replace "Write the report to `report/data-quality/$STAMP.md`" with
  "present the report **in this session** (chat)". Keep the same skeleton/sections
  as the message body. Add a `commit: <sha> · generated: <iso>` line to the header
  (from `git rev-parse --short HEAD` / `date -Iseconds`).
- Section 6 ("Report back") stays.
- Drop the `git status --short` check that asserted "only new files under
  `report/`".
- Update the front-matter `description` (drop "Writes one report to
  `report/data-quality/`").

### J. `.gitignore`

Add:

```
# Local-only run outputs; regenerated on demand from the model + commit.
report/
preview/
```

### K. Git surgery

1. **Pause the background pipeline job** that auto-commits `fix` commits to `main`
   (it would re-push pre-rewrite history).
2. Land all the code changes above on `main` in a normal commit first (so the
   working tree is clean and the new `.gitignore` is in history).
3. `git worktree prune` — clears the 15 `prunable` run worktrees. Finish or
   `git worktree remove` the 3 live ones
   (`emojic-runs/modal-train-26-09-04-09-07`, `…-08-09`,
   `.worktrees/rvr-impl`).
4. Backup: `git clone --mirror . ../emojic-backup.git` (or `cp -r .git`).
5. Install `git-filter-repo` (`uvx git-filter-repo …` or `pipx install
   git-filter-repo`).
6. `git filter-repo --path report/ --invert-paths`.
7. Re-add the remote (`filter-repo` drops it):
   `git remote add origin git@github.com:emojic-co/model`.
8. `git push --force origin main`.
9. Recreate any needed worktrees from the rewritten `main`.
10. Re-enable the background pipeline job.
11. Tell collaborators to re-clone (or hard-reset to the new `main`).

### L. Docs

- `CLAUDE.md`: lines 11, 13, 14, 25, 26, 33, 41, 54 — drop `report/data-stat`,
  `report/data-quality`, `report/color-analysis`, `report/preview*` from the
  "Generated docs & reports" paragraph and the per-script blurbs; note the
  PostToolUse hook is gone; note `test_emoji.py` / `test_color.py` reports carry a
  commit SHA + config stamp and live in gitignored `report/`; note preview tools
  write to gitignored `preview/`.
- `train-modal.py`: audit the artifacts it copies back — `report/` is still
  produced on the Modal box (`report/test-emoji/` from `test_emoji.py`), so the
  collection still works; update any comment that lists the old report types.
- `Taskfile.yml`: `modal-train:reports` still valid (`report/test-emoji/*.md`);
  the `-newer "${wt}.git"` freshness check still works on mtime. No change.
- `.claude/commands/update-model-md.md`: already references a non-existent
  `report/model/*.md`. **Out of scope** — flag to the user, don't fix here.

## Out of scope

- Reproduce-a-historical-report tooling (explicit: checkout + re-run by hand).
- Any run-registry / run-ID scheme beyond the SHA stamp.
- Fixing `update-model-md`'s stale `report/model/` reference.
- `model.md` / `data.md` regeneration.

## Testing / verification

- `uv run ruff check . && uv run ruff format --check .` — `runmeta.py`, `config.py`,
  `test_emoji.py`, `test_color.py`.
- `uv run python -c "import runmeta; print(runmeta.run_meta())"` — sane dict, dirty
  flag reflects `git status`.
- `uv run python test_emoji.py` against existing `enc.pt` / `emoji.pt` (if present)
  — report lands at `report/test-emoji/<stamp>-<sha>.md`, header shows commit +
  config, `.json` has the new keys. (Skip if no `.pt` files locally.)
- `bun run tools/data/stat.ts` — prints to stdout, writes nothing (`git status`
  clean, no `report/data-stat/`).
- `bun run tools/data/preview.ts …` — writes `preview/<stamp>.html`, and `preview/`
  is gitignored (`git status` clean).
- `git check-ignore report/ preview/` — both ignored.
- Post-rewrite: `git log --stat | grep -c report/` is 0; fresh `git clone` of the
  pushed repo has no `report/` in history; `du -sh .git` dropped.
- `web/` build untouched (`report/` was never part of the Pages build).
